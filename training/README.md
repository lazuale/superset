# Учебный стенд и данные

Вся первая версия курса использует **один локальный учебный стенд** и **один фиксированный набор данных**.

Задача каталога `training/` — дать новичку одинаковую рабочую среду без отдельной установки PostgreSQL и без ручной настройки Superset.

На Windows команды этого курса выполняются в оболочке WSL 2 при запущенном Docker Desktop с Linux containers. На macOS и Linux используйте обычный терминал.

## Что входит в стенд

```text
training/
├── README.md
├── compose.yaml
├── schema.sql
├── data.sql
├── readonly.sql
└── check.sql
```

### `compose.yaml`

Запускает:

- Apache Superset `6.1.0-dev`;
- PostgreSQL `17.11`;
- одноразовую инициализацию Superset.

Веб-интерфейс Superset:

```text
http://localhost:8088
```

Порт `8088` публикуется только на `127.0.0.1`, поэтому учебный интерфейс предназначен для доступа с того же компьютера, где запущен Docker.

Учебная учётная запись Superset:

```text
login:    admin
password: admin
```

### `schema.sql`

Создаёт в PostgreSQL:

```text
database: training
schema:   training
table:    sales
```

Саму базу `training` и пользователя-владельца `training` создаёт официальный PostgreSQL image из переменных окружения в `compose.yaml`; `schema.sql` создаёт внутри этой базы схему и таблицу.

Пользователь `training` нужен для инициализации учебной базы и контрольных команд. В подключении Superset он **не используется**.

### `data.sql`

Загружает фиксированные 12 строк.

Скрипт начинается с `TRUNCATE`, поэтому его можно повторно выполнить для возврата самой таблицы к исходным строкам без изменения её структуры.

### `readonly.sql`

Создаёт отдельного пользователя PostgreSQL:

```text
superset_reader
```

Ему выдаются только права, необходимые для чтения учебных данных:

```text
CONNECT к database training
USAGE на schema training
SELECT на таблицы schema training
```

Именно этой учётной записью Superset подключается к учебной базе. Так курс не приучает подключать BI-инструмент под владельцем базы или PostgreSQL-superuser.

### `check.sql`

Проверяет контрольные итоги учебного набора: общие суммы, регионы, месяцы, продукты, `NULL` в `manager` и показатели по непустым менеджерам.

Главные значения:

| Показатель | Ожидается |
|---|---:|
| строк | 12 |
| количество | 31 |
| выручка | 4005.00 |
| себестоимость | 2475.00 |
| прибыль | 1530.00 |

## Таблица `training.sales`

| Поле | Тип | Что означает |
|---|---|---|
| `sale_id` | `BIGINT` | номер строки продажи |
| `sale_date` | `DATE` | дата продажи |
| `region` | `TEXT` | регион |
| `office` | `TEXT` | офис |
| `manager` | `TEXT` | менеджер; одна строка специально содержит `NULL` |
| `product` | `TEXT` | продукт |
| `quantity` | `INTEGER` | количество |
| `revenue` | `NUMERIC(12,2)` | выручка |
| `cost` | `NUMERIC(12,2)` | себестоимость |

Одна строка таблицы — одна учебная продажа.

## Реквизиты учебного PostgreSQL для Superset

Из контейнеров этого `docker compose`-проекта база доступна Superset по реквизитам:

```text
host:     db
port:     5432
database: training
user:     superset_reader
password: superset_reader
```

Именно эти значения используются в уроке 03 при создании `Database` в Superset.

Пользователь-владелец базы:

```text
training
```

оставлен для инициализации стенда и локальных контрольных команд. Не подставляйте `training / training` в Database Connection Superset вместо `superset_reader`.

PostgreSQL наружу на порт компьютера не публикуется: для курса это не требуется.

## Проверка данных

Из каталога `training/`:

```bash
docker compose exec -T db \
  psql -U training -d training -f /training/check.sql
```

Эта команда выполняется владельцем учебной базы, потому что это административная проверка самого стенда, а не аналитическое подключение Superset.

Проверить, что read-only пользователь действительно читает данные, можно так:

```bash
docker compose exec -T \
  -e PGPASSWORD=superset_reader \
  db psql -h 127.0.0.1 -U superset_reader -d training \
  -c "SELECT COUNT(*) FROM training.sales;"
```

Ожидается:

```text
12
```

## Остановка

```bash
docker compose stop
```

Обычная остановка сохраняет данные и состояние курса.

## Полный сброс

```bash
docker compose down -v --remove-orphans
docker compose up -d
```

Полный сброс удаляет Docker volumes и создаёт стенд заново.

Будут удалены и созданные позже объекты Superset: Dataset, Chart, Dashboard и другие учебные настройки.

## Почему используется `6.1.0-dev`

Курс зафиксирован на Apache Superset 6.1.0.

Официальная документация Superset для Docker Compose рекомендует использовать суффикс `-dev` при работе с PostgreSQL в таком учебном сценарии, потому что dev-образ уже содержит `psycopg2-binary`.

Поэтому стенд использует:

```text
apache/superset:6.1.0-dev
```

Это официальный образ релиза 6.1.0 с build preset `dev`. Суффикс `-dev` здесь не означает, что курс работает с незавершённой веткой разработки: номер версии остаётся `6.1.0`, а preset добавляет инструменты и драйверы, которых нет в lean-варианте образа.

## Почему PostgreSQL зафиксирован на `17.11`

Для учебного стенда важна повторяемость.

Поэтому используется конкретный тег:

```text
postgres:17.11
```

а не плавающий major-тег `postgres:17`, который со временем начинает указывать на новый minor-релиз.

## Граница применения

Этот стенд предназначен только для:

- обучения;
- локальных экспериментов;
- повторяемой практики курса.

Он **не является production-конфигурацией**.

Не переносите из него в реальную систему:

- `admin / admin`;
- открытый учебный `SUPERSET_SECRET_KEY`;
- учебные пароли PostgreSQL;
- локальный способ хранения служебного состояния Superset;
- упрощённый учебный состав контейнеров и сервисов.

Отдельный `superset_reader` нужен не для того, чтобы объявить стенд production-ready, а чтобы даже в учебном примере не закреплять лишние права на аналитическое подключение.

Продовое развёртывание изучается только после базового курса.
