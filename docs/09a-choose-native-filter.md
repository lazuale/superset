# Справочник к уроку 09. Как выбрать Native Filter

Урок 09 показывает механику Native Filters. Здесь разбираем выбор: **что пользователь должен выбирать, по какому полю и какие графики этот выбор должен менять**.

| Что выбирает пользователь | Native Filter |
|---|---|
| регион / статус / объект | `Value` |
| период | `Time range` |
| числовой интервал | `Range` |
| дату события | `Time column` |
| день / месяц / квартал | `Time grain` |

После выбора типа отдельно настраивается область действия (`Scoping`).

## `Value` — значения категории

Подходит для региона, менеджера, участка, статуса, типа документа и других категориальных полей.

Например:

```text
Filter type = Value
Dataset     = sales
Column      = region
```

Такой фильтр отвечает на запросы вроде «покажи только Север» или «оставь Анну и Бориса».

## `Time range` — период

Используется, когда пользователь выбирает, за какой период смотреть данные.

Для полного февраля 2026 года:

```text
2026-02-01 <= date < 2026-03-01
```

Подробнее о времени:

→ [Time column, Time range и Time grain](05b-time-range-and-grain.md)

## `Range` — числовой диапазон

Подходит для полей, где пользователь задаёт нижнюю и/или верхнюю границу: сумма, пробег, процент и т. п.

`Range` отбирает строки. Он не заменяет метрику.

## `Time column` — выбор даты события

Нужен, если один Dashboard должен переключаться между разными временными колонками, например `created_at` и `closed_at`.

Если у панели одна очевидная дата события, отдельный выбор Time column обычно только усложняет интерфейс.

## `Time grain` — детализация времени

Позволяет переключать календарную детализацию:

```text
Day
Week
Month
Quarter
Year
```

`Time range` отвечает за период, `Time grain` — за то, как этот период группируется.

## Scoping — куда действует фильтр

Фильтр не обязан влиять на каждый график Dashboard.

Для каждого Chart стоит задать простой вопрос:

> Имеет ли этот фильтр смысл для того вопроса, на который отвечает график?

В учебном Dashboard:

```text
Регион  → все графики
Менеджер → только Table и Big Number
```

Именно это проверяется в уроке 09.

## Пример осознанной области действия

Пусть на Dashboard есть:

```text
KPI ошибок
Динамика ошибок
Ошибки по участкам
Общий корпоративный план
Детальная таблица
```

Фильтр `Участок` может влиять на показатели ошибок и детализацию, но не на общий корпоративный план, если тот должен оставаться единым ориентиром независимо от участка.

`Scoping` задаётся по смыслу, а не по принципу «включить везде».

## Несколько фильтров работают вместе

Если график входит в область действия нескольких активных фильтров, условия применяются одновременно:

```text
Период
AND Регион
AND Менеджер
```

Если Chart исключён из Scoping одного фильтра, именно это условие к нему не применяется.

## Native Filter не является правом доступа

Фильтр Dashboard нужен для анализа. Пользователь может его очистить или выбрать другое значение, если права это позволяют.

Ограничение доступа к данным настраивается отдельными механизмами безопасности Superset и/или источника. Native Filter не должен использоваться вместо них.

## Разные Dataset на одном Dashboard

Если графики используют разные Dataset, один фильтр не становится корректным для всех автоматически.

Проверьте:

- есть ли нужная колонка в каждом Dataset;
- одинаков ли её смысл;
- совместимы ли типы данных.

Одинаковое имя `region` ещё не гарантирует одинаковую семантику.

## Не добавляйте фильтры «на всякий случай»

Большой набор редко используемых фильтров усложняет начало работы, повышает шанс получить пустой результат и делает Scoping труднее для понимания.

Каждый фильтр должен отвечать реальному пользовательскому сценарию.

## Типовые проблемы

| Симптом | Что проверить |
|---|---|
| фильтр не меняет график | `Scoping`, затем `Apply filters` |
| не те значения | Dataset и Column |
| пустой результат | комбинацию активных фильтров |
| изменились лишние графики | `Scoping` |
| один фильтр странно работает с разными Dataset | семантику колонок |

## Перед публикацией

Проверьте, что у каждого фильтра понятны назначение, тип, Dataset, Column и Scoping. Отдельно проверьте одно значение, комбинацию с другими фильтрами и `Clear all`.

Если пользователь не может заранее понять, что изменится после выбора значения, настройку фильтра стоит упростить.
