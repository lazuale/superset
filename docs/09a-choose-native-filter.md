# Шпаргалка к уроку 09. Как выбрать Native Filter

Эта шпаргалка нужна, чтобы понять:

> **какой фильтр добавить на Dashboard, по какому полю и на какие Chart он должен влиять.**

Самая короткая схема:

```text
Что пользователь хочет ограничить?
        ↓
категорию / объект → Value
период             → Time range
числовой диапазон  → Range
временную колонку  → Time column
детализацию времени→ Time grain
        ↓
после этого настроить Scoping
```

Главное правило:

```text
создать фильтр
≠
сделать его полезным
```

Фильтр должен отвечать реальной задаче пользователя и иметь понятную область действия.

---

## 1. Сначала сформулируйте вопрос

Не начинайте с меню типов фильтра.

Сначала спросите:

```text
Что именно пользователь хочет выбрать?
```

Примеры:

```text
регион
менеджера
подразделение
статус
период
диапазон суммы
временную колонку
день / неделю / месяц
```

После этого выбирайте тип Native Filter.

---

# 2. `Value` — выбор значения категории

Используйте `Value`, когда пользователь выбирает одно или несколько значений столбца.

Примеры:

```text
Регион
Менеджер
Участок
Статус
Тип документа
Категория
```

Настройка концептуально выглядит так:

```text
Filter type = Value
Dataset     = sales
Column      = region
```

То есть фильтр строится по значениям конкретной колонки Dataset.

---

## Когда `Value` подходит

Вопрос пользователя звучит примерно так:

```text
покажи только Север
покажи Анну и Бориса
покажи статус Ошибка
покажи выбранные участки
```

Это категориальный выбор.

---

## Когда `Value` не подходит

Если пользователь хочет:

```text
с 1 февраля по 1 марта
```

нужен временной фильтр.

Если:

```text
сумма от 1000 до 5000
```

логичнее диапазонный фильтр.

---

# 3. `Time range` — период

Используйте для вопроса:

```text
за какой период показать данные?
```

Примеры:

```text
сегодня
последние 7 дней
текущий месяц
февраль 2026
произвольный диапазон
```

Для точного календарного месяца удобно мыслить границами:

```text
Start inclusive
End exclusive
```

Например февраль 2026:

```text
2026-02-01 <= date < 2026-03-01
```

---

# 4. `Range` — числовой диапазон

Используйте, если пользователь должен задать нижнюю и/или верхнюю границу числового поля.

Примеры:

```text
сумма от 1000 до 5000
пробег от 100 до 500 км
возраст от 20 до 40
процент от 80 до 100
```

Это не замена Metric.

`Range` ограничивает строки по значениям поля, а Metric считает показатель по оставшимся строкам.

---

# 5. `Time column` — выбор временного поля

Нужен, если один Dashboard должен уметь анализировать данные по разным временным колонкам.

Например в Dataset есть:

```text
created_at
closed_at
```

Пользователь может захотеть переключаться между:

```text
датой создания
датой закрытия
```

Это уже более продвинутый сценарий.

Для обычного Dashboard, где время однозначно определяется одной датой события, такой фильтр часто не нужен.

---

# 6. `Time grain` — детализация времени

Этот фильтр нужен, когда пользователь должен менять уровень временной группировки.

Например:

```text
Day
Week
Month
Quarter
Year
```

То есть вопрос не:

> какой период взять?

а:

> с какой детализацией показать выбранный период?

Не путайте:

```text
Time range
→ какие даты взять

Time grain
→ как сгруппировать выбранные даты
```

---

# 7. Самая короткая таблица выбора

| Что хочет пользователь | Фильтр |
|---|---|
| выбрать регион / статус / объект | `Value` |
| выбрать период | `Time range` |
| выбрать диапазон числа | `Range` |
| выбрать дату события | `Time column` |
| переключить день / месяц / квартал | `Time grain` |

Если задачу можно описать одной строкой этой таблицы, более сложный фильтр обычно не нужен.

---

# 8. `Scoping` — куда действует фильтр

Это одна из самых важных настроек Native Filters.

```text
Filter существует
```

не означает:

```text
Filter влияет на каждый Chart
```

В `Scoping` задаётся область действия.

Например:

```text
Регион
→ все Chart

Менеджер
→ только Table и Big Number
```

Такой сценарий используется в учебном уроке 09.

---

# 9. Как выбирать Scoping

Для каждого Chart спросите:

> имеет ли этот фильтр смысл для вопроса, на который отвечает Chart?

Например:

```text
Фильтр = Менеджер
```

Chart:

```text
Продажи конкретных менеджеров
```

→ фильтр уместен.

Но если другой Chart специально показывает общий корпоративный benchmark независимо от менеджера, его можно оставить вне Scoping.

Scoping должен отражать смысл панели, а не случайную техническую доступность.

---

# 10. Почему фильтр может не влиять на Chart

Частые причины:

```text
Chart не включён в Scoping
значение ещё не применено
выбран не тот Dataset / Column
Chart использует несовместимый Dataset
фильтр очищен
```

Первое, что проверяем:

```text
Scoping
```

Затем:

```text
Apply filters
```

---

# 11. Несколько фильтров обычно работают вместе

Например:

```text
Период = февраль 2026
Регион = Север
Менеджер = Анна
```

Для Chart, который входит в Scoping всех трёх фильтров, смысл такой:

```text
Период
AND Регион
AND Менеджер
```

То есть остаются строки, удовлетворяющие всем активным условиям.

Если Chart не входит в Scoping `Менеджер`, он продолжит учитывать только первые два условия.

---

# 12. Фильтр не является механизмом безопасности

Это принципиально важно.

Если пользователь видит:

```text
Регион = Север
```

он может очистить фильтр или выбрать другой регион, если права доступа это позволяют.

Поэтому:

```text
Native Filter
→ удобство анализа

не
→ защита данных
```

Ограничение доступа делается механизмами безопасности Superset и/или на уровне источника данных.

---

# 13. Не добавляйте фильтры «на всякий случай»

Плохой Dashboard:

```text
15 фильтров
```

из которых реально используются три.

Проблемы:

- пользователь не понимает, с чего начинать;
- легче получить пустой результат комбинацией условий;
- сложнее объяснить Scoping;
- панель занимает место;
- поддержка становится тяжелее.

Добавляйте фильтр, если у пользователя есть реальный сценарий выбора.

---

# 14. Выбирайте понятные имена

Хорошо:

```text
Период
Регион
Менеджер
Статус
```

Плохо:

```text
Filter 1
region_select
Дата2
Поле
```

Название должно описывать то, что выбирает пользователь, а не внутреннюю структуру SQL.

---

# 15. Осторожно с NULL

Если колонка содержит `NULL`, нужно понимать, что означает отсутствие значения.

Например:

```text
manager = NULL
```

может означать:

```text
менеджер не указан
```

Это не то же самое, что любой из существующих менеджеров.

Если отсутствие значения важно для анализа, его смысл должен быть понятен пользователю и согласован с моделью данных.

---

# 16. Фильтр должен соответствовать Dataset

Если Dashboard собирает Chart из разных Dataset, нельзя автоматически считать, что один фильтр корректно применим ко всем.

Проверьте:

```text
есть ли нужная колонка
одинаков ли её смысл
совместим ли тип данных
```

Например колонка с названием `region` в двух Dataset может иметь разный смысл или разные значения.

Одинаковое имя ещё не гарантирует одинаковую семантику.

---

# 17. Период и временные Chart

Если Dashboard содержит временной Chart, проверьте отдельно:

```text
какая Time column используется
какой Time range активен
какой Time grain выбран
```

Это три разных настройки.

Подробнее:

→ [Шпаргалка: Time column, Time range и Time grain](05b-time-range-and-grain.md)

---

# 18. Пример фильтров рабочего Dashboard

Допустим, есть операционная панель.

Пользователь реально работает с:

```text
периодом
участком
типом ошибки
```

Тогда разумный набор:

```text
Период      → Time range
Участок     → Value
Тип ошибки  → Value
```

В большинстве случаев этого достаточно.

Необязательно добавлять одновременно:

```text
год
месяц
день
неделя
начало периода
конец периода
```

если один `Time range` закрывает задачу.

---

# 19. Пример осознанного Scoping

Dashboard:

```text
KPI ошибок
Динамика ошибок
Ошибки по участкам
Общий корпоративный план
Детальная таблица
```

Фильтр:

```text
Участок
```

Можно настроить:

```text
KPI ошибок           → да
Динамика ошибок      → да
Ошибки по участкам   → да
Общий план           → нет
Детальная таблица    → да
```

Почему `Общий план` не фильтруется?

Потому что его аналитический смысл — оставаться общим benchmark.

Это и есть смысловой Scoping.

---

# 20. Чек-лист перед сохранением фильтра

```text
[ ] Понятно, какую задачу решает фильтр.
[ ] Выбран правильный тип фильтра.
[ ] Dataset правильный.
[ ] Column правильная.
[ ] Название понятно пользователю.
[ ] Scoping проверен для каждого нужного Chart.
[ ] Проверена работа одного значения.
[ ] Проверена очистка фильтра.
[ ] Проверена комбинация с другими фильтрами.
[ ] Фильтр не используется как замена прав доступа.
```

---

# 21. Алгоритм выбора для новичка

```text
Что пользователь выбирает?
        ↓
категорию?
→ Value

период?
→ Time range

числовой интервал?
→ Range

временную колонку?
→ Time column

уровень группировки времени?
→ Time grain
        ↓
какие Chart должны измениться?
→ Scoping
        ↓
проверить Apply filters
        ↓
проверить Clear all
```

---

# 22. Главное правило

```text
Native Filter должен быть понятен
по трём вещам:

что выбираем
по какому полю
какие Chart меняются
```

Если пользователь не может предсказать результат фильтра, конфигурацию нужно упрощать.
