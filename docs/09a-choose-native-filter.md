# Справочник к уроку 09. Как выбрать Native Filter

Урок 09 показывает, как добавить и проверить Native Filters. Этот справочник помогает решить, **какой фильтр нужен, по какому полю и на какие графики (`Chart`) он должен влиять**.

## Быстрая схема

```text
категория / объект
→ Value

период
→ Time range

числовой диапазон
→ Range

выбор временной колонки
→ Time column

детализация времени
→ Time grain

после выбора типа
→ настроить Scoping
```

## 1. `Value` — выбрать значения категории

Подходит для:

```text
Регион
Менеджер
Участок
Статус
Тип документа
Категория
```

Схематично:

```text
Filter type = Value
Dataset     = sales
Column      = region
```

Вопрос пользователя:

```text
покажи только Север
покажи Анну и Бориса
покажи статус Ошибка
```

## 2. `Time range` — выбрать период

Подходит для вопроса:

```text
за какой период показать данные?
```

Например полный февраль 2026:

```text
2026-02-01 <= date < 2026-03-01
```

Подробнее о времени:

→ [Time column, Time range и Time grain](05b-time-range-and-grain.md)

## 3. `Range` — числовой диапазон

Используйте, когда пользователь задаёт нижнюю и/или верхнюю границу числового поля:

```text
сумма 1000–5000
пробег 100–500 км
процент 80–100
```

`Range` отбирает строки. Он не заменяет метрику (`Metric`).

## 4. `Time column` — выбор даты события

Нужен, если один Dashboard должен переключаться между разными временными колонками:

```text
created_at
closed_at
```

Это продвинутый сценарий. Если у Dashboard одна очевидная дата события, такой фильтр обычно не нужен.

## 5. `Time grain` — детализация времени

Позволяет пользователю переключать:

```text
Day
Week
Month
Quarter
Year
```

Не путайте:

```text
Time range
→ какой период берём

Time grain
→ как группируем этот период
```

## 6. Таблица выбора

| Что выбирает пользователь | Native Filter |
|---|---|
| регион / статус / объект | `Value` |
| период | `Time range` |
| числовой интервал | `Range` |
| дату события | `Time column` |
| день / месяц / квартал | `Time grain` |

## 7. `Scoping` — куда действует фильтр

Сам факт существования фильтра не означает, что он влияет на каждый график.

Для каждого графика спросите:

> Имеет ли этот фильтр смысл для вопроса, на который отвечает график?

Пример:

```text
Регион
→ все графики

Менеджер
→ только Table и Big Number
```

Именно такой принцип проверяется в уроке 09.

## 8. Осознанная область действия

Dashboard:

```text
KPI ошибок
Динамика ошибок
Ошибки по участкам
Общий корпоративный план
Детальная таблица
```

Фильтр:

```text
Участок
```

Возможный смысл:

```text
KPI ошибок           → да
Динамика ошибок      → да
Ошибки по участкам   → да
Общий план           → нет
Детальная таблица    → да
```

`Общий план` остаётся вне области действия (`Scoping`), если он должен быть общим контрольным ориентиром независимо от участка.

## 9. Несколько фильтров

Для графика, который входит в область действия всех активных фильтров:

```text
Период
AND Регион
AND Менеджер
```

То есть условия работают вместе.

Если график исключён из области действия одного фильтра, этот конкретный фильтр к нему не применяется.

## 10. Native Filter не является правом доступа

Критически важно:

```text
Native Filter
→ удобство анализа

не
→ механизм безопасности
```

Пользователь может очистить фильтр или выбрать другое значение, если права доступа это позволяют.

Ограничение данных настраивается отдельными механизмами безопасности Superset и/или источника.

## 11. Несколько Dataset на одном Dashboard

Если графики используют разные Dataset, не считайте автоматически, что один фильтр корректен для всех.

Проверяйте:

```text
есть ли нужная колонка
одинаков ли её смысл
совместим ли тип данных
```

Одинаковое имя `region` ещё не гарантирует одинаковую семантику.

## 12. Не добавляйте фильтры «на всякий случай»

Плохо:

```text
15 фильтров
```

из которых реально нужны три.

Проблемы:

```text
сложнее начать работу
легче получить пустой результат
сложнее настроить область действия
больше визуального шума
```

Добавляйте фильтр под реальный пользовательский сценарий.

## 13. Типовые проблемы

| Симптом | Что проверить |
|---|---|
| фильтр не меняет график | `Scoping`, затем `Apply filters` |
| не те значения | Dataset и Column |
| пустой результат | комбинацию активных фильтров |
| изменились лишние графики | `Scoping` |
| один фильтр странно работает с разными Dataset | семантику колонок |

## Чек-лист

```text
[ ] Понятно, зачем нужен фильтр.
[ ] Выбран правильный тип.
[ ] Dataset правильный.
[ ] Column правильная.
[ ] Название понятно пользователю.
[ ] Scoping проверен.
[ ] Проверено одно значение.
[ ] Проверена комбинация с другими фильтрами.
[ ] Проверен Clear all.
[ ] Фильтр не используется как замена прав доступа.
```

## Главное

Native Filter должен быть понятен по трём вещам:

```text
что выбираем
по какому полю
какие графики меняются
```
