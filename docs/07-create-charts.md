# 07. Строим и сохраняем Chart

## Что научимся делать

После этого урока вы должны уметь:

- выбирать визуализацию под конкретный аналитический вопрос;
- понимать разницу между `Dataset`, настройками `Explore` и сохранённым `Chart`;
- построить обычную таблицу;
- показать один KPI через `Big Number`;
- построить столбчатую диаграмму для сравнения категорий;
- построить временной график;
- использовать сохранённую Metric из Dataset;
- понимать разницу между `Create chart`, `Update chart` и `Save`;
- сохранять Chart;
- находить сохранённый Chart в общем списке;
- повторно открывать Chart в `Explore`;
- изменять его настройки и сохранять изменения поверх существующего Chart;
- отличать изменение визуализации от изменения смысла расчёта.

В этом уроке мы создадим несколько **сохранённых Chart**, которые в следующем уроке соберём в Dashboard.

Сам Dashboard пока не создаём.

## Что нужно до начала

Должны быть полностью пройдены предыдущие уроки.

Особенно важен [урок 06](06-metrics-and-calculations.md).

В Dataset `sales` уже должны существовать:

```text
Calculated column: profit
Metric key:        total_profit
Metric label:      Прибыль
```

Для `total_profit` используется выражение:

```sql
SUM(revenue) - SUM(cost)
```

Контрольный результат по всем данным:

```text
1530.00
```

Откройте Superset:

<http://localhost:8088>

и войдите под учебной учётной записью:

```text
логин:  admin
пароль: admin
```

## Что такое Chart в Superset

К этому моменту у нас уже есть:

```text
PostgreSQL table
        ↓
Database connection
        ↓
Dataset
        ↓
Explore
```

Теперь добавляется ещё один уровень:

```text
PostgreSQL
└── training.sales
        ↓
Dataset sales
        ↓
Explore
        ↓
Chart
```

`Chart` — это сохранённая конфигурация визуализации.

В неё входят, среди прочего:

- Dataset;
- тип визуализации;
- выбранные измерения;
- Metrics;
- Filters;
- временная гранулярность;
- параметры отображения.

Chart **не является копией строк PostgreSQL**.

Когда Chart выполняется, Superset формирует запрос на основании сохранённой конфигурации и обращается к источнику данных.

Поэтому важно различать:

```text
Dataset → описывает доступные данные и расчёты
Chart   → описывает конкретный аналитический вопрос и способ его показать
```

## Три разных действия в Explore

В Superset 6.1.0 нельзя смешивать выполнение конфигурации и сохранение объекта.

### `Create chart`

Показывается для нового, ещё не сохранённого Chart.

Нажатие выполняет текущую конфигурацию Explore и обновляет результат на экране.

### `Update chart`

Показывается при работе с уже существующим сохранённым Chart.

Нажатие повторно выполняет текущую изменённую конфигурацию и обновляет визуальный результат на экране.

### `Save`

Открывает диалог сохранения Chart.

В нём для нового Chart выбирается:

```text
Save as...
```

а для существующего Chart владелец может выбрать:

```text
Save (Overwrite)
```

Поэтому модель такая:

```text
настроили запрос
↓
Create chart / Update chart
↓
проверили результат
↓
Save
↓
Save as... / Save (Overwrite)
```

## Где в этих Chart задаётся временной фильтр

В уроке 05 мы уже увидели реальный интерфейс Superset 6.1.0: для используемых здесь визуализаций временное ограничение задаётся через:

```text
Filters
```

а не через отдельное универсальное поле `Time Range`.

Если в `Filters` отображается temporal-фильтр:

```text
sale_date (No filter)
```

то для всех основных упражнений этого урока оставляем:

```text
No filter
```

Нам нужны все учебные данные января–марта 2026 года.

## Сначала выбираем вопрос, потом график

В этом уроке будут четыре разных задачи:

| Вопрос | Подходящая визуализация |
|---|---|
| сколько выручки и прибыли у каждого региона? | `Table` |
| какова общая прибыль? | `Big Number` |
| какой регион даёт больше выручки? | `Bar Chart` |
| как менялась выручка по месяцам? | `Line Chart` |

Один и тот же Dataset используется для всех четырёх Chart.

```text
один Dataset
    ├── Chart 1
    ├── Chart 2
    ├── Chart 3
    └── Chart 4
```

Не нужно создавать новый Dataset для каждого графика.

# Chart 1. Таблица по регионам

## Какой вопрос решаем

Нужно одновременно увидеть:

- регион;
- выручку;
- прибыль.

Для такого результата таблица удобнее, чем график: нам важны точные числа сразу по двум показателям.

## Открываем Dataset

Перейдите:

```text
Datasets
```

Откройте:

```text
sales
```

Откроется `Explore`.

## Выбираем визуализацию

Выберите:

```text
Table
```

## Настраиваем запрос

В `Dimensions` добавьте:

```text
region
```

В `Metrics` добавьте две метрики.

Первая — временная `ad hoc metric`:

```text
SUM(revenue)
```

Вторая — сохранённая Metric из урока 06:

```text
Прибыль
```

Её технический ключ:

```text
total_profit
```

В `Filters` не должно быть активного ограничения по времени или региону.

Если отображается `sale_date`, оставьте:

```text
No filter
```

Итоговая конфигурация:

```text
Visualization: Table
Dimensions:    region
Metrics:       SUM(revenue), Прибыль
Filters:       без активного ограничения
```

Выполните конфигурацию кнопкой:

```text
Create chart
```

## Проверяем результат

Должны получиться два региона:

| Регион | Выручка | Прибыль |
|---|---:|---:|
| Север | 1360.00 | 520.00 |
| Юг | 2645.00 | 1010.00 |

Контроль итогов:

```text
выручка: 1360 + 2645 = 4005
прибыль:  520 + 1010 = 1530
```

Если числа отличаются, Chart пока не сохраняйте. Сначала проверьте:

```text
Dataset    = sales
Dimensions = region
Filters    = нет активных ограничений
```

и используемые Metrics.

## Сохраняем первый Chart

Нажмите:

```text
Save
```

В диалоге сохранения для нового Chart выбран режим:

```text
Save as...
```

Укажите имя:

```text
Продажи по регионам — таблица
```

Dashboard пока не выбирайте и не создавайте.

Нажмите кнопку сохранения в диалоге.

Теперь в Superset существует самостоятельный сохранённый объект Chart.

# Chart 2. Общая прибыль

## Какой вопрос решаем

Теперь нужен ответ только на один вопрос:

> Какова общая прибыль за весь учебный период?

Здесь группировка по категориям не нужна.

Нужно одно число.

Для этого подходит:

```text
Big Number
```

## Создаём новый Chart

Снова начните с Dataset:

```text
Datasets → sales
```

В `Explore` выберите визуализацию:

```text
Big Number
```

У `Big Number` в Superset 6.1.0 основная секция `Query` содержит Metric и `Filters`.

В качестве Metric выберите сохранённую метрику:

```text
Прибыль
```

или по её техническому ключу:

```text
total_profit
```

В `Filters` оставьте данные без активного ограничения. Если отображается `sale_date`, оставьте:

```text
No filter
```

Выполните конфигурацию:

```text
Create chart
```

## Проверяем результат

На экране должно быть одно основное значение:

```text
1530.00
```

Это тот же расчёт:

```sql
SUM(revenue) - SUM(cost)
```

который мы проверили в уроке 06.

`Big Number` не изменил формулу.

Он изменил только **способ представления результата**.

```text
Metric отвечает за смысл числа
Chart отвечает за способ его показать
```

## Сохраняем

Нажмите:

```text
Save
```

Оставьте режим:

```text
Save as...
```

и сохраните новый Chart под именем:

```text
Общая прибыль
```

Dashboard пока не добавляем.

# Chart 3. Сравниваем регионы столбцами

## Какой вопрос решаем

Теперь хотим быстро сравнить:

> какой регион даёт больше выручки?

В Superset 6.1.0 для такого сценария есть отдельная ECharts-визуализация:

```text
Bar Chart
```

## Открываем новый Explore

Перейдите:

```text
Datasets → sales
```

Выберите тип визуализации:

```text
Bar Chart
```

## Настраиваем столбчатую диаграмму

Установите:

```text
X Axis:      region
Metrics:     SUM(revenue)
Dimensions:  пусто
Filters:     без активного ограничения
```

Если в `Filters` отображается `sale_date`, оставьте:

```text
No filter
```

Смысл настройки:

```text
ось категорий = region
высота столбца = сумма revenue
```

Выполните конфигурацию:

```text
Create chart
```

## Проверяем результат

Должно быть два столбца:

```text
Север → 1360.00
Юг    → 2645.00
```

Столбец `Юг` должен быть заметно выше.

Это тот же аналитический результат, который мы уже видели в Table.

Разница только в представлении:

```text
Table
→ удобнее читать точные значения

Bar Chart
→ удобнее сравнивать величины категорий
```

## Включаем подписи значений

В настройках отображения найдите параметр:

```text
Show value
```

и включите его.

Снова выполните конфигурацию кнопкой:

```text
Create chart
```

Теперь значения должны отображаться рядом со столбцами или на них.

Не нужно менять цветовую схему, шрифты и десятки декоративных параметров.

## Сохраняем

Нажмите `Save`, оставьте `Save as...` и сохраните Chart под именем:

```text
Выручка по регионам — столбцы
```

Dashboard пока не выбирайте.

# Chart 4. Выручка по месяцам

## Какой вопрос решаем

Теперь категории `Север` и `Юг` нас не интересуют.

Нужно понять:

> как менялась общая выручка во времени?

Это уже временной вопрос.

Здесь естественно использовать линию.

## Создаём временной Chart

Снова откройте:

```text
Datasets → sales
```

Выберите:

```text
Line Chart
```

Настройте:

```text
X Axis:      sale_date
Time grain:  Month
Metrics:     SUM(revenue)
Dimensions:  пусто
Filters:     без активного ограничения
```

Если отображается temporal-фильтр `sale_date`, оставьте:

```text
No filter
```

Нам нужна одна линия общей выручки, поэтому `Dimensions` для этого упражнения оставляем пустым.

Выполните конфигурацию:

```text
Create chart
```

## Проверяем месяцы

Учебные данные содержат три месяца.

Контрольные значения:

| Месяц | Выручка |
|---|---:|
| 2026-01 | 1160.00 |
| 2026-02 | 1180.00 |
| 2026-03 | 1665.00 |

На графике должны быть три месячных значения.

Смысл настройки:

```text
sale_date
   ↓
Time grain = Month
   ↓
строки собираются по месяцам
   ↓
SUM(revenue)
   ↓
одно значение выручки на месяц
```

В отличие от столбчатого сравнения регионов здесь порядок по оси X имеет естественный смысл:

```text
январь → февраль → март
```

## Включаем маркеры

В настройках Chart найдите:

```text
Marker
```

и включите отображение маркеров точек.

Снова выполните конфигурацию:

```text
Create chart
```

На каждой месячной точке линии должен появиться маркер.

Это безопасная настройка оформления: она не меняет расчёт и не меняет набор данных.

## Сохраняем

Нажмите `Save`, оставьте `Save as...` и сохраните Chart под именем:

```text
Выручка по месяцам
```

Dashboard пока не создавайте.

# Что мы теперь сохранили

К этому моменту в Superset должны существовать четыре Chart:

```text
Продажи по регионам — таблица
Общая прибыль
Выручка по регионам — столбцы
Выручка по месяцам
```

Все они используют один Dataset:

```text
sales
```

Но отвечают на разные вопросы.

```text
Dataset sales
│
├── Продажи по регионам — таблица
├── Общая прибыль
├── Выручка по регионам — столбцы
└── Выручка по месяцам
```

Именно эти сохранённые Chart понадобятся в следующем уроке для Dashboard.

## Находим Chart после выхода из Explore

Теперь специально выйдите из текущего `Explore`.

В верхнем меню откройте:

```text
Charts
```

Найдите четыре созданных Chart по именам.

Chart не должен существовать только в открытой вкладке браузера.

После сохранения он является отдельным объектом Superset и должен находиться через общий список `Charts`.

## Повторно открываем существующий Chart

В списке `Charts` откройте:

```text
Выручка по месяцам
```

Перейдите к его редактированию в `Explore`, если сначала открывается режим просмотра.

Проверьте, что сохранились основные настройки:

```text
Visualization: Line Chart
Dataset:       sales
X Axis:        sale_date
Time grain:    Month
Metrics:       SUM(revenue)
Dimensions:    пусто
Filters:       без активного ограничения
```

и маркеры, которые мы включили перед сохранением.

Теперь Chart уже существует как сохранённый объект, поэтому текущая конфигурация выполняется кнопкой:

```text
Update chart
```

Нажмите её и снова получите:

```text
2026-01 → 1160.00
2026-02 → 1180.00
2026-03 → 1665.00
```

Если настройки и результат сохранились, повторное открытие Chart работает правильно.

## Изменяем существующий Chart

Оставьте все расчёты прежними и отключите:

```text
Marker
```

Нажмите:

```text
Update chart
```

Данные должны остаться теми же:

```text
1160.00
1180.00
1665.00
```

Изменился только внешний вид линии.

Теперь нажмите:

```text
Save
```

Поскольку мы хотим обновить тот же объект, в диалоге выберите:

```text
Save (Overwrite)
```

Не выбирайте `Save as...`.

Нажмите кнопку сохранения в диалоге.

После этого снова выйдите в:

```text
Charts
```

Откройте `Выручка по месяцам` ещё раз и убедитесь, что маркеры остались выключены.

Теперь вы прошли полный рабочий цикл:

```text
создать
→ Create chart
→ проверить
→ Save as...
→ найти
→ открыть
→ изменить
→ Update chart
→ проверить
→ Save (Overwrite)
```

## Save as... и Save (Overwrite) — разные действия

### Нужен новый независимый Chart

Используйте:

```text
Save as...
```

### Нужно изменить текущий Chart

Используйте:

```text
Save (Overwrite)
```

Иначе вместо обновления одного рабочего Chart легко получить список вроде:

```text
Выручка по месяцам
Выручка по месяцам 2
Выручка по месяцам final
Выручка по месяцам final2
```

Перед сохранением всегда задайте себе один вопрос:

> я создаю новый аналитический объект или изменяю существующий?

## Измерение и Metric выполняют разные роли

Во всех четырёх упражнениях повторяется одна модель.

### Измерение

Отвечает на вопрос:

> по чему разделить результат?

Примеры:

```text
Table: Dimensions = region
Bar Chart: X Axis = region
Line Chart: X Axis = sale_date с Time grain = Month
```

### Metric

Отвечает на вопрос:

> что посчитать внутри каждой группы?

Примеры:

```text
SUM(revenue)
total_profit
```

Для столбчатой диаграммы:

```text
region
   ↓
категория

SUM(revenue)
   ↓
высота столбца
```

Для временного графика:

```text
sale_date → Month
   ↓
положение по времени

SUM(revenue)
   ↓
высота точки линии
```

Это важнее запоминания расположения отдельных кнопок.

## Тип Chart не меняет смысл Metric

Например:

```text
Север → 1360
Юг    → 2645
```

можно представить как:

- строки Table;
- два столбца Bar Chart.

Но расчёт остаётся:

```sql
SUM(revenue)
```

Поэтому выбор визуализации и выбор расчёта — разные решения.

## Когда использовать четыре типа из урока

### Table

Используйте, когда важны:

- точные значения;
- несколько показателей одновременно;
- сравнение строк;
- компактный аналитический срез.

### Big Number

Используйте, когда главное — одно итоговое значение.

### Bar Chart

Используйте для сравнения отдельных категорий.

### Line Chart

Используйте, когда ось X имеет естественный временной порядок и нужен тренд.

Не используйте линию для набора независимых категорий только потому, что линия выглядит аккуратно: соединение точек визуально подразумевает последовательность.

## Типичные ошибки

### График пустой

Сначала проверьте:

```text
Filters
```

Учебные данные находятся в январе–марте 2026 года.

Для упражнений этого урока временное ограничение не нужно. Если отображается `sale_date`, оставьте:

```text
No filter
```

### Получилось одно число вместо двух регионов в Table

Проверьте:

```text
Dimensions = region
```

Без измерения Superset агрегирует все строки вместе.

### Получилось 4005 вместо 1530

Вы используете выручку вместо прибыли.

Проверьте выбранную Metric:

```text
Прибыль / total_profit
```

для Big Number.

### Временной график показывает дни вместо месяцев

Проверьте:

```text
Time grain = Month
```

для `X Axis = sale_date`.

### После изменения появилось два почти одинаковых Chart

Вероятно, при сохранении существующего Chart был выбран:

```text
Save as...
```

вместо:

```text
Save (Overwrite)
```

### Chart исчез после закрытия вкладки

Скорее всего, вы выполнили конфигурацию через `Create chart`, но не сохранили объект через `Save`.

```text
Create chart / Update chart
→ выполнить текущую конфигурацию Explore

Save
→ открыть диалог сохранения Chart
```

## Попробуйте сами

Нужно ответить на вопрос:

> Какова общая выручка по всем 12 строкам?

Наиболее естественный вариант для одного KPI:

```text
Big Number
```

с:

```text
SUM(revenue)
```

В `Filters` не должно быть активных ограничений.

Контрольный результат:

```text
4005.00
```

Этот тренировочный Chart сохранять не обязательно.

## Что должно получиться

К концу урока одновременно выполнены следующие условия:

- Dataset `sales` по-прежнему один;
- Calculated column `profit` не изменён;
- сохранённая Metric `total_profit` не изменена;
- создан Chart `Продажи по регионам — таблица`;
- создан Chart `Общая прибыль`;
- создан Chart `Выручка по регионам — столбцы`;
- создан Chart `Выручка по месяцам`;
- все четыре находятся через список `Charts`;
- `Общая прибыль` показывает `1530.00`;
- столбчатая диаграмма показывает `1360.00` и `2645.00`;
- временной Chart показывает `1160.00`, `1180.00`, `1665.00` по трём месяцам;
- для нового Chart вы используете `Create chart`, а для сохранённого — `Update chart`;
- вы умеете открыть сохранённый Chart, изменить параметр отображения и сохранить изменение через `Save (Overwrite)`.

Если это выполняется, базовый цикл работы с Chart освоен.
