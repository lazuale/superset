# 12. Итоговая проверка и что изучать дальше

Здесь новых функций уже не будет. Это самостоятельная работа на чистом стенде: нужно воспроизвести весь базовый маршрут без пошаговых подсказок и проверить себя по известным числам.

Смысл не в том, чтобы помнить расположение каждой кнопки. Важно уметь самому восстановить цепочку от источника данных до готового Dashboard и Virtual Dataset.

## Начинаем с чистого стенда

Из корня репозитория:

```bash
cd training
docker compose down -v --remove-orphans
docker compose up -d
```

После инициализации проверьте:

```bash
docker compose ps -a
```

Ожидается:

```text
db             running / healthy
superset       running / healthy
superset-init  exited (0)
```

Затем:

```bash
docker compose exec -T db \
  psql -U training -d training -f /training/check.sql
```

После полного сброса все объекты Superset из предыдущих уроков удалены. Их придётся создать заново — именно это и нужно для проверки.

## Исходные данные задания

Superset:

```text
http://localhost:8088
login:    admin
password: admin
```

PostgreSQL внутри Compose-сети:

```text
host:     db
port:     5432
database: training
user:     superset_reader
password: superset_reader
```

Источник:

```text
database: training
schema:   training
table:    sales
```

Физические поля:

```text
sale_id
sale_date
region
office
manager
product
quantity
revenue
cost
```

Физического столбца `profit` в PostgreSQL нет.

## Часть 1. Восстановите базовую модель Superset

Создайте подключение:

```text
Training PostgreSQL
```

Используйте `superset_reader`, проверьте соединение и убедитесь, что видны схема `training` и таблица `sales`.

После этого зарегистрируйте `training.sales` как Physical Dataset:

```text
sales
```

В Dataset должны быть девять физических столбцов, а `sale_date` должен определяться как временной (`Is temporal`).

## Часть 2. Решите четыре задачи в Explore

SQL Lab пока не используйте.

Нужно получить ответы на четыре вопроса:

1. Какова выручка каждого региона по всем данным?
2. Какова выручка каждого региона только за февраль 2026 года?
3. Как менялась общая выручка по месяцам?
4. Какова общая выручка Севера, если `region` используется только как обычный Filter, а не как Dimension?

Какие `Dimension`, `Metric`, `Filter`, `Time range` и `Time grain` нужны — определите сами.

## Часть 3. Восстановите расчёт прибыли

Для одной продажи:

```text
profit = revenue - cost
```

Создайте Calculated Column:

```text
profit
```

Затем сохранённую Metric:

```text
Metric Key: total_profit
Label:      Прибыль
```

Она должна считать общую прибыль через агрегированные `revenue` и `cost`.

Проверьте оба варианта на всех данных и по регионам. Если не можете словами объяснить, чем Calculated Column отличается от Metric, к следующей части лучше не переходить.

## Часть 4. Сохраните четыре Chart

На Dataset `sales` должны появиться:

```text
Продажи по регионам — таблица
Общая прибыль
Выручка по регионам — столбцы
Выручка по месяцам
```

Подберите тип визуализации по смыслу задачи самостоятельно.

После сохранения откройте один из существующих Chart, поменяйте только визуальную настройку и сохраните **тот же объект**. В списке должно остаться четыре основных Chart, а не пять из-за случайного `Save as...`.

## Часть 5. Соберите Dashboard

Создайте:

```text
Учебные продажи
```

Разместите на нём все четыре Chart. KPI должен быть заметен, сравнение регионов и динамика — читаться отдельно, а таблица — оставаться доступной для проверки точных чисел.

Сохраните Dashboard и переведите его из `Draft` в `Published`.

Затем снова откройте панель из списка, измените размер или положение одного блока, сохраните и ещё раз проверьте, что изменение осталось.

## Часть 6. Настройте Native Filters

Нужны три фильтра:

- `Период` — действует на все четыре Chart;
- `Регион` — действует на все четыре Chart;
- `Менеджер` — действует только на таблицу и Big Number.

Проверьте три сценария:

```text
Регион = Север
```

```text
Менеджер = Анна
```

```text
февраль 2026 + Регион = Север + Менеджер = Анна
```

Смотрите не только на те Chart, которые изменились, но и на те, которые **не должны** реагировать на менеджера.

После проверки очистите фильтры.

## Часть 7. Повторите расчёты в SQL Lab

Не копируйте запросы из урока 10. Самостоятельно получите:

- количество всех строк;
- количество строк с заполненным `manager`;
- количество разных непустых менеджеров;
- общую выручку;
- общую прибыль;
- выручку и прибыль регионов за февраль;
- выручку по месяцам.

Результаты должны совпасть с теми же вопросами в Explore и Dashboard.

## Часть 8. Создайте Virtual Dataset

В SQL Lab подготовьте построчный запрос к `training.sales`, который сохраняет исходные девять полей и добавляет:

```text
profit = revenue - cost
```

Продажи заранее не агрегируйте.

Сохраните результат как:

```text
sales_virtual
```

Проверьте:

```text
sales         → Physical
sales_virtual → Virtual
```

Физическая таблица `sales_virtual` в PostgreSQL появиться не должна.

На `sales_virtual` создайте Chart:

```text
Прибыль по регионам — Virtual Dataset
```

и убедитесь, что его источник — именно `sales_virtual`.

## Эталонные результаты

Сюда лучше смотреть только после самостоятельной попытки.

### Исходные данные

```text
rows     = 12
quantity = 31
revenue  = 4005.00
cost     = 2475.00
profit   = 1530.00
```

### Регионы

| region | revenue | profit |
|---|---:|---:|
| Север | 1360.00 | 520.00 |
| Юг | 2645.00 | 1010.00 |

### Февраль 2026

Диапазон:

```text
2026-02-01 <= sale_date < 2026-03-01
```

| region | revenue | profit |
|---|---:|---:|
| Север | 450.00 | 175.00 |
| Юг | 730.00 | 285.00 |

Итого:

```text
revenue = 1180.00
profit  = 460.00
```

### По месяцам

| month | revenue |
|---|---:|
| 2026-01 | 1160.00 |
| 2026-02 | 1180.00 |
| 2026-03 | 1665.00 |

### Обычный Filter в Explore

При:

```text
region = Север
```

без группировки по `region` должно получиться одно значение:

```text
1360.00
```

Если видны две региональные группы, `region` всё ещё находится в Dimension.

### Четыре основных Chart

| Имя | Тип | Контроль |
|---|---|---|
| `Продажи по регионам — таблица` | `Table` | Север 1360 / 520; Юг 2645 / 1010 |
| `Общая прибыль` | `Big Number` | 1530.00 |
| `Выручка по регионам — столбцы` | `Bar Chart` | Север 1360; Юг 2645 |
| `Выручка по месяцам` | `Line Chart` | 1160; 1180; 1665 |

Другой тип визуализации не обязательно ошибочен, если он отвечает задаче. Но базовый курс всё равно предполагает, что `Table`, `Big Number`, `Bar Chart` и `Line Chart` вы умеете собрать руками.

### Native Filters

`Регион = Север` должен дать:

```text
revenue = 1360.00
profit  = 520.00
```

и динамику:

```text
2026-01 = 350.00
2026-02 = 450.00
2026-03 = 560.00
```

`Менеджер = Анна` меняет только Table и Big Number:

```text
Север → revenue = 750.00, profit = 285.00
Big Number = 285.00
```

Bar Chart и Line Chart остаются общими.

При комбинации `февраль + Север + Анна` Table и Big Number должны показать:

```text
revenue = 180.00
profit  = 70.00
```

А графики вне `Scoping` менеджера:

```text
Bar Chart: Север = 450.00
Line Chart: 2026-02 = 450.00
```

### SQL Lab

```text
COUNT(*)               = 12
COUNT(manager)          = 11
COUNT(DISTINCT manager) = 4
SUM(revenue)            = 4005.00
profit                  = 1530.00
```

### Virtual Dataset

`sales_virtual`:

```text
12 строк
10 столбцов
1 строка = 1 продажа
profit присутствует
```

Chart на нём:

```text
Север = 520.00
Юг    = 1010.00
```

## Что изучать после базы

Не нужно открывать весь Superset подряд. Следующий блок выбирайте под реальную задачу.

Если появляется вопрос доступа к данным — изучайте роли, permissions и row-level security.

Если система готовится к реальной эксплуатации — развёртывание, служебную БД метаданных, кэширование, Celery/Redis.

Для рассылок и доставки результатов — Alerts & Reports.

Для более сложной модели данных — JOIN, CTE, оконные функции, витрины и зерно данных.

Для более сложных Dashboard — cross-filtering, drill и дополнительные Native Filters.

Для интеграции с другими системами — API и embedding.

И отдельно после всей практики полезно ещё раз вернуться к вопросу, [где заканчивается Superset](12a-what-belongs-in-superset.md). После 11 практических уроков эта граница воспринимается уже совсем иначе, чем в начале курса.
