# 12. Итоговая проверка и что изучать дальше

## Задача урока

**Новых функций здесь нет.**

Это не сокращённое повторение предыдущих инструкций, а итоговая самостоятельная работа.

Нужно на чистом учебном стенде без пошагового маршрута воспроизвести базовый цикл:

```text
PostgreSQL
    ↓
Database connection
    ↓
Physical Dataset
    ↓
Explore
    ↓
Calculated Column + saved Metric
    ↓
4 базовых Chart
    ↓
Dashboard
    ↓
Native Filters + selective Scoping
    ↓
SQL Lab
    ↓
Virtual Dataset
    ↓
Chart на Virtual Dataset
```

Если задачи ниже выполняются самостоятельно и контрольные результаты совпадают, базовый курс пройден.

## Правила итоговой проверки

Во время первой попытки:

1. читайте только условие текущего задания;
2. не открывайте пошаговые уроки 03–11 заранее;
3. сами выбирайте нужный экран, поля Explore, агрегации и тип Chart;
4. после выполнения всех заданий сверяйтесь с разделом **«Эталонные результаты»**;
5. если застряли, используйте таблицу **«К какому уроку возвращаться»** в конце.

Смысл проверки — не вспомнить расположение каждой кнопки наизусть, а уметь самостоятельно собрать правильную аналитическую цепочку.

## Чистый старт

Итоговую проверку выполняйте на чистом учебном стенде.

Из корневого каталога репозитория:

```bash
cd training
docker compose down -v --remove-orphans
docker compose up -d
```

Проверьте:

```bash
docker compose ps -a
```

После завершения инициализации ожидается:

```text
db             running / healthy
superset       running / healthy
superset-init  exited (0)
```

Проверьте исходные данные:

```bash
docker compose exec -T db \
  psql -U training -d training -f /training/check.sql
```

Только после этого начинайте задания Superset.

Полный сброс удаляет результаты предыдущих уроков из metadata Superset и учебной PostgreSQL. После запуска объекты Superset нужно создать заново.

## Задания

### 1. Подключите источник данных

Самостоятельно создайте в Superset Database connection:

```text
Training PostgreSQL
```

Требования:

- подключение использует `superset_reader`;
- тест соединения проходит;
- Superset видит schema `training` и table `sales`.

Не используйте владельца базы `training` как учётную запись Superset.

### 2. Создайте Physical Dataset

Зарегистрируйте `training.sales` как Physical Dataset:

```text
sales
```

Проверьте самостоятельно:

- источник — `Training PostgreSQL / training / sales`;
- в Dataset девять физических столбцов;
- `sale_date` распознаётся как temporal column.

После сохранения откройте Dataset в Explore.

### 3. Ответьте на четыре вопроса в Explore

Не используйте SQL Lab.

#### Вопрос A

> Какова выручка каждого региона по всем данным?

#### Вопрос B

> Какова выручка каждого региона только за февраль 2026 года?

#### Вопрос C

> Как менялась общая выручка по месяцам?

#### Вопрос D

> Какова общая выручка только Севера, если оставить регион через обычный `Filter` в Explore, а не группировать результат по `region`?

Самостоятельно определите:

```text
Dimension
Metric
обычный Filter
Time range
Time grain, если он нужен
```

На этом этапе Chart сохранять не требуется.

### 4. Создайте два разных уровня расчёта

Бизнес-определение прибыли одной продажи:

```text
profit = revenue - cost
```

Создайте в Physical Dataset Calculated Column:

```text
profit
```

Затем создайте повторно используемую сохранённую Metric:

```text
Metric Key: total_profit
Label:      Прибыль
```

Metric должна считать общую прибыль выбранных строк через агрегированные `revenue` и `cost`.

После сохранения убедитесь, что можете словами объяснить разницу:

```text
Calculated Column
→ значение одной строки

Metric
→ показатель набора строк после фильтрации и группировки
```

Проверьте оба способа расчёта по всем данным и по регионам.

### 5. Создайте четыре базовых Chart

На Dataset `sales` сохраните четыре самостоятельных Chart.

#### Chart A — точные показатели по регионам

Должен одновременно показывать:

```text
выручку
прибыль
```

для каждого региона.

Имя:

```text
Продажи по регионам — таблица
```

#### Chart B — один KPI

Должен показывать общую прибыль одним числом.

Имя:

```text
Общая прибыль
```

#### Chart C — сравнение категорий

Должен позволять взглядом сравнить выручку Севера и Юга.

Имя:

```text
Выручка по регионам — столбцы
```

#### Chart D — динамика

Должен показывать общую выручку по месяцам.

Имя:

```text
Выручка по месяцам
```

Тип визуализации для каждой задачи выберите самостоятельно.

После сохранения откройте один из существующих Chart, измените только визуальную настройку и сохраните **тот же объект**, не создавая копию.

В результате в `Charts` по-прежнему должны быть четыре основных объекта, а не пять из-за случайного `Save as...`.

### 6. Соберите Dashboard

Создайте Dashboard:

```text
Учебные продажи
```

Добавьте все четыре Chart из предыдущего задания.

Самостоятельно организуйте layout так, чтобы:

- KPI был заметен;
- сравнение регионов и динамика читались отдельно;
- точная таблица оставалась доступной для проверки;
- блоки не перекрывали друг друга.

Сохраните Dashboard и переведите его из:

```text
Draft
```

в:

```text
Published
```

После этого:

1. выйдите из Dashboard в общий список;
2. откройте его снова;
3. войдите в режим редактирования;
4. измените размер или положение одного блока;
5. сохраните;
6. ещё раз откройте Dashboard и убедитесь, что layout сохранился.

### 7. Настройте Native Filters и докажите, что понимаете Scoping

Создайте три Native Filter.

#### Период

Назначение:

> ограничивать период данных на всех четырёх Chart.

#### Регион

Назначение:

> выбирать регион на всех четырёх Chart.

#### Менеджер

Назначение:

> фильтровать **только** `Продажи по регионам — таблица` и `Общая прибыль`.

`Выручка по регионам — столбцы` и `Выручка по месяцам` должны оставаться вне Scoping фильтра `Менеджер`.

Проведите три проверки:

1. только `Регион = Север`;
2. только `Менеджер = Анна`;
3. одновременно февраль 2026 + `Регион = Север` + `Менеджер = Анна`.

После каждой проверки смотрите не только на изменившиеся Chart, но и на те Chart, которые **не должны** измениться из-за selective Scoping.

В конце очистите все фильтры.

### 8. Повторите основные расчёты в SQL Lab

Не копируйте SQL из урока 10.

Самостоятельно получите:

1. количество всех строк;
2. количество строк с заполненным `manager`;
3. количество разных непустых менеджеров;
4. общую выручку;
5. общую прибыль;
6. выручку и прибыль каждого региона за февраль 2026 года;
7. выручку по месяцам.

Проверьте, что результаты SQL Lab совпадают с теми же аналитическими вопросами в Explore и Dashboard.

### 9. Создайте Virtual Dataset

В SQL Lab подготовьте **построчный** запрос к `training.sales`, который:

- сохраняет исходные девять полей;
- добавляет десятое поле `profit` как `revenue - cost`;
- не агрегирует продажи заранее.

Сохраните результат как Virtual Dataset:

```text
sales_virtual
```

Самостоятельно вспомните маршрут сохранения из SQL Lab — он здесь намеренно не приведён пошагово.

Проверьте:

```text
sales         → Physical
sales_virtual → Virtual
```

`training.sales` в PostgreSQL остаётся исходной таблицей; физическая таблица `sales_virtual` появиться не должна.

### 10. Создайте Chart на Virtual Dataset

На `sales_virtual` создайте и сохраните Chart, который сравнивает прибыль регионов.

Имя:

```text
Прибыль по регионам — Virtual Dataset
```

После сохранения найдите его через `Charts`, снова откройте и убедитесь, что источник Chart:

```text
sales_virtual
```

а не Physical Dataset `sales`.

## Эталонные результаты

Сверяйтесь с этим разделом **после самостоятельной попытки**.

### Исходные данные

```text
rows     = 12
quantity = 31
revenue  = 4005.00
cost     = 2475.00
profit   = 1530.00
```

### Explore: регионы

| region | revenue | profit |
|---|---:|---:|
| Север | 1360.00 | 520.00 |
| Юг | 2645.00 | 1010.00 |

### Explore: февраль 2026

Для полного февраля используется диапазон:

```text
2026-02-01 <= sale_date < 2026-03-01
```

| region | revenue | profit |
|---|---:|---:|
| Север | 450.00 | 175.00 |
| Юг | 730.00 | 285.00 |

Итого:

```text
revenue = 1180.00
profit  = 460.00
```

### Explore: месяцы

| month | revenue |
|---|---:|
| 2026-01 | 1160.00 |
| 2026-02 | 1180.00 |
| 2026-03 | 1665.00 |

### Explore: обычный Filter

При обычном Explore Filter:

```text
region = Север
```

и без группировки по `region` общая выручка должна быть:

```text
1360.00
```

Если вместо одного результата получены две региональные группы, `region` всё ещё используется как Dimension.

### Четыре Chart

Ожидаемый смысл и подходящий UI type:

| Имя | UI type | Контроль |
|---|---|---|
| `Продажи по регионам — таблица` | `Table` | Север 1360 / 520; Юг 2645 / 1010 |
| `Общая прибыль` | `Big Number` | 1530.00 |
| `Выручка по регионам — столбцы` | `Bar Chart` | Север 1360; Юг 2645 |
| `Выручка по месяцам` | `Line Chart` | 1160; 1180; 1665 |

Если выбран другой Chart и он действительно отвечает условию, это не автоматически ошибка. Но базовый курс считается освоенным только если вы умеете самостоятельно работать с `Table`, `Big Number`, `Bar Chart` и `Line Chart`, поэтому эти четыре типа должны быть воспроизведены в итоговой работе.

### Native Filters

#### Регион = Север

Все четыре Chart должны учитывать Север.

Контроль:

```text
revenue = 1360.00
profit  = 520.00
```

Динамика выручки Севера:

```text
2026-01 = 350.00
2026-02 = 450.00
2026-03 = 560.00
```

#### Менеджер = Анна

Только Table и Big Number должны измениться.

Table:

```text
Север → revenue = 750.00, profit = 285.00
```

Big Number:

```text
285.00
```

Bar Chart и Line Chart должны сохранить общие значения, потому что находятся вне Scoping фильтра `Менеджер`.

#### Февраль + Север + Анна

Table и Big Number получают все три фильтра:

```text
revenue = 180.00
profit  = 70.00
```

Bar Chart и Line Chart получают только `Период + Регион`:

```text
Bar Chart:
Север = 450.00

Line Chart:
2026-02 = 450.00
```

Если все четыре Chart показывают данные Анны, selective Scoping настроен неправильно.

### SQL Lab

```text
COUNT(*)               = 12
COUNT(manager)          = 11
COUNT(DISTINCT manager) = 4
SUM(revenue)            = 4005.00
profit                  = 1530.00
```

Февраль по регионам:

| region | revenue | profit |
|---|---:|---:|
| Север | 450.00 | 175.00 |
| Юг | 730.00 | 285.00 |

### Virtual Dataset

`sales_virtual` должен возвращать:

```text
12 строк
10 столбцов
1 строка = 1 продажа
profit присутствует
```

Chart на Virtual Dataset:

```text
Север = 520.00
Юг    = 1010.00
```

Курс считается пройденным, если без пошаговых подсказок вы смогли подтвердить весь список:

## Что изучать дальше

Не пытайтесь изучать весь Superset одновременно. После базового курса выбирайте следующий блок под реальную задачу.

Типовые направления:

```text
безопасность и разграничение доступа
→ роли, permissions, row-level security

production-эксплуатация
→ production deployment, metadata DB, кэширование, Celery/Redis

автоматическая доставка
→ Alerts & Reports

продвинутый SQL и моделирование
→ JOIN, CTE, оконные функции, витрины, grain

расширенные Dashboard
→ cross-filtering, drill, дополнительные Native Filters

встраивание и интеграции
→ API, embedding
```

Это уже следующий уровень. Базовый маршрут 01–12 должен оставаться компактным и воспроизводимым.
