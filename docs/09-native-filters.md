# 09. Добавляем Native Filters

## Что научимся делать

После этого урока вы должны уметь:

- понимать разницу между фильтром внутри `Explore` и `Native Filter` на Dashboard;
- открыть настройку фильтров Dashboard;
- создать фильтр периода;
- создать фильтр по региону;
- создать фильтр по менеджеру;
- выбрать Dataset и столбец для фильтра по значению;
- настроить `Scoping` и понимать, какие Chart входят в область действия фильтра;
- применить несколько фильтров одновременно;
- очистить выбранные значения через `Clear all`;
- проверить работу фильтров по известным контрольным значениям.

В этом уроке мы работаем только с `Native Filters` готового Dashboard.

Не разбираем:

- зависимости фильтров друг от друга;
- cross-filtering по клику на Chart;
- drill-функции;
- фильтры безопасности;
- Dashboard RBAC;
- Jinja и передачу фильтров в SQL.

Эти темы относятся к следующему уровню работы с Superset.

## Что должно быть готово до начала

Должны быть полностью пройдены предыдущие уроки.

Особенно важен [урок 08](08-build-dashboard.md).

В Superset должен существовать опубликованный Dashboard:

```text
Учебные продажи
```

На нём должны находиться четыре Chart из урока 07:

```text
Продажи по регионам — таблица
Общая прибыль
Выручка по регионам — столбцы
Выручка по месяцам
```

Все четыре Chart используют Dataset:

```text
sales
```

Перед началом убедитесь, что Dashboard без фильтров показывает исходные контрольные результаты:

```text
общая выручка = 4005.00
общая прибыль = 1530.00

Север:
выручка = 1360.00
прибыль = 520.00

Юг:
выручка = 2645.00
прибыль = 1010.00
```

Если эти значения уже не совпадают, сначала очистите активные фильтры или верните Chart к состоянию урока 07.

## Что такое Native Filter

В уроке 05 мы использовали фильтр внутри `Explore`.

Такой фильтр является частью конкретного аналитического запроса или сохранённого Chart.

Например:

```text
Chart «Продажи по регионам — таблица»
└── Filters: region = Север
```

Этот фильтр относится к одному Chart.

`Native Filter` находится на уровне Dashboard.

```text
Dashboard
├── Native Filter: Период
├── Native Filter: Регион
├── Native Filter: Менеджер
│
├── Chart 1
├── Chart 2
├── Chart 3
└── Chart 4
```

Один фильтр Dashboard может воздействовать сразу на несколько Chart.

При этом его область действия задаётся отдельно через `Scoping`.

Поэтому нельзя считать, что любой фильтр Dashboard автоматически обязан менять каждый Chart.

## Открываем Dashboard

Перейдите:

```text
Dashboards
```

Откройте:

```text
Учебные продажи
```

Слева или сверху, в зависимости от выбранной ориентации панели фильтров, находится `Filter Bar`.

Для курса оставляем стандартную ориентацию. Менять её не требуется.

## Открываем настройку Native Filters

В `Filter Bar` нажмите значок настроек с шестерёнкой.

В меню выберите:

```text
Add or edit filters and controls
```

Откроется окно конфигурации фильтров.

Для каждого обычного фильтра здесь есть две принципиально разные части:

```text
Settings
Scoping
```

`Settings` отвечает на вопрос:

> что именно пользователь сможет выбирать?

`Scoping` отвечает на вопрос:

> какие Chart должны получить выбранное значение?

Эти понятия не смешиваем.

## Типы фильтров

Для этого урока нужны два типа:

```text
Value      → фильтр по значениям столбца
Time range → фильтр временного диапазона
```

# Фильтр 1. Период

## Что хотим получить

Пользователь Dashboard должен иметь возможность выбрать период и сразу пересчитать все четыре Chart.

## Добавляем фильтр

В окне настройки создайте новый фильтр.

Укажите имя:

```text
Период
```

В качестве типа выберите:

```text
Time range
```

Это фильтр временного диапазона Dashboard.

Он не требует выбора `region`, `manager` или другого категориального столбца.

## Настраиваем Scoping

Перейдите на вкладку:

```text
Scoping
```

В область действия фильтра должны входить все четыре Chart:

```text
Продажи по регионам — таблица
Общая прибыль
Выручка по регионам — столбцы
Выручка по месяцам
```

Проверьте их явно.

```text
Период
  ↓
Scope
  ├── таблица
  ├── Big Number
  ├── столбцы
  └── временной график
```

Сохраните конфигурацию фильтра.

## Проверяем февраль 2026

Вернитесь к Dashboard.

В фильтре:

```text
Период
```

выберите интервал, охватывающий только февраль 2026 года.

Логически нужен диапазон:

```text
2026-02-01 <= sale_date < 2026-03-01
```

После выбора нажмите:

```text
Apply filters
```

Если панель фильтров расположена горизонтально, кнопка отображается короче:

```text
Apply
```

## Контрольные значения для февраля

В феврале в учебной таблице находятся четыре продажи.

Общая выручка:

```text
1180.00
```

Общая прибыль:

```text
460.00
```

По регионам:

| Регион | Выручка | Прибыль |
|---|---:|---:|
| Север | 450.00 | 175.00 |
| Юг | 730.00 | 285.00 |

Временной Chart должен оставить только февральское значение:

```text
2026-02 → 1180.00
```

Если один из четырёх Chart не изменился, сначала проверяйте `Scoping` фильтра `Период`.

## Очищаем фильтр

После проверки нажмите:

```text
Clear all
```

Dashboard должен вернуться к исходным значениям:

```text
выручка = 4005.00
прибыль = 1530.00
```

# Фильтр 2. Регион

Теперь создадим фильтр по значению столбца Dataset.

## Открываем конфигурацию

Снова откройте:

```text
Filter Bar → настройки → Add or edit filters and controls
```

Добавьте новый фильтр.

Имя:

```text
Регион
```

Тип:

```text
Value
```

## Выбираем источник значений

Для фильтра `Value` нужно определить Dataset и столбец.

Укажите:

```text
Dataset: sales
Column:  region
```

Именно из этого столбца Superset получает значения фильтра.

В наших данных ожидаются:

```text
Север
Юг
```

Отличие двух типов:

```text
Период
→ Time range
→ передаёт временной диапазон

Регион
→ Value
→ фильтрует по значениям конкретного столбца Dataset
```

Дополнительные настройки вроде обязательности значения, множественного выбора и значения по умолчанию пока не меняйте, если они не требуются для базового сценария.

## Настраиваем Scope

Перейдите:

```text
Scoping
```

Для фильтра `Регион` включите все четыре Chart.

Причина проста: все они используют один Dataset `sales`, и во всех четырёх сценариях ограничение по региону имеет понятный смысл.

Сохраните фильтр.

## Проверяем Север

На Dashboard выберите:

```text
Регион = Север
```

Нажмите:

```text
Apply filters
```

Контрольные значения:

```text
выручка = 1360.00
прибыль = 520.00
```

Таблица должна оставить только строку:

| Регион | Выручка | Прибыль |
|---|---:|---:|
| Север | 1360.00 | 520.00 |

Столбчатая диаграмма должна оставить категорию:

```text
Север → 1360.00
```

Временной Chart должен показывать выручку только региона `Север`:

| Месяц | Выручка |
|---|---:|
| 2026-01 | 350.00 |
| 2026-02 | 450.00 |
| 2026-03 | 560.00 |

Проверка суммы:

```text
350 + 450 + 560 = 1360
```

Теперь выберите:

```text
Регион = Юг
```

и снова примените фильтры.

Ожидается:

```text
выручка = 2645.00
прибыль = 1010.00
```

После проверки нажмите:

```text
Clear all
```

# Фильтр 3. Менеджер

Третий фильтр нужен не только для выбора менеджера. На нём разберём `Scope` так, чтобы его действие было видно сразу.

## Создаём фильтр

Откройте:

```text
Filter Bar → настройки → Add or edit filters and controls
```

Добавьте фильтр:

```text
Имя:     Менеджер
Тип:     Value
Dataset: sales
Column:  manager
```

В учебных данных есть четыре непустых значения:

```text
Анна
Борис
Клара
Денис
```

Также в одной строке `manager = NULL`.

Наличие `NULL` не означает, что в список обязательно должна отображаться отдельная удобная категория «пусто». Для базового упражнения выбираем только конкретных менеджеров.

## Ограничиваем Scope

Откройте:

```text
Scoping
```

На этот раз **не включайте все Chart**.

Оставьте в Scope только:

```text
Продажи по регионам — таблица
Общая прибыль
```

Исключите:

```text
Выручка по регионам — столбцы
Выручка по месяцам
```

```text
Менеджер
   ↓
Scope
   ├── Продажи по регионам — таблица   ✓
   ├── Общая прибыль                   ✓
   ├── Выручка по регионам — столбцы   ✗
   └── Выручка по месяцам              ✗
```

Сохраните конфигурацию.

Это намеренно искусственное ограничение для упражнения. Его задача — сделать работу `Scope` очевидной.

## Проверяем Scope на Анне

Перед проверкой убедитесь, что другие фильтры очищены:

```text
Clear all
```

Затем выберите:

```text
Менеджер = Анна
```

Нажмите:

```text
Apply filters
```

### Chart внутри Scope

Таблица должна измениться.

Анна работает только с регионом `Север`, поэтому ожидается:

| Регион | Выручка | Прибыль |
|---|---:|---:|
| Север | 750.00 | 285.00 |

`Big Number` должен показать:

```text
285.00
```

### Chart вне Scope

Столбчатая диаграмма не должна получить фильтр `Менеджер`.

На ней по-прежнему остаются исходные значения:

```text
Север → 1360.00
Юг    → 2645.00
```

Временной Chart тоже должен остаться без фильтра по менеджеру:

```text
2026-01 → 1160.00
2026-02 → 1180.00
2026-03 → 1665.00
```

Вот это и есть практический смысл `Scope`.

Фильтр существует на Dashboard, но получает его только выбранная часть Chart.

## Почему Scope нельзя игнорировать

Представьте рабочий Dashboard, где есть:

```text
общие показатели подразделения
личные показатели сотрудника
технические показатели системы
```

Фильтр `Сотрудник` может быть логичен для второй группы и бессмысленен для третьей.

Если бездумно отправлять его во все Chart, Dashboard начинает давать странные или пустые результаты.

Поэтому для каждого Native Filter нужно уметь ответить на два вопроса:

```text
1. что фильтруем?
2. какие Chart должны это получить?
```

Первый вопрос решается через `Settings`.

Второй — через `Scoping`.

# Несколько фильтров одновременно

Сначала очистите всё:

```text
Clear all
```

Установите:

```text
Период = февраль 2026
Регион = Север
```

Фильтр `Менеджер` оставьте пустым.

Нажмите:

```text
Apply filters
```

Оба фильтра входят в Scope всех четырёх Chart.

Значит Dashboard должен использовать пересечение условий:

```text
февраль 2026
AND
region = Север
```

Контроль:

```text
выручка = 450.00
прибыль = 175.00
```

Таблица:

| Регион | Выручка | Прибыль |
|---|---:|---:|
| Север | 450.00 | 175.00 |

Столбцы:

```text
Север → 450.00
```

Временной Chart:

```text
2026-02 → 450.00
```

## Добавляем Менеджера к уже выбранным фильтрам

Теперь дополнительно выберите:

```text
Менеджер = Анна
```

и примените фильтры.

Поскольку `Менеджер` входит только в Scope таблицы и Big Number:

```text
таблица и Big Number
→ Период + Регион + Менеджер

столбцы и временной график
→ только Период + Регион
```

Для Анны в феврале на Севере есть одна продажа:

```text
revenue = 180.00
cost    = 110.00
profit  = 70.00
```

Поэтому:

```text
таблица:
Север → выручка 180.00, прибыль 70.00

Big Number:
70.00
```

А два Chart вне Scope фильтра `Менеджер` должны продолжать показывать февральский Север целиком:

```text
выручка = 450.00
```

Если они тоже стали показывать `180.00`, значит фильтр `Менеджер` случайно включён в их Scope.

После проверки нажмите:

```text
Clear all
```

## Apply filters и Clear all

В Superset 6.1.0 выбранные значения фильтров и применённые значения — не одно и то же действие.

После изменения значения используйте:

```text
Apply filters
```

или при горизонтальной панели:

```text
Apply
```

Чтобы удалить текущие выбранные значения, используйте:

```text
Clear all
```

После `Clear all` Dashboard должен вернуться к исходному состоянию.

Не путайте:

```text
Clear all
→ очищает выбранные значения фильтров

удаление фильтра в конфигурации
→ удаляет сам Native Filter с Dashboard
```

## Native Filter не меняет исходные данные

После выбора:

```text
Регион = Север
```

из PostgreSQL ничего не удаляется.

Dataset тоже не переписывается.

```text
Dashboard
   ↓
Native Filter
   ↓
Chart в Scope
   ↓
дополнительное условие запроса
   ↓
PostgreSQL
```

После `Clear all` снова доступны все строки.

Поэтому Native Filters — это интерактивные условия аналитического запроса, а не механизм изменения данных.

## Native Filter не является системой прав

Фильтр:

```text
Регион = Север
```

не означает:

> пользователь имеет право видеть только Север.

Пользователь может очистить фильтр или выбрать другое значение, если его права позволяют читать Dataset.

Ограничение доступа к данным решается механизмами безопасности и прав, а не Native Filters.

В базовый курс RBAC/RLS не входит.

## Типовые ошибки

### Фильтр есть, но Chart не меняется

Проверяйте по порядку:

```text
1. нажали ли Apply filters;
2. входит ли Chart в Scoping;
3. выбран ли правильный Dataset;
4. выбран ли правильный Column для фильтра Value;
5. действительно ли Chart работает на ожидаемом Dataset;
6. нет ли внутри самого Chart другого ограничения, которое делает результат пустым.
```

### Регион работает на одних Chart и не работает на других

Первым делом смотрите:

```text
Scoping
```

Не пересоздавайте Dataset и не переделывайте Chart, пока не проверили Scope.

### После выбора периода пусто

Наши данные существуют только в диапазоне:

```text
2026-01-05 … 2026-03-24
```

Если выбрать текущий месяц или последние семь дней относительно сегодняшней даты, результат будет пустым.

Для учебных проверок используйте январь, февраль или март 2026 года.

### В списке менеджеров нет отдельного понятного значения для NULL

Это не ошибка.

В исходных данных одна запись имеет:

```text
manager = NULL
```

Фильтр типа `Value` используется здесь для выбора конкретных непустых менеджеров.

### После выбора значения ничего не происходит сразу

Нажмите:

```text
Apply filters
```

Значение в поле фильтра и применённый к Chart фильтр — отдельные состояния интерфейса.

## Самостоятельная проверка

### Задание 1

```text
Регион = Юг
```

Ожидается:

```text
выручка = 2645.00
прибыль = 1010.00
```

### Задание 2

Только февраль 2026 года:

```text
выручка = 1180.00
прибыль = 460.00
```

### Задание 3

```text
Период = февраль 2026
Регион = Юг
```

Ожидается:

```text
выручка = 730.00
прибыль = 285.00
```

### Задание 4

Очистите период и регион.

Выберите:

```text
Менеджер = Клара
```

Для Chart внутри Scope фильтра `Менеджер` ожидается:

```text
выручка = 1250.00
прибыль = 465.00
```

При этом столбчатая диаграмма и временной Chart должны сохранить исходные общие значения, потому что они исключены из Scope этого фильтра.

## Что должно остаться после урока

На Dashboard `Учебные продажи` должны существовать три Native Filter:

| Фильтр | Тип | Dataset / Column | Scope |
|---|---|---|---|
| Период | `Time range` | временной диапазон | все 4 Chart |
| Регион | `Value` | `sales.region` | все 4 Chart |
| Менеджер | `Value` | `sales.manager` | только таблица и Big Number |

Перед завершением урока очистите активные значения:

```text
Clear all
```

Dashboard должен снова показывать:

```text
общая выручка = 4005.00
общая прибыль = 1530.00
```

## Критерий завершения урока

Урок завершён, если вы можете без подсказки:

1. открыть конфигурацию Native Filters;
2. создать фильтр `Value` на конкретном Dataset и Column;
3. создать фильтр `Time range`;
4. открыть `Scoping`;
5. включить и исключить конкретные Chart из Scope;
6. применить фильтр через `Apply filters`;
7. очистить значения через `Clear all`;
8. объяснить, почему один и тот же фильтр может менять только часть Dashboard;
9. объяснить, почему Native Filter не является механизмом ограничения доступа к данным.

## Что дальше

К этому моменту учебная цепочка выглядит так:

```text
PostgreSQL
   ↓
Database
   ↓
Dataset
   ↓
Explore
   ↓
Metric + Calculated column
   ↓
Chart
   ↓
Dashboard
   ↓
```
