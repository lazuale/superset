# Шпаргалка к урокам 05–07. Почему цифры в Superset не сходятся

Если график не показывает ошибку, но число выглядит подозрительно, не меняйте сразу несколько настроек. Разберите расчёт сверху вниз и найдите первый уровень, где результат перестаёт совпадать с ожиданием.

## Порядок проверки

```text
1. Тот ли Dataset?
2. Правильный ли период?
3. Нет ли лишних фильтров?
4. Нужные ли измерения?
5. Метрика отвечает на нужный вопрос?
6. Правильная ли агрегация?
7. Учтены ли NULL?
8. Понятно ли зерно Dataset?
9. Если Dataset подготовлен SQL — JOIN не размножил строки?
10. Контрольный SQL даёт тот же результат?
```

## 1. Dataset

Сначала убедитесь, что Explore открыт на нужном Dataset.

Похожие Dataset могут отличаться исходной таблицей, SQL, фильтрами внутри SQL, набором колонок и зерном. Если выбран не тот источник, дальнейшая проверка настроек уже бессмысленна.

## 2. Период

В учебном наборе данные находятся только в январе–марте 2026 года.

Для всего февраля:

```text
2026-02-01 <= sale_date < 2026-03-01
```

Если график пустой или показывает только часть данных, `Time range` стоит проверить одним из первых.

→ [Time column, Time range и Time grain](05b-time-range-and-grain.md)

## 3. Фильтры

Проговорите каждый активный фильтр словами.

Например:

```text
region = Север
```

при вопросе «какова общая выручка всех регионов?» уже делает результат неправильным для поставленной задачи, хотя сам Superset считает корректно.

## 4. Измерения

Если ожидались две группы — Север и Юг, — а получено одно итоговое число, проверьте, добавлен ли `region` как измерение (`Dimension`).

Если групп неожиданно слишком много, ищите лишнее измерение.

## 5. Метрика и агрегация

Полезно проговорить расчёт обычными словами:

```text
COUNT(*)
→ количество строк

COUNT(manager)
→ строки с непустым manager

COUNT_DISTINCT(manager)
→ разные manager

SUM(revenue)
→ сумма revenue
```

Если словесная формулировка не совпадает с бизнес-вопросом, метрика выбрана неправильно.

→ [Как выбрать агрегирование](06a-aggregations.md)

## 6. NULL

В `training.sales`:

```text
COUNT(*)       = 12
COUNT(manager) = 11
```

Это правильный результат: одна строка имеет `manager = NULL`.

## 7. Зерно Dataset

Спросите:

```text
1 строка = что?
```

Для `training.sales`:

```text
1 строка = 1 продажа
```

Если строка фактически представляет позицию документа, транзакцию или другой более детальный объект, `COUNT(*)` может считать не то, что вы думаете.

→ [Зерно Dataset](06c-data-grain.md)

## 8. JOIN проверяйте только там, где он действительно есть

JOIN не является частью базовых упражнений 05–07. Но если используемый Dataset подготовлен SQL-запросом с JOIN и итог стал кратно больше, проверьте размножение строк.

Характерные признаки:

```text
COUNT(*) вырос
COUNT(DISTINCT id) не вырос
SUM стала кратно больше
один id неожиданно повторяется
```

→ [JOIN без размножения данных](10b-join-without-duplication.md)

## 9. Упростите график

Для диагностики временно оставьте:

```text
Visualization = Table
Dimension     = одна
Metric        = одна
Filters       = только необходимые
```

Сначала получите правильное число в простой таблице. После этого возвращайте остальные настройки по одной.

## 10. Сравните с контрольным SQL

Пример:

```sql
SELECT
    region,
    SUM(revenue) AS revenue
FROM training.sales
GROUP BY region
ORDER BY region;
```

Ожидается:

```text
Север = 1360.00
Юг    = 2645.00
```

Если SQL и график различаются, сопоставьте одинаковые роли:

```text
FROM      ↔ Dataset
WHERE     ↔ Filters / Time range
GROUP BY  ↔ Dimensions
SUM/COUNT ↔ Metric
```

## Таблица симптомов

| Симптом | Сначала проверить |
|---|---|
| график пустой | Time range, Filters, Dataset |
| число меньше ожидаемого | фильтры, период, NULL |
| число больше ожидаемого | агрегацию, зерно; при SQL-Dataset — JOIN |
| число выросло кратно | JOIN / дублирование строк |
| одна строка вместо нескольких групп | измерения |
| слишком много групп | лишние измерения |
| считаются строки вместо объектов | `COUNT(*)` и `COUNT_DISTINCT` |
| вместо месяцев появились дни | Time grain |
| среднее странное | уровень данных, веса, зерно |
| SQL и график различаются | Dataset, фильтры, измерение, метрика, период |

## Контрольные числа курса

```text
rows     = 12
quantity = 31
revenue  = 4005.00
cost     = 2475.00
profit   = 1530.00
```

По регионам:

```text
Север: revenue = 1360.00, profit = 520.00
Юг:    revenue = 2645.00, profit = 1010.00
```

Февраль:

```text
revenue = 1180.00
```

Менеджеры:

```text
COUNT(*)               = 12
COUNT(manager)          = 11
COUNT_DISTINCT(manager) = 4
```

В итоге Dataset, фильтры, измерения, метрика и агрегация должны отвечать одному и тому же вопросу. Если хотя бы один слой отвечает на другой вопрос, Superset вполне может вернуть корректное SQL-число, которое будет неправильным по смыслу.
