# Справочник к уроку 06. Как выбрать SUM, COUNT, COUNT DISTINCT, AVG, MIN и MAX

Эта шпаргалка нужна, когда колонка выбрана правильно, но непонятно, **как именно её считать**.

Главная мысль:

> одна и та же колонка с разным агрегированием отвечает на разные вопросы.

Например, для `manager`:

```text
COUNT(manager)
→ сколько строк имеют заполненного manager

COUNT_DISTINCT(manager)
→ сколько разных manager встречается
```

Это не одно и то же.

---

## Самая короткая шпаргалка

| Что нужно узнать | Агрегирование |
|---|---|
| сумму значений | `SUM` |
| количество строк | `COUNT(*)` |
| количество непустых значений колонки | `COUNT(column)` |
| количество уникальных значений | `COUNT_DISTINCT` |
| среднее значение | `AVG` |
| минимальное значение | `MIN` |
| максимальное значение | `MAX` |

---

# 1. SUM — сложить значения

Используйте `SUM`, когда значения можно и нужно складывать.

Примеры:

```text
SUM(revenue)
SUM(cost)
SUM(quantity)
```

В учебных данных:

```text
SUM(revenue)  = 4005.00
SUM(quantity) = 31
```

Типичные задачи:

- общая выручка;
- общий расход;
- общий пробег;
- количество произведённых единиц;
- сумма начислений.

## Когда SUM опасен

Не всё числовое поле можно складывать.

Например:

```text
процент выполнения
температура
средняя скорость
тариф
остаток на определённую дату
```

Числовой тип колонки ещё не означает, что `SUM` имеет смысл.

Сначала сформулируйте бизнес-смысл показателя.

---

# 2. COUNT(*) — посчитать строки

`COUNT(*)` отвечает на вопрос:

> сколько строк попало в результат?

В учебном Dataset:

```text
COUNT(*) = 12
```

Это не обязательно означает:

```text
12 продаж
12 менеджеров
12 клиентов
12 автомобилей
```

Это означает только:

```text
12 строк Dataset после фильтрации
```

Правильный смысл зависит от **зерна Dataset** — того, что представляет одна строка.

Если одна строка = одна продажа, `COUNT(*)` можно интерпретировать как число продаж.

Если одна строка = позиция документа, `COUNT(*)` считает позиции, а не документы.

---

# 3. COUNT(column) — посчитать непустые значения

`COUNT(column)` не считает `NULL`.

В учебных данных:

```text
COUNT(*)       = 12
COUNT(manager) = 11
```

Почему?

Одна строка содержит:

```text
manager = NULL
```

Поэтому:

```text
COUNT(*)
→ считает строку

COUNT(manager)
→ эту строку не считает
```

Используйте `COUNT(column)`, если вопрос звучит примерно так:

> в скольких строках поле заполнено?

---

# 4. COUNT DISTINCT — посчитать уникальные объекты

Это одно из самых важных агрегирований в BI.

В Superset 6.1.0 в интерфейсе агрегирование отображается как:

```text
COUNT_DISTINCT
```

В учебных данных:

```text
COUNT(manager)          = 11
COUNT_DISTINCT(manager) = 4
```

Потому что один и тот же менеджер встречается в нескольких строках.

Используйте `COUNT_DISTINCT`, когда нужно узнать:

- сколько разных сотрудников;
- сколько уникальных автомобилей;
- сколько документов;
- сколько клиентов;
- сколько участков;
- сколько заказов;

если один объект может повторяться в Dataset несколько раз.

## Классическая ошибка

Вопрос:

> Сколько автомобилей работало за день?

Если один автомобиль имеет 10 строк, то:

```text
COUNT(*) = 10
```

не означает 10 автомобилей.

Если идентификатор автомобиля — `vehicle_id`, нужен расчёт:

```text
COUNT_DISTINCT(vehicle_id)
```

---

# 5. AVG — среднее значение

`AVG` отвечает на вопрос:

> каково среднее значение среди строк, попавших в расчёт?

В учебных данных:

```text
AVG(revenue) = 333.75
```

Проверка:

```text
4005.00 / 12 = 333.75
```

Примеры разумного применения:

- средняя стоимость одной операции;
- среднее время обработки;
- средний пробег одной поездки;
- средняя масса одной отгрузки.

## Главная опасность AVG

Не усредняйте уже посчитанные средние без понимания весов.

Пример:

```text
Участок A:
100 операций
среднее время = 10 мин

Участок B:
2 операции
среднее время = 100 мин
```

Простое:

```text
(10 + 100) / 2 = 55
```

не является средним временем всех 102 операций.

Правильное общее среднее должно учитывать количество исходных наблюдений.

Поэтому правило:

> если Metric уже является средним, не стройте «среднее от среднего» автоматически.

---

# 6. MIN — минимальное значение

`MIN` возвращает минимальное значение внутри текущей группы.

Примеры:

```text
MIN(price)
MIN(duration)
MIN(event_date)
```

Может отвечать на вопросы:

- минимальная стоимость;
- самое короткое время;
- первая дата события.

Для дат `MIN(date)` часто означает:

> самая ранняя дата.

---

# 7. MAX — максимальное значение

`MAX` возвращает максимальное значение внутри текущей группы.

Примеры:

```text
MAX(price)
MAX(duration)
MAX(event_date)
```

Может отвечать на вопросы:

- максимальная стоимость;
- самое длинное время;
- последняя дата события.

Для дат `MAX(date)` часто используется как:

> последняя известная дата события.

Но помните: последнее значение по дате и максимальное числовое значение — разные задачи. Иногда для получения «последней записи» нужен SQL, а не просто `MAX`.

---

# 8. Сначала определите объект подсчёта

Перед `COUNT` задайте себе вопрос:

> что именно я хочу посчитать?

Например:

```text
строки
документы
автомобили
сотрудников
операции
смены
участки
```

После этого найдите колонку, которая идентифицирует этот объект.

Пример:

```text
Нужно: количество документов

Dataset:
один document_id может иметь несколько строк

Правильно:
COUNT_DISTINCT(document_id)
```

А не:

```text
COUNT(*)
```

---

# 9. Dimension меняет уровень агрегирования

Одна Metric даёт разные результаты в зависимости от Dimension.

Без Dimension:

```text
SUM(revenue) = 4005.00
```

С:

```text
Dimension = region
```

получаем:

```text
Север = 1360.00
Юг    = 2645.00
```

Формула Metric не изменилась.

Изменился набор групп, внутри которых она считается.

Поэтому при неожиданном результате проверяйте одновременно:

```text
Metric
Dimension
Filter
```

---

# 10. Filter применяется до итогового расчёта

Например:

```text
Metric = SUM(revenue)
```

без фильтра:

```text
4005.00
```

За февраль 2026:

```text
1180.00
```

Metric та же самая.

Изменился набор строк, который участвует в расчёте.

---

# 11. Не доверяйте имени колонки без проверки смысла

Допустим, есть колонка:

```text
amount
```

Нельзя автоматически решить, что ей нужен `SUM`.

Сначала надо понять:

- что означает одна строка;
- что означает `amount`;
- может ли одно бизнес-событие встречаться несколько раз;
- не является ли значение уже агрегированным;
- допускается ли суммирование между периодами и группами.

BI-ошибка часто возникает не потому, что Superset неправильно считает, а потому что пользователь правильно применил `SUM` к показателю, который **нельзя было суммировать по смыслу**.

---

# 12. Быстрый алгоритм выбора

```text
Нужно сложить значения?
→ SUM

Нужно количество строк?
→ COUNT(*)

Нужно количество заполненных значений поля?
→ COUNT(column)

Нужно количество разных объектов?
→ COUNT_DISTINCT(column)

Нужно среднее исходных наблюдений?
→ AVG

Нужно самое маленькое значение?
→ MIN

Нужно самое большое значение?
→ MAX
```

# 13. Контрольные примеры курса

Для `training.sales`:

| Расчёт | Результат | Что означает |
|---|---:|---|
| `SUM(revenue)` | 4005.00 | сумма выручки |
| `SUM(quantity)` | 31 | сумма количества |
| `COUNT(*)` | 12 | число строк |
| `COUNT(sale_id)` | 12 | строк с заполненным `sale_id` |
| `COUNT(manager)` | 11 | строк с заполненным `manager` |
| `COUNT_DISTINCT(manager)` | 4 | разных менеджера |
| `COUNT_DISTINCT(office)` | 4 | разных офиса |
| `AVG(revenue)` | 333.75 | средняя выручка строки |
| `AVG(cost)` | 206.25 | средняя себестоимость строки |

Если эти различия понятны, базовые агрегирования освоены.

# 14. Красный флаг: число выглядит правдоподобно

Самая опасная BI-ошибка — не ошибка SQL и не пустой Chart.

Это **неправильное число, которое выглядит нормальным**.

Например:

```text
COUNT(*) = 1200
```

может выглядеть как «1200 автомобилей», хотя на самом деле это 1200 строк по 137 автомобилям.

Поэтому всегда проговаривайте Metric словами:

```text
COUNT(*)
→ количество строк

COUNT_DISTINCT(vehicle_id)
→ количество уникальных автомобилей
```

Если словесная формулировка не совпадает с бизнес-вопросом — Metric выбрана неправильно.

## Главное, что нужно запомнить

```text
SUM
→ сумма

COUNT(*)
→ строки

COUNT(column)
→ непустые значения

COUNT_DISTINCT
→ уникальные значения

AVG
→ среднее исходных наблюдений

MIN / MAX
→ крайние значения
```

И ещё важнее:

> сначала определите, что представляет одна строка Dataset, и только потом выбирайте агрегирование.

Если итог всё равно не сходится, используйте:

→ [Почему цифры в Superset не сходятся](07b-troubleshoot-wrong-numbers.md)
