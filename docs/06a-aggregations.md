# Шпаргалка к уроку 06. SUM, COUNT, COUNT DISTINCT, AVG, MIN и MAX

Одна и та же колонка с разным агрегированием отвечает на разные вопросы. Выбирать функцию нужно не по типу поля, а по смыслу показателя.

| Нужно узнать | Использовать |
|---|---|
| сумму значений | `SUM` |
| количество строк | `COUNT(*)` |
| количество непустых значений | `COUNT(column)` |
| количество уникальных значений | `COUNT_DISTINCT(column)` |
| среднее | `AVG` |
| минимум | `MIN` |
| максимум | `MAX` |

## 1. `SUM` — сложить значения

Для `training.sales`:

```text
SUM(revenue)  = 4005.00
SUM(quantity) = 31
```

Но не каждое числовое поле можно складывать. Процент, температура, средняя скорость, тариф или остаток на дату тоже могут быть числами, но сумма таких значений далеко не всегда имеет бизнес-смысл.

## 2. `COUNT(*)` — посчитать строки

```text
COUNT(*) = количество строк после фильтрации
```

В учебном Dataset:

```text
COUNT(*) = 12
```

Это одновременно 12 продаж только потому, что зерно учебного Dataset — одна продажа на строку. Если одна строка представляет позицию документа, `COUNT(*)` посчитает позиции, а не документы.

→ [Зерно Dataset](06c-data-grain.md)

## 3. `COUNT(column)` — посчитать непустые значения

`COUNT(column)` не считает `NULL`.

В учебных данных:

```text
COUNT(*)       = 12
COUNT(manager) = 11
```

У одной продажи `manager = NULL`, поэтому результаты различаются.

## 4. `COUNT_DISTINCT` — посчитать разные объекты

```text
COUNT(manager)          = 11
COUNT_DISTINCT(manager) = 4
```

`COUNT_DISTINCT` нужен, когда объект может встречаться в нескольких строках, а вопрос звучит как «сколько разных сотрудников / автомобилей / документов / клиентов?».

Например:

```text
COUNT(*)
→ строки

COUNT_DISTINCT(vehicle_id)
→ уникальные автомобили
```

## 5. `AVG` — среднее исходных наблюдений

В учебных данных:

```text
AVG(revenue) = 333.75
```

потому что:

```text
4005 / 12 = 333.75
```

Со средними нужна осторожность. Если две группы посчитаны на разном числе наблюдений, простое среднее их средних может быть неверным.

```text
Группа A: 100 операций, AVG = 10
Группа B:   2 операции, AVG = 100
```

`(10 + 100) / 2` не является средним всех 102 операций. Нужны исходные значения или корректные веса.

## 6. `MIN` и `MAX`

```text
MIN(value) → минимальное значение группы
MAX(value) → максимальное значение группы
```

Для дат это самая ранняя и самая поздняя дата. Но `MAX(date)` сам по себе не означает «взять всю последнюю строку» — для этого может понадобиться отдельный SQL.

## 7. Измерение меняет группы, а не формулу метрики

Без измерения:

```text
SUM(revenue) = 4005.00
```

С `Dimension = region`:

```text
Север = 1360.00
Юг    = 2645.00
```

Формула та же. Изменились группы, внутри которых она считается.

## 8. Перед COUNT определите объект подсчёта

Сначала ответьте, что именно нужно посчитать: строки, документы, автомобили, сотрудников, смены. Затем найдите идентификатор этого объекта и проверьте, повторяется ли он между строками.

## 9. Опасны не только явные ошибки

Неправильное число может выглядеть вполне правдоподобно. Например, `COUNT(*) = 1200` легко принять за 1200 автомобилей, хотя это могут быть 1200 строк по 137 автомобилям.

Поэтому метрику полезно уметь проговорить обычными словами.

## Контрольные значения курса

| Расчёт | Результат |
|---|---:|
| `SUM(revenue)` | 4005.00 |
| `SUM(quantity)` | 31 |
| `COUNT(*)` | 12 |
| `COUNT(manager)` | 11 |
| `COUNT_DISTINCT(manager)` | 4 |
| `COUNT_DISTINCT(office)` | 4 |
| `AVG(revenue)` | 333.75 |
| `AVG(cost)` | 206.25 |

Перед любой агрегацией вернитесь к одному вопросу: **что означает одна строка Dataset?**
