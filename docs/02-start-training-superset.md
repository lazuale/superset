# 02. Запускаем учебный Superset

## Что научимся делать

После этого урока вы должны уметь:

- проверить, что Docker готов к работе;
- запустить учебный стенд Apache Superset 6.1.0;
- проверить версию Superset;
- убедиться, что таблица `training.sales` создана и содержит правильные данные;
- открыть Superset в браузере и войти в учебную учётную запись;
- остановить стенд и снова его запустить;
- полностью вернуть стенд в исходное состояние, если что-то сломалось.

В этом уроке мы **не изучаем Docker как отдельную технологию**. Docker здесь нужен только для того, чтобы у всех учеников был одинаковый Superset и одинаковый PostgreSQL.

## Что нужно до начала

Нужны:

- локальная копия этого репозитория;
- Docker с командой `docker compose`;
- браузер.

Если локальной копии репозитория ещё нет, сначала выполните раздел [«Получаем файлы курса»](../README.md#получаем-файлы-курса) в README.

Перед выполнением команд этого урока откройте терминал **в корневом каталоге репозитория** — там, где находятся:

```text
README.md
docs/
training/
```

PostgreSQL отдельно устанавливать не нужно. Он входит в учебный стенд.

### Linux и macOS

Apache Superset рекомендует Docker Compose как быстрый способ локально попробовать Superset. Для Linux и macOS это официальный путь для локального запуска.

Если Docker ещё не установлен, используйте официальную документацию Docker:

- Linux: <https://docs.docker.com/engine/install/>
- macOS: <https://docs.docker.com/desktop/setup/install/mac-install/>

### Windows

Apache Superset не заявляет Windows как официально поддерживаемую систему для локального Docker Compose-сценария.

Для этого курса на Windows используйте **Docker Desktop с WSL 2 и Linux-контейнерами**. Сам Superset при этом работает внутри Linux-контейнера.

Официальная установка Docker Desktop для Windows:

<https://docs.docker.com/desktop/setup/install/windows-install/>

В рамках курса **все команды терминала на Windows выполняйте в оболочке WSL 2**. PowerShell и CMD не являются учебным путём этого маршрута. Так команды ниже остаются одинаковыми для Windows, macOS и Linux, включая bash-переносы строк через `\`.

## Проверяем Docker

Откройте терминал и выполните:

```bash
docker version
```

Затем:

```bash
docker compose version
```

Обе команды должны завершиться без ошибки.

Если первая команда сообщает, что не удаётся подключиться к службе Docker, сначала запустите Docker Desktop или службу Docker.

## Что именно мы запускаем

Учебный стенд находится в каталоге:

```text
training/
```

Основной файл:

```text
training/compose.yaml
```

Он запускает три сервиса:

```text
db
│
├── PostgreSQL 17
└── база training
        └── схема training
                └── таблица sales

superset-init
└── однократная подготовка Superset

superset
└── Apache Superset 6.1.0
        └── http://localhost:8088
```

`superset-init` — вспомогательный одноразовый контейнер. После успешной подготовки он завершает работу. Это нормально.

Для Superset используется образ:

```text
apache/superset:6.1.0-dev
```

Это официальный образ релиза Superset 6.1.0 с вариантом сборки `dev`. Такой вариант нужен учебному стенду, потому что он уже содержит PostgreSQL-драйвер `psycopg2-binary`.

Стенд предназначен **только для локального обучения**. Это не схема промышленного развёртывания.

## Первый запуск

Перейдите в каталог `training` из корня репозитория:

```bash
cd training
```

Начиная с этого шага все команды `docker compose ...` в курсе выполняются из каталога `training/`, если явно не сказано иначе.

Сначала загрузите нужные образы:

```bash
docker compose pull
```

Теперь запустите стенд:

```bash
docker compose up -d
```

Ключ `-d` означает, что контейнеры запускаются в фоне и терминал остаётся свободным.

## Проверяем состояние контейнеров

Выполните:

```bash
docker compose ps -a
```

Нормальная картина после завершения инициализации:

```text
db             running / healthy
superset       running / healthy
superset-init  exited (0)
```

Названия контейнеров целиком могут выглядеть немного иначе. Важны названия сервисов и их состояние.

Если `superset-init` имеет код завершения `0`, подготовка Superset прошла успешно. Статус `healthy` у `superset` означает, что встроенная проверка получила успешный ответ от `http://localhost:8088/health` внутри контейнера.

Сразу после запуска проверка состояния может несколько секунд показывать промежуточное состояние. Продолжайте только после появления `healthy`.

## Проверяем версию Superset

Выполните:

```bash
docker compose exec superset superset version
```

В выводе должна присутствовать версия:

```text
6.1.0
```

Если вывод показывает другую версию, не продолжайте курс: учебный стенд запущен не из того образа.

## Проверяем учебные данные

При первом создании PostgreSQL автоматически выполняются:

```text
schema.sql
data.sql
readonly.sql
```

Они создают:

```text
database: training
schema:   training
table:    sales
```

и загружают фиксированные данные курса.

Для проверки выполните:

```bash
docker compose exec -T db \
  psql -U training -d training -f /training/check.sql
```

Главная контрольная строка должна содержать:

```text
rows     = 12
quantity = 31
revenue  = 4005.00
cost     = 2475.00
profit   = 1530.00
```

`check.sql` дополнительно показывает контрольные итоги по регионам, месяцам и продуктам. Эти же значения мы позже будем получать через Superset.

Если числа совпали, учебные данные готовы.

## Открываем Superset

Откройте в браузере:

<http://localhost:8088>

Используйте учебную учётную запись:

```text
логин:  admin
пароль: admin
```

Порт `8088` учебного compose-файла привязан только к `127.0.0.1`. То есть этот интерфейс предназначен для открытия **на том же компьютере**, где запущен Docker, и не публикуется учебным compose-файлом на сетевые интерфейсы машины.

Эти реквизиты специально простые, потому что стенд локальный и предназначен для обучения.

Не используйте такой пароль в реальной системе.

## Коротко ориентируемся в интерфейсе

Пока ничего не создавайте.

Найдите в интерфейсе основные разделы, с которыми будем работать дальше:

- `Datasets` — наборы данных;
- `Charts` — сохранённые графики;
- `Dashboards` — аналитические панели;
- `SQL → SQL Lab` — редактор SQL и работа с SQL;
- настройки подключений к базам данных.

Названия некоторых элементов интерфейса могут оставаться английскими даже при русской локали. В курсе английское название будет сохраняться рядом с русским объяснением, когда оно нужно для поиска элемента.

На этом этапе достаточно убедиться, что интерфейс открывается и основные разделы видны.

## Что произошло внутри

После команды:

```bash
docker compose up -d
```

произошло несколько вещей.

### 1. Запустился PostgreSQL

Контейнер `db` создал учебную базу:

```text
training
```

Затем из `schema.sql` была создана таблица:

```text
training.sales
```

После этого `data.sql` загрузил фиксированные строки, а `readonly.sql` создал пользователя `superset_reader` для подключения Superset только на чтение.

### 2. Superset подготовил своё служебное состояние

Контейнер `superset-init` выполнил миграции Superset, создал учебного администратора и подготовил стандартные роли.

Это служебные данные самого Superset. Они не являются строками `training.sales`.

### 3. Запустилось веб-приложение Superset

Контейнер `superset` открыл веб-интерфейс на порту:

```text
8088
```

Учебный compose-файл публикует этот порт только на локальном интерфейсе:

```text
127.0.0.1:8088
```

Поэтому браузер на том же компьютере обращается к:

```text
http://localhost:8088
```

### 4. Учебные данные пока ещё не подключены к Superset

PostgreSQL уже работает и `training.sales` уже существует, но отдельное подключение `Database` в интерфейсе Superset мы ещё не создавали.

Именно это будет задачей следующего урока.

## Останавливаем стенд

Чтобы временно остановить контейнеры и сохранить результаты работы:

```bash
docker compose stop
```

Чтобы снова запустить стенд:

```bash
docker compose up -d
```

Ваши созданные позже объекты Dataset, Chart и Dashboard при обычной остановке сохранятся.

## Полный сброс стенда

Если нужно полностью начать сначала:

```bash
docker compose down -v --remove-orphans
```

После этого снова выполните:

```bash
docker compose up -d
```

Команда с `-v` удаляет учебные тома Docker.

Это означает, что будут удалены:

- служебное состояние Superset;
- созданные вами Dataset, Chart и Dashboard;
- база `training` вместе с данными.

При следующем запуске всё будет создано заново из файлов репозитория.

**Не используйте полный сброс без необходимости после того, как начнёте проходить следующие уроки.**

## Попробуйте сами

Не подглядывая выше, выполните четыре действия:

1. остановите учебный стенд;
2. снова запустите его;
3. проверьте версию Superset;
4. повторно выполните `check.sql`.

После этого откройте Superset в браузере и войдите под `admin`.

Если всё получилось, вы уже умеете безопасно возвращаться к одной и той же учебной среде.

## Если не получилось

### Docker не отвечает

Проверьте:

```bash
docker version
```

Если клиент установлен, но сервер недоступен, запустите Docker Desktop или службу Docker.

### `superset-init` завершился с ошибкой

Посмотрите его журнал:

```bash
docker compose logs superset-init
```

После исправления причины проще всего выполнить полный сброс и повторить запуск.

### Superset не открывается на `localhost:8088`

Проверьте состояние:

```bash
docker compose ps -a
```

Затем журнал приложения:

```bash
docker compose logs superset
```

Если порт `8088` уже занят другой программой, освободите его перед повторным запуском стенда.

### `training.sales` не найдена или контрольные суммы неправильные

Выполните полный сброс:

```bash
docker compose down -v --remove-orphans
docker compose up -d
```

Затем снова запустите `check.sql`.

PostgreSQL выполняет `schema.sql`, `data.sql` и `readonly.sql` автоматически именно при создании нового тома с базой.

### Windows

Если проблема возникает только на Windows, сначала убедитесь, что Docker Desktop использует Linux-контейнеры и WSL 2, а команды выполняются внутри WSL 2.

Помните: Apache Superset не предоставляет официальную поддержку Windows как хоста для своего Docker Compose-сценария. Поэтому проблемы Windows-окружения не следует путать с проблемами самого Superset.

## Что должно получиться

К концу урока одновременно выполнены пять условий:

- `docker compose ps -a` показывает `db` и `superset` в состоянии `healthy`;
- `superset-init` завершён с кодом `0`;
- `superset version` показывает `6.1.0`;
- `check.sql` подтверждает 12 строк и выручку `4005.00`;
- <http://localhost:8088> открывается и принимает `admin / admin`.

Если это так, стенд готов для всего дальнейшего курса.
