# 01. Что такое Apache Superset

## Результат урока

После этого урока вы должны понимать базовую модель Superset:

```text
данные в SQL-источнике
        ↓
Database connection
        ↓
Dataset
        ↓
Explore
        ↓
Chart
        ↓
Dashboard
```

Также нужно понимать, для чего нужны `Metric` и `SQL Lab` и где в общих чертах заканчивается область ответственности Superset.

В этом уроке ничего устанавливать и настраивать не нужно.

## Superset на пальцах

Apache Superset — веб-приложение для исследования данных, аналитических запросов, визуализаций и Dashboard.

Самый простой рабочий сценарий:

```text
данные уже находятся в базе
        ↓
Superset подключается к базе
        ↓
выбираем набор данных
        ↓
задаём аналитический вопрос
        ↓
получаем число / таблицу / график
        ↓
сохраняем Chart
        ↓
собираем Dashboard
```

В учебном курсе исходные продажи находятся в PostgreSQL:

```text
training.sales
```

Superset будет читать эти данные и выполнять аналитические запросы через подключение к PostgreSQL.

Главное различие:

```text
PostgreSQL
→ хранит исходные строки training.sales

Superset
→ знает, как подключиться к источнику,
  как анализировать данные
  и как показать результат
```

Создание Dataset или Chart не переносит исходную таблицу продаж из PostgreSQL в Superset как новую рабочую копию.

---

## Что обычно делают в Superset

### Исследуют данные

Например:

```text
какова общая выручка?
какой регион больше?
что происходило по месяцам?
какие записи относятся к выбранному периоду?
```

Для таких вопросов используется `Explore`.

### Считают показатели

Например:

```text
SUM(revenue)
COUNT(*)
AVG(revenue)
прибыль
доля
```

Повторно используемый агрегированный показатель можно сохранить как `Metric`.

### Строят визуализации

Например:

```text
одно число
таблица
столбцы
линия
```

Сохранённая визуализация в Superset называется `Chart`.

### Собирают Dashboard

Несколько связанных Chart можно разместить на одной аналитической панели и добавить общие фильтры.

### Выполняют SQL

В `SQL Lab` аналитик может выполнить SQL-запрос непосредственно к подключённому SQL-источнику.

SQL изучать заранее для начала курса не требуется: первый SQL будет только в уроке 10.

# Основные сущности Superset

## 1. Database

`Database` в Superset — это **настроенное подключение к SQL-источнику**.

Например:

```text
Superset
   │
   └── Database: Training PostgreSQL
            │
            └── PostgreSQL
```

В объекте подключения находятся параметры, необходимые Superset для обращения к базе.

Саму учебную Database connection создадим в уроке 03.

Важно различать:

```text
PostgreSQL database
```

и:

```text
Database object в Superset
```

Второй является настройкой подключения к первому.

---

## 2. Dataset

`Dataset` — зарегистрированный в Superset источник для анализа.

В начале курса схема максимально простая:

```text
PostgreSQL
└── training.sales
        ↓
Superset Dataset
└── sales
```

Dataset даёт Superset описание данных, с которыми затем работают `Explore`, Metrics и Chart.

В Dataset могут быть, например:

```text
Columns
Calculated Columns
Metrics
настройки временных полей
описание
```

В уроке 04 создадим Dataset прямо на существующей таблице `training.sales`.

Позже, в уроке 11, отдельно увидим второй вариант — Dataset, определённый SQL-запросом. Пока достаточно запомнить:

> Dataset — это точка входа данных в аналитическую работу Superset.

---

## 3. Explore

`Explore` — основной рабочий экран для построения аналитического запроса и визуализации без необходимости писать SQL вручную.

Упрощённо:

```text
Dataset
   ↓
Explore
   ├── что считать
   ├── по чему группировать
   ├── какие строки оставить
   └── как показать результат
```

Например вопрос:

> Какова выручка каждого региона?

в Explore превращается в идею:

```text
разбить по region
посчитать SUM(revenue)
```

Практически Explore начнём изучать в уроке 05.

---

## 4. Metric

`Metric` — агрегированный показатель.

Примеры:

```text
SUM(revenue)
COUNT(*)
AVG(cost)
```

В Superset Metric может быть создана временно внутри конкретного Explore или сохранена в Dataset для повторного использования.

Например одна сохранённая Metric:

```text
Прибыль
```

может затем использоваться в нескольких Chart.

Metrics и Calculated Columns подробно разбираются в уроке 06.

---

## 5. Chart

`Chart` — сохранённая конфигурация аналитической визуализации.

Она связывает, в частности:

```text
Dataset
+ аналитический запрос
+ Metrics
+ Dimensions / группировки
+ Filters
+ тип визуализации
+ настройки отображения
```

Chart может быть:

```text
Table
Big Number
Bar Chart
Line Chart
...
```

Создавать и сохранять Chart будем в уроке 07.

---

## 6. Dashboard

`Dashboard` — аналитическая панель из сохранённых Chart.

Например:

```text
Dashboard
├── общий KPI
├── сравнение регионов
├── динамика по месяцам
└── детальная таблица
```

Dashboard позволяет разместить связанные показатели в одном месте и добавить общие фильтры.

Собирать Dashboard будем в уроке 08, а Native Filters — в уроке 09.

---

## 7. SQL Lab

`SQL Lab` — рабочая среда Superset для выполнения SQL в подключённом источнике.

Упрощённо:

```text
SQL Lab
   ↓
SQL-запрос
   ↓
PostgreSQL выполняет запрос
   ↓
Superset показывает результат
```

То есть SQL-запрос к учебной PostgreSQL рассчитывает именно PostgreSQL.

В уроке 10 сравним знакомые операции Explore с SQL:

```text
Filter      ↔ WHERE
Dimension   ↔ GROUP BY
Metric      ↔ SUM / COUNT / ...
```

До урока 10 SQL для прохождения курса не нужен.

---

# Как сущности связаны

Для основной части курса цепочка будет такой:

```text
PostgreSQL: training.sales
          ↓
Database: Training PostgreSQL
          ↓
Dataset: sales
          ↓
Explore
          ↓
Metrics / Filters / группировки
          ↓
Chart
          ↓
Dashboard
          ↓
Native Filters
```

Позже добавится ещё один маршрут:

```text
Database
   ↓
SQL Lab
   ↓
результат SQL
   ↓
Virtual Dataset
   ↓
Explore / Chart
```

Не нужно запоминать детали второго маршрута сейчас. Он станет понятен после практики SQL Lab.

# Где Superset подходит хорошо

Для первого знакомства достаточно такой матрицы:

| Задача | Superset |
|---|---|
| исследовать уже доступные SQL-данные | да |
| фильтровать и группировать | да |
| считать аналитические показатели | да |
| строить таблицы и графики | да |
| собирать интерактивные Dashboard | да |
| выполнять аналитический SQL | да |
| вводить и редактировать рабочие бизнес-записи как в учётной системе | не основная задача |
| согласовывать заявки и назначать исполнителей | не задача BI-инструмента |
| регулярно загружать и очищать сырые данные как ETL-конвейер | не основная задача |

Главное правило для старта:

```text
есть данные, доступные через SQL
→ Superset помогает их исследовать, считать и показывать
```

Если сначала нужно получить правильные данные из множества сырых источников, очистить и регулярно загружать их, это уже отдельная задача подготовки данных.

Подробно архитектурную границу разберём **после практического курса**, когда будут понятны Dataset, SQL Lab и Virtual Dataset:

→ [Где заканчивается Superset](12a-what-belongs-in-superset.md)

Сейчас углубляться в DWH, ETL, materialized views, сложные JOIN или оконные функции не требуется.

# Что важно не перепутать

## Dataset не равен исходной таблице

В учебном курсе Dataset `sales` указывает на `training.sales`, но это разные сущности разных систем:

```text
training.sales
→ объект PostgreSQL

sales
→ объект Superset
```

## Chart не хранит отдельную бизнес-таблицу

Chart сохраняет аналитическую конфигурацию и визуализацию, а исходные строки остаются в SQL-источнике.

## Dashboard не является новым Dataset

Dashboard собирает Chart и управляет панелью. Он не заменяет источник данных.

## Native Filter не является правом доступа

Фильтр Dashboard нужен для анализа. Ограничения безопасности — отдельная тема и в базовый курс не входят.

# Что пройдём дальше

Маршрут построен так, чтобы каждый новый объект появлялся только после предыдущего.

```text
01  понять общую модель
 ↓
02  запустить одинаковый учебный стенд
 ↓
03  подключить PostgreSQL
 ↓
04  создать Physical Dataset
 ↓
05  освоить Explore
 ↓
06  разобраться с Metric и Calculated Column
 ↓
07  создать и сохранить Chart
 ↓
08  собрать Dashboard
 ↓
09  добавить Native Filters
 ↓
10  выполнить первые SQL-запросы
 ↓
11  создать Virtual Dataset
 ↓
12  повторить весь маршрут самостоятельно
```

Поэтому не нужно пытаться освоить весь интерфейс Superset в первом уроке.
