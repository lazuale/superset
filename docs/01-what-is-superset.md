# 01. Что такое Apache Superset

В первом уроке ничего устанавливать не нужно. Задача проще: разобраться, что вообще делает Superset и как связаны его основные объекты. Если эту модель понять сейчас, дальше интерфейс будет восприниматься намного спокойнее.

Для начала достаточно одной цепочки:

```text
данные в SQL-источнике
        ↓
подключение Database
        ↓
Dataset
        ↓
Explore
        ↓
Chart
        ↓
Dashboard
```

SQL, Docker, PostgreSQL и Python заранее знать не требуется. Каждый основной объект мы ещё создадим руками в следующих уроках.

## Что делает Superset

Apache Superset — BI-приложение для работы с уже доступными аналитическими данными. Он подключается к SQL-источнику, позволяет исследовать данные, считать показатели, строить визуализации и собирать из них Dashboard.

В нашем стенде исходные данные живут в PostgreSQL, в таблице:

```text
training.sales
```

Superset эту таблицу не «забирает к себе». Он подключается к PostgreSQL и запрашивает нужные данные тогда, когда пользователь работает в Explore или открывает Chart.

Это важное различие. PostgreSQL хранит строки продаж. Superset хранит настройки подключения, описание Dataset, формулы, графики и панели.

## Как выглядит обычная работа

Допустим, нужно понять, сколько выручки дал каждый регион.

В Superset путь примерно такой:

1. выбираем Dataset с продажами;
2. открываем его в `Explore`;
3. указываем `region` как группировку;
4. считаем `SUM(revenue)`;
5. смотрим результат в таблице или на графике;
6. если результат нужен дальше — сохраняем Chart;
7. несколько связанных Chart собираем в Dashboard.

То есть Superset не заставляет начинать с SQL. Для обычного анализа большая часть работы делается через Explore.

## Основные объекты

### Database

`Database` в Superset — это не сама база данных, а **настроенное подключение к ней**.

В уроке 03 мы создадим подключение с именем:

```text
Training PostgreSQL
```

Оно будет указывать на учебную PostgreSQL.

Отсюда первая полезная привычка: различать базу `training` в PostgreSQL и объект `Database` в Superset. Это связанные, но разные вещи.

### Dataset

`Dataset` — источник, который Superset использует для аналитической работы.

В начале курса всё максимально просто:

```text
PostgreSQL: training.sales
        ↓
Superset Dataset: sales
```

Dataset хранит описание доступных колонок, временных полей, Calculated Columns и Metrics. Через него данные попадают в Explore.

Позже мы увидим и `Virtual Dataset`, который определяется SQL-запросом. Пока это можно не держать в голове: в уроке 04 создадим обычный Dataset прямо на таблице `training.sales`.

### Explore

`Explore` — основной рабочий экран аналитика в Superset.

Именно здесь обычно решается вопрос вида:

> Что посчитать, по чему разбить результат и какие строки оставить?

Например:

```text
по чему разбить → region
что посчитать   → SUM(revenue)
```

После этого Superset сам формирует запрос к источнику и показывает результат.

### Metric

`Metric` — агрегированный показатель: сумма, количество, среднее или более сложная формула.

Примеры:

```text
SUM(revenue)
COUNT(*)
AVG(cost)
```

Разовую метрику можно собрать прямо в Explore. Если показатель используется постоянно, его удобнее сохранить в Dataset и затем выбирать по имени в разных Chart.

В уроке 06 мы сделаем именно такую сохранённую метрику — `Прибыль`.

### Chart

`Chart` — сохранённая аналитическая визуализация.

Это не просто картинка. В Chart сохраняются Dataset, группировки, метрики, фильтры, тип визуализации и настройки отображения.

В курсе будем работать, в частности, с:

```text
Table
Big Number
Bar Chart
Line Chart
```

Создавать и сохранять их начнём в уроке 07.

### Dashboard

`Dashboard` собирает несколько Chart на одной панели.

Например, на одной странице можно показать общую прибыль, сравнение регионов, динамику по месяцам и детальную таблицу. Позже туда же добавим общие Native Filters.

Важно: Dashboard не создаёт новый набор данных. Он показывает уже существующие Chart и управляет их размещением и фильтрацией.

### SQL Lab

`SQL Lab` нужен, когда удобнее или необходимо написать SQL вручную.

Запрос выполняет выбранный SQL-источник — в нашем случае PostgreSQL. Superset отправляет SQL и показывает результат.

В уроке 10 мы сравним уже знакомые действия Explore с их SQL-аналогами:

```text
Filter    ↔ WHERE
Dimension ↔ GROUP BY
Metric    ↔ SUM / COUNT / ...
```

До этого момента SQL для прохождения курса не нужен.

## Что Superset делает хорошо, а что — уже не его работа

Superset хорошо подходит, когда данные уже доступны через SQL и их нужно:

- исследовать;
- фильтровать и группировать;
- считать показатели;
- показывать в таблицах и графиках;
- собирать в Dashboard;
- проверять SQL-запросами.

Но из этого не следует, что Superset нужно превращать во всё сразу. Ввод и исправление рабочих записей, согласования, назначение исполнителей или регулярная очистка сырых данных — задачи других систем и слоя подготовки данных.

К этой границе вернёмся после практики, когда будут понятны Dataset, SQL Lab и Virtual Dataset. Сейчас достаточно знать: **Superset работает поверх данных, а не заменяет систему, в которой эти данные рождаются и исправляются.**

## Что не стоит путать дальше

`training.sales` и Dataset `sales` — не одно и то же. Первый объект находится в PostgreSQL, второй — в Superset.

Chart не хранит отдельную копию бизнес-данных. Он хранит конфигурацию анализа.

Dashboard не является Dataset. Он собирает Chart.

Native Filter не является механизмом разграничения прав. Фильтр помогает пользователю анализировать данные, но не заменяет настройки безопасности.
