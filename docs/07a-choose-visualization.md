# Справочник к уроку 07. Как выбрать визуализацию

Этот раздел нужен не для того, чтобы выучить все Chart в Apache Superset.

Его задача проще: **понять, какой тип визуализации выбирать под конкретный аналитический вопрос**.

Главное правило:

```text
сначала вопрос к данным
       ↓
что именно нужно увидеть
       ↓
какая форма лучше это показывает
       ↓
только потом выбираем Chart
```

Не начинайте работу с просмотра галереи визуализаций по принципу «какой график выглядит красивее».

---

## Самая короткая шпаргалка

Если нужно быстро выбрать Chart, начните с этой таблицы.

| Что хотите понять | Что обычно выбирать |
|---|---|
| Каково одно итоговое значение? | `Big Number` |
| Какие точные значения у каждой строки или группы? | `Table` |
| Нужна сводная таблица по нескольким измерениям? | `Pivot Table` |
| Какая категория больше или меньше? | `Bar Chart` |
| Как показатель менялся со временем? | `Line Chart` |
| Как менялся объём по периодам? | `Bar Chart` по времени |
| Как менялась структура или накопление во времени? | `Area Chart` |
| Нужно совместить несколько временных рядов разного типа? | `Mixed Time-series` |
| Из каких нескольких крупных частей состоит целое? | `Pie Chart` / `Donut` |
| Где сосредоточен основной объём среди многих категорий? | `Treemap` |
| Как распределены значения? | `Histogram` |
| Где выбросы и нетипичные значения? | `Box Plot` |
| Есть ли связь между двумя показателями? | `Scatter Plot` |
| Нужно показать третий показатель размером точки? | `Bubble Chart` |
| Где находится концентрация значений по двум измерениям? | `Heatmap` |
| Почему итог вырос или уменьшился? | `Waterfall Chart` |
| Как объекты проходят последовательные стадии? | `Funnel Chart` |
| Как объекты переходят между состояниями или направлениями? | `Sankey Diagram` |
| В какие дни происходили события? | `Calendar Heatmap` |
| Когда начинаются и заканчиваются интервалы или работы? | `Gantt Chart` |
| Как устроена иерархия? | `Tree`, `Treemap`, `Sunburst` |
| Где что происходит географически? | карты / `deck.gl` |

Если подходящий ответ уже найден в этой таблице, обычно нет смысла искать более сложный Chart.

# 1. Базовый набор: сначала научитесь этому

Для обычной корпоративной BI не нужно начинать со всего каталога Superset.

Новичку достаточно уверенно освоить примерно десять типов.

## `Big Number`

**Вопрос:** сколько всего?

Примеры:

```text
Выручка = 12 450 000
Ошибок = 324
Выполнение плана = 96,4 %
```

Используйте, когда главное — одно число.

Не заменяйте им таблицу, если пользователю нужна расшифровка этого числа.

---

## `Table`

**Вопрос:** какие точные значения получились?

Используйте для:

- детализации;
- реестров;
- списков проблемных записей;
- точных значений по группам;
- расшифровки показателя с Dashboard.

Если человек должен прочитать конкретную строку, идентификатор, дату или сумму, таблица обычно полезнее графика.

---

## `Pivot Table`

**Вопрос:** как показатель раскладывается сразу по нескольким измерениям?

Например:

| участок | январь | февраль | март |
|---|---:|---:|---:|
| A | 120 | 135 | 128 |
| B | 98 | 110 | 123 |

Используйте, когда нужна именно аналитическая матрица, а не только визуальное сравнение.

---

## `Bar Chart`

**Вопрос:** что больше, меньше или отличается сильнее?

Например:

```text
Участок A → 125 ошибок
Участок B → 47 ошибок
Участок C → 18 ошибок
```

Это один из самых универсальных Chart.

Если категорий много, `Bar Chart` почти всегда читается лучше, чем круговая диаграмма.

---

## `Line Chart`

**Вопрос:** как показатель меняется во времени?

Примеры:

- выручка по месяцам;
- количество ошибок по дням;
- среднее время обработки по неделям;
- расход по сменам.

Линия особенно полезна, когда важен тренд и направление изменения.

---

## `Time-series Bar Chart`

**Вопрос:** сколько было в каждом отдельном периоде?

Например:

```text
январь  → 120 заявок
февраль → 180 заявок
март    → 135 заявок
```

По смыслу похож на Line Chart, но лучше подчёркивает отдельные объёмы каждого периода.

---

## `Area Chart`

**Вопрос:** как менялся объём или структура во времени?

Используйте осторожнее Line Chart: заливка визуально усиливает ощущение объёма.

Подходит, когда это действительно важно для смысла графика.

---

## `Pie Chart` / Donut

**Вопрос:** из каких нескольких частей состоит целое?

Хороший пример:

```text
ОК       = 82 %
Ошибка   = 12 %
Нет данных = 6 %
```

Плохой пример — круг из 20 участков.

Практическое правило курса:

> Используйте Pie/Donut только для небольшого числа хорошо различимых категорий. Если категорий становится много, переходите на `Bar Chart` или `Treemap`.

---

## `Heatmap`

**Вопрос:** где находится концентрация значений или проблем?

Например:

| | Ошибка A | Ошибка B | Ошибка C |
|---|---:|---:|---:|
| Участок 1 | 4 | 7 | 89 |
| Участок 2 | 3 | 5 | 8 |
| Участок 3 | 2 | 67 | 3 |

Heatmap помогает быстро заметить сочетание двух измерений, в котором показатель особенно высокий или низкий.

---

## `Treemap`

**Вопрос:** где сосредоточена основная часть объёма среди большого числа категорий?

Пример структуры:

```text
Все ошибки
├── Транспорт
│   ├── ТТН
│   ├── ПЛ
│   └── ГСМ
├── Табель
└── Документы
```

Размер прямоугольника показывает вклад категории в общий объём.

---

# 2. Набор аналитика: когда базовых Chart уже мало

Следующие визуализации полезны, когда нужно не просто показать показатель, а **исследовать данные**.

## `Scatter Plot`

**Вопрос:** есть ли зависимость между двумя величинами и какие объекты выбиваются?

Например:

```text
X = пробег
Y = расход топлива
точка = автомобиль
```

Scatter Plot помогает увидеть:

- общую зависимость;
- отдельные группы объектов;
- выбросы;
- подозрительные точки.

Для поиска аномалий это один из самых полезных Chart.

---

## `Histogram`

**Вопрос:** как распределены значения?

Например время выполнения задач:

```text
0–1 день   → много
1–2 дня    → меньше
2–3 дня    → ещё меньше
10+ дней   → отдельная группа
```

Среднее значение может скрыть такую структуру. Histogram показывает само распределение.

---

## `Box Plot`

**Вопрос:** где типичный диапазон и какие значения являются выбросами?

Полезен для:

- расхода;
- длительности;
- стоимости;
- производительности;
- любых числовых показателей, где нужно искать нетипичные объекты.

Это аналитический Chart. Пользователю, не знакомому с медианой, квартилями и выбросами, его нужно объяснять.

---

## `Mixed Time-series`

**Вопрос:** как показать вместе несколько временных показателей разного характера?

Например:

```text
столбцы = количество заявок
линия   = доля ошибок
```

Используйте, когда объединение действительно помогает сравнению.

Не собирайте в одном Chart много несвязанных показателей только потому, что это технически возможно.

---

## `Waterfall Chart`

**Вопрос:** из-за чего изменился итог?

Пример:

```text
Остаток вчера       100
+ новые              45
- обработано         32
- отменено            3
+ возвращено          7
Итого сегодня       117
```

Waterfall удобен для объяснения перехода от начального значения к конечному.

---

## `Funnel Chart`

**Вопрос:** сколько объектов осталось на каждой последовательной стадии?

Например:

```text
Получено        1000
Проверено        920
Принято          780
Закрыто          740
```

Используйте только для процесса, где стадии действительно идут последовательно.

---

## `Sankey Diagram`

**Вопрос:** куда переходят объекты или объёмы между состояниями?

Например:

```text
Получено
├── ОК
└── Ошибка
    ├── Исправлено
    └── Ожидает
```

Sankey показывает не только стадии, но и **потоки между ними**.

Если переходов слишком много, диаграмма быстро становится нечитаемой.

---

## `Calendar Heatmap`

**Вопрос:** в какие конкретные дни показатель был высоким или низким?

Полезен для:

- событий по дням;
- ежедневной нагрузки;
- инцидентов;
- активности;
- сезонных паттернов внутри календаря.

---

# 3. Специализированные визуализации

Их не нужно учить заранее. Возвращайтесь к ним, когда появится соответствующая задача.

## Иерархии

### `Tree`

Показывает структуру «родитель → дочерний элемент».

Выбирайте, если важна сама структура дерева.

### `Sunburst`

Показывает иерархию концентрическими уровнями.

Может быть полезен для нескольких уровней вложенности, но читается сложнее Treemap.

### `Partition`

Ещё один специализированный способ показать иерархическое разбиение.

Для обычного Dashboard чаще проще использовать `Treemap`, `Tree` или `Sunburst`.

---

## `Bubble Chart`

Похож на Scatter Plot, но размер точки кодирует дополнительный показатель.

Пример:

```text
X = количество рейсов
Y = расход
размер пузыря = перевезённый объём
```

Используйте только если третий показатель действительно нужен для ответа на вопрос.

---

## `Gauge Chart`

Показывает положение значения на шкале.

Например:

```text
Выполнение плана = 76 %
```

В большинстве случаев обычный `Big Number` занимает меньше места и читается быстрее.

Gauge имеет смысл, когда сама шкала, диапазон или порог важны для понимания.

---

## `Radar Chart`

Используется для сравнения профилей нескольких объектов по набору показателей.

Выглядит эффектно, но точные различия читать сложнее, чем на обычных Bar Chart.

Используйте только при небольшом числе объектов и показателей.

---

## `Graph Chart`

Показывает сеть узлов и связей.

Нужен, если предмет анализа — именно сеть:

- связи объектов;
- взаимодействия;
- зависимости;
- маршруты между сущностями.

Для обычных категорий и сумм Graph Chart не нужен.

---

## `Chord Diagram`

Показывает связи между категориями по окружности.

Полезен только при ограниченном числе связей. При большом количестве категорий быстро превращается в трудно читаемую схему.

---

## `Gantt Chart`

**Вопрос:** когда начинается и заканчивается каждый интервал?

Подходит для:

- работ;
- этапов;
- простоев;
- процессов с началом и окончанием;
- временных интервалов по объектам.

Не стоит превращать Superset в систему управления проектами только из-за наличия Gantt: Chart визуализирует данные, но не заменяет специализированный task/project management.

---

# 4. Статистические и исследовательские Chart

## `Paired t-test`

Статистический инструмент для парного t-теста.

Не используйте его просто как необычную визуализацию. Нужны понимание статистической гипотезы, выборок и интерпретации результата.

---

## `Parallel Coordinates`

Позволяет одновременно рассматривать много числовых характеристик объектов.

Например:

```text
пробег
расход
рейсы
масса
скорость
время
```

Подходит для exploratory analysis, но обычно слишком сложен для обычного управленческого Dashboard.

---

# 5. Временные Chart специального назначения

В Superset 6.1.0 кроме обычных Line, Bar и Area есть дополнительные варианты временных рядов.

| Chart | Когда может понадобиться |
|---|---|
| `Time-series Chart` | универсальная временная серия |
| `Smooth Line` | сглаженное представление линии |
| `Step Chart` | значение меняется ступенями |
| `Time-series Scatter` | отдельные точки во времени |
| `Compare` | специализированное сравнение временных рядов |
| `Time Pivot` | специализированный временной pivot |
| `Time Table` | временные показатели в табличном виде |
| `Horizon Chart` | плотное компактное отображение временных рядов |

Для первого Dashboard начинайте с обычного `Line Chart` или `Bar Chart`. К специальным вариантам переходите только если они решают конкретную проблему представления.

# 6. Карты и геоаналитика

Геовизуализация — отдельный класс задач.

Если в данных нет осмысленной географии, карту использовать не нужно.

В Superset 6.1.0 доступны обычные географические Chart и отдельный набор `deck.gl`.

## Обычные карты

| Chart | Назначение |
|---|---|
| `Country Map` | показатели по административной географии страны |
| `World Map` | показатели на мировой карте |
| `MapBox` | географическая визуализация на Mapbox |
| `Cartodiagram` | диаграммы и показатели поверх карты |

## `deck.gl`

`deck.gl` нужен для более специализированной геоаналитики.

| Chart | Что показывает |
|---|---|
| `deck.gl Scatterplot` | отдельные точки |
| `deck.gl Arc` | дуги между точками |
| `deck.gl Path` | линии и маршруты |
| `deck.gl Polygon` | полигоны |
| `deck.gl GeoJSON` | геометрию из GeoJSON |
| `deck.gl Grid` | агрегирование по сетке |
| `deck.gl Hexagon` | агрегирование по шестиугольникам |
| `deck.gl Heatmap` | географическую плотность |
| `deck.gl Screen Grid` | агрегирование в экранную сетку |
| `deck.gl Contour` | контуры / изолинии |
| `deck.gl Multiple Layers` | несколько географических слоёв одновременно |

Для работы с этими Chart могут понадобиться координаты, GeoJSON, полигоны и понимание пространственных данных. Это отдельная тема, а не обязательная часть базового курса.

# 7. Визуализации, с которыми нужно быть осторожнее

## `Word Cloud`

Облако слов хорошо выглядит, но плохо подходит для точного сравнения.

Если нужно понять, какое слово встречается чаще и насколько чаще, обычная таблица или Bar Chart обычно информативнее.

---

## `Rose Chart`

Полярная диаграмма может быть уместна в специальных случаях, но для простого сравнения категорий Bar Chart обычно читается лучше.

---

## `Bullet Chart`

Компактно показывает показатель относительно ориентира или диапазона.

Может быть полезен для KPI, но новичку сначала проще освоить `Big Number` и обычные сравнения.

---

## `Handlebars`

Это не обычный готовый график. Он позволяет формировать собственное представление результата через шаблон.

Используйте, когда штатных визуализаций действительно недостаточно.

Не превращайте обычный Dashboard в набор самописных HTML-шаблонов без необходимости: такие решения сложнее сопровождать.

---

# 10. Что означает `legacy`

В исходном коде Superset 6.1.0 часть визуализаций подключается из пакетов, в названии которых есть `legacy`.

Это **не означает автоматически**, что Chart сломан или запрещён.

Для новичка достаточно правила:

> Если обычный современный Chart решает задачу, выбирайте его. Legacy-вариант изучайте только тогда, когда он даёт нужную возможность, которой нет в более простом варианте.

Например, не нужно выбирать старую Bubble-визуализацию только потому, что она присутствует в каталоге, если задачу нормально решает современный Bubble или Scatter Plot.

# 11. Как выбирать Chart на практике

Перед созданием визуализации ответьте на четыре вопроса.

### 1. Что я пытаюсь доказать или увидеть?

Не «хочу график», а, например:

```text
хочу понять, какой участок даёт больше всего ошибок
```

Тогда первый кандидат — `Bar Chart`.

### 2. Нужны точные значения или визуальное сравнение?

```text
точные строки и суммы → Table
быстро сравнить категории → Bar Chart
```

### 3. Есть ли время в вопросе?

```text
динамика → Line / Bar / Area
конкретные дни → Calendar Heatmap
интервалы начала и окончания → Gantt
```

### 4. Не усложняю ли я ответ?

Если вопрос нормально решается Bar Chart, не нужен Radar, Chord или Graph Chart.

Принцип курса:

> **Самая простая визуализация, которая правильно отвечает на вопрос, обычно и есть лучший выбор.**

# 12. Пример выбора для рабочего Dashboard

Задача: контролировать обработку документов.

Нужно показать:

```text
сколько всего документов
сколько ошибок
долю ошибок
динамику ошибок
участки с наибольшим числом ошибок
типы ошибок по участкам
конкретные проблемные записи
```

Подходящий набор:

| Вопрос | Chart |
|---|---|
| сколько документов | Big Number |
| сколько ошибок | Big Number |
| доля ошибок | Big Number |
| как ошибки меняются по дням | Line Chart |
| где ошибок больше | Bar Chart |
| где концентрируются типы ошибок | Heatmap |
| какие записи проблемные | Table |

Здесь не нужны Sankey, Radar, Gauge, Word Cloud или карта, пока для них нет отдельного аналитического вопроса.

Это и есть нормальный подход к Dashboard: **не показать как можно больше видов Chart, а минимальным набором ответить на нужные вопросы**.
