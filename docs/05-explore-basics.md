# 05. Осваиваем Explore

## Что научимся делать

После этого урока вы должны уметь:

- открыть `Explore` для существующего Dataset;
- понимать, что именно настраивается в `Explore`;
- получить агрегированный результат без написания SQL;
- использовать `Group by`;
- создать простую временную метрику прямо в `Explore`;
- применять обычный фильтр;
- работать с `Time Range`;
- понимать, когда нужен `Time Grain`;
- сгруппировать даты по месяцам;
- ограничить число возвращаемых строк через `Row limit`;
- запустить запрос через `Run Query`;
- прочитать результат и проверить его по контрольным значениям;
- изменить условие и повторно выполнить тот же аналитический запрос.

В этом уроке мы **не создаём сохранённые Metrics, Calculated Columns и не сохраняем Chart**.

Наша задача — научиться задавать простой аналитический вопрос через `Explore` и понимать, как настройки превращаются в результат.

## Какой вопрос будем решать

Начнём с конкретного вопроса:

> Какая суммарная выручка приходится на каждый регион?

В таблице `training.sales` есть:

```text
region
revenue
```

Чтобы ответить на вопрос, нужно:

1. сгруппировать строки по `region`;
2. сложить `revenue` внутри каждой группы.

То есть логика задачи выглядит так:

```text
region
   │
   └── Group by

revenue
   │
   └── SUM
```

SQL для этого писать не будем. Эту конструкцию соберём через `Explore`.

## Открываем Explore

Перейдите:

```text
Data → Datasets
```

Найдите Dataset:

```text
sales
```

Нажмите на его имя.

Откроется `Explore`.

Слева должен быть выбран Dataset `sales`, а в списке его полей должны присутствовать:

```text
sale_id
sale_date
region
office
manager
product
quantity
revenue
cost
```

Если открылся другой Dataset, не продолжайте: вернитесь в `Data → Datasets` и снова откройте `sales`.

## Что такое Explore

`Explore` — основной визуальный конструктор аналитического запроса в Superset.

Здесь мы выбираем:

```text
из какого Dataset брать данные
        ↓
как группировать строки
        ↓
что считать
        ↓
какие строки отфильтровать
        ↓
какой период использовать
        ↓
в каком виде показать результат
```

После нажатия `Run Query` Superset формирует запрос к источнику данных и получает результат из PostgreSQL.

Важно:

```text
Explore ≠ отдельная копия данных
Explore ≠ Excel-лист
Explore ≠ SQL Lab
```

Мы задаём параметры запроса через интерфейс, а данные остаются в PostgreSQL.

## Выбираем Table

Для первого упражнения используем визуализацию:

```text
Table
```

Если `Table` уже выбрана, ничего менять не нужно.

Если выбран другой тип визуализации, нажмите на текущий тип визуализации и выберите:

```text
Table
```

В этом уроке Table нужна не для оформления. Это просто удобный способ увидеть агрегированный результат в строках и столбцах.

Сохранённый `Chart` мы пока не создаём.

## Сначала убираем временное ограничение

В официальном учебном сценарии Superset у нового Explore может быть установлен ограниченный `Time Range`, например последние несколько дней.

Наши фиксированные учебные данные находятся в периоде:

```text
2026-01-05 … 2026-03-24
```

Поэтому относительный период вроде:

```text
Last week
```

сейчас даст пустой результат.

Найдите секцию времени и откройте:

```text
Time Range
```

Установите:

```text
No Filter
```

Примените изменение.

Теперь в запрос должны попадать все 12 строк учебной таблицы.

## Настраиваем Group by

В секции `Query` найдите:

```text
Group by
```

Добавьте столбец:

```text
region
```

Это означает:

```text
собрать все строки с одинаковым region в одну группу
```

В наших данных существуют два значения:

```text
Север
Юг
```

Поэтому итоговая таблица должна содержать две группы.

## Добавляем временную метрику SUM(revenue)

Найдите:

```text
Metrics
```

Добавьте столбец:

```text
revenue
```

Для агрегирования выберите:

```text
SUM
```

Итоговая временная метрика должна означать:

```text
SUM(revenue)
```

Она отвечает на вопрос:

> сколько всего выручки находится внутри каждой группы?

### Почему это пока не сохранённая Metric

Сейчас мы создаём **ad hoc metric** — разовый расчёт внутри текущего Explore.

Он нужен для конкретного запроса и пока не становится постоянным элементом Dataset.

То есть сейчас:

```text
Explore
└── временный SUM(revenue)
```

А в следующем уроке будет другой уровень:

```text
Dataset
└── сохранённая Metric
```

Разницу между временной и сохранённой метрикой подробно разберём в уроке 06.

## Устанавливаем Row limit

Найдите:

```text
Row limit
```

Для учебного запроса можно установить:

```text
100
```

Здесь фактически вернутся только две строки, потому что у нас всего два региона.

`Row limit` задаёт верхнюю границу количества строк результата, которые Superset запрашивает для этой визуализации.

Это не означает:

```text
взять первые 100 строк training.sales и только потом посчитать результат
```

Для агрегированного запроса ограничивается уже результирующий набор групп.

## Запускаем первый запрос

Проверьте основную конфигурацию:

```text
Visualization: Table
Time Range:    No Filter
Group by:      region
Metric:        SUM(revenue)
Row limit:     100
```

Нажмите:

```text
Run Query
```

## Контрольный результат

Должны получиться две строки:

| region | SUM(revenue) |
|---|---:|
| Север | 1360.00 |
| Юг | 2645.00 |

Порядок строк может отличаться.

Главная проверка:

```text
Север = 1360.00
Юг    = 2645.00
```

Их сумма:

```text
1360.00 + 2645.00 = 4005.00
```

Это совпадает с общей контрольной выручкой учебного набора из урока 02:

```text
revenue = 4005.00
```

Если числа совпали, вы впервые получили проверяемый агрегированный результат через `Explore`.

## Что сейчас сделал Superset

Мы настроили интерфейс так:

```text
Group by = region
Metric   = SUM(revenue)
```

По смыслу запрос близок к:

```sql
SELECT
    region,
    SUM(revenue)
FROM training.sales
GROUP BY region;
```

Superset может сгенерировать технически более сложный SQL, чем этот пример. Сейчас важно понять саму логику:

```text
Group by → определяет группы
Metric   → определяет расчёт внутри групп
```

## Сортируем результат

В полученной таблице нажмите на заголовок столбца с `SUM(revenue)`.

Добейтесь сортировки по убыванию.

Первой строкой должен стать:

```text
Юг    2645.00
```

второй:

```text
Север 1360.00
```

Повторное нажатие на заголовок меняет направление сортировки.

Не путайте сортировку уже отображённой таблицы с `Group by`: сортировка меняет порядок строк результата, но не меняет сами группы и их значения.

## Добавляем обычный фильтр

Теперь ответим на более узкий вопрос:

> Какая суммарная выручка у региона Север?

В секции `Query` найдите:

```text
Filters
```

Добавьте фильтр по столбцу:

```text
region
```

Условие должно оставить только значение:

```text
Север
```

В зависимости от доступного оператора это может выглядеть как равенство или выбор значения из списка.

После этого снова нажмите:

```text
Run Query
```

Теперь должна остаться одна группа:

| region | SUM(revenue) |
|---|---:|
| Север | 1360.00 |

Что изменилось:

```text
до фильтра
training.sales
├── Север
└── Юг

после фильтра
training.sales
└── Север
```

Сначала фильтр ограничил строки, участвующие в запросе, затем `Group by` и `SUM(revenue)` посчитали результат по оставшимся данным.

Измените значение фильтра:

```text
Север → Юг
```

Снова выполните:

```text

```

Контрольный результат:

```text

```

Теперь удалите фильтр `region`, чтобы снова работать со всеми данными.

## Разбираемся с Time Range

`Time Range` отвечает на вопрос:

> какие строки по времени вообще должны попасть в запрос?

Для Dataset `sales` временным столбцом является:

```text
sale_date
```

До этого мы установили:

```text
No Filter
```

поэтому участвовали все даты.

Теперь ограничим результат только февралем 2026 года.

Откройте:

```text
Time Range
```

Выберите пользовательский (`Custom`) диапазон и задайте:

```text
Start: 2026-02-01
End:   2026-02-28
```

Примените диапазон и нажмите:

```text
Run Query
```

Конфигурация по-прежнему должна содержать:

```text
Group by = region
Metric   = SUM(revenue)
```

Контрольные значения за февраль:

| region | SUM(revenue) |
|---|---:|
| Север | 450.00 |
| Юг | 730.00 |

Итого:

```text
1180.00
```

Теперь верните:

```text
Time Range = No Filter
```

и снова выполните запрос.

Должны вернуться исходные значения:

```text
Север = 1360.00
Юг    = 2645.00
```

## Фиксированный и относительный Time Range

Superset умеет работать как с фиксированными датами, так и с относительными выражениями времени.

Примеры относительных диапазонов:

```text
Last 7 days
Last month
Last quarter
Last year
```

Их смысл зависит от момента выполнения запроса.

Например:

```text
Last month
```

сегодня и через месяц будет означать разные календарные интервалы.

Поэтому в учебном наборе с фиксированными историческими датами мы используем:

```text
No Filter
```

или конкретные даты 2026 года.

Так результаты урока остаются воспроизводимыми.

## Time Range и Time Grain — не одно и то же

Эти две настройки часто путают.

`Time Range` отвечает:

```text
какой период данных взять?
```

`Time Grain` отвечает:

```text
с какой временной детализацией сгруппировать даты?
```

Например:

```text
Time Range = январь–март 2026
Time Grain = month
```

означает:

```text
взять данные за январь–март
и собрать даты в месячные группы
```

Сам по себе `Time Grain` не задаёт период отбора.

## Смотрим Time Grain на практике

В нашей первой таблице время вообще не участвовало в `Group by`, поэтому `Time Grain` там не был нужен.

Теперь зададим другой вопрос:

> Как менялась общая выручка по месяцам?

Чтобы увидеть именно временную группировку, временно переключим визуализацию на:

```text
Pivot Table
```

Это нужно только для упражнения. Сохранять Chart не будем.

Выберите `Pivot Table` и создайте новую конфигурацию визуализации для текущего Dataset.

В секции времени установите:

```text
Time Column = sale_date
Time Grain  = month
Time Range  = No Filter
```

В `Metrics` добавьте:

```text
SUM(revenue)
```

В `Group by` выберите временное поле `Time`, если интерфейс предлагает такой вариант для текущей визуализации. Оно использует выбранные выше `Time Column` и `Time Grain`.

Не добавляйте сейчас `region` в группировку.

Запустите:

```text
Run Query
```

## Контроль по месяцам

Должны получиться три временные группы:

| месяц | SUM(revenue) |
|---|---:|
| 2026-01 | 1160.00 |
| 2026-02 | 1180.00 |
| 2026-03 | 1665.00 |

Проверка общей суммы:

```text
1160.00 + 1180.00 + 1665.00 = 4005.00
```

Теперь смысл `Time Grain = month` можно увидеть непосредственно:

```text
12 отдельных дат продаж
        ↓
Time Grain = month
        ↓
3 группы
├── 2026-01
├── 2026-02
└── 2026-03
```

Если вместо `month` выбрать более мелкую детализацию, групп станет больше. Если выбрать более крупную — меньше.

Пока не перебирайте все варианты `Time Grain`. Важно понять принцип.

## Как читать запрос Explore

Для простого агрегированного запроса удобно мыслить в таком порядке:

```text
1. Dataset
   Что является источником?

2. Time Range
   Какой период допускаем в запрос?

3. Filters
   Какие строки оставляем?

4. Group by
   На какие группы разбиваем оставшиеся строки?

5. Metrics
   Что считаем внутри каждой группы?

6. Row limit
   Сколько строк результата разрешаем вернуть?

7. Run Query
   Выполняем запрос.
```

Для нашего основного примера:

```text
Dataset    = sales
Time Range = No Filter
Filters    = нет
Group by   = region
Metric     = SUM(revenue)
Row limit  = 100
```

Результат:

```text
Север 1360
Юг    2645
```

## Почему Run Query нужно нажимать повторно

Изменение параметра в панели управления ещё не означает, что результат уже пересчитан.

После изменения:

- `Group by`;
- `Metrics`;
- `Filters`;
- `Time Range`;
- `Time Grain`;
- других параметров запроса

запускайте:

```text
Run Query
```

Только после этого сравнивайте результат с ожидаемым.

## Если не получилось

### Результат пустой

Первым делом проверьте:

```text
Time Range
```

Если там стоит относительный диапазон вроде `Last week`, он не включает наши учебные даты января–марта 2026 года.

Установите:

```text
No Filter
```

и снова нажмите `Run Query`.

### Получается 4005 одной строкой вместо двух регионов

Проверьте:

```text
Group by = region
```

Если группировка отсутствует, `SUM(revenue)` считается по всему набору целиком.

### Получаются две строки, но числа не 1360 и 2645

Проверьте одновременно:

```text
Metric     = SUM(revenue)
Time Range = No Filter
Filters    = нет
```

Также убедитесь, что используется Dataset `sales` из:

```text
Training PostgreSQL → training → sales
```

### После фильтра остался только один регион

Это нормально, если фильтр всё ещё активен.

Удалите фильтр или очистите его значение и снова выполните запрос.

### sale_date нельзя использовать как временное поле

Вернитесь к настройкам Dataset из урока 04 и проверьте, что `sale_date` распознан как temporal/date column.

При необходимости выполните:

```text
Sync columns from source
```

и снова откройте Explore.

### Time Grain ничего не меняет

`Time Grain` имеет смысл только тогда, когда временное поле реально участвует в группировке или временной визуализации.

Если вы группируете только по `region`, изменение `Time Grain` само по себе не обязано изменить две строки регионов.

Для проверки вернитесь к упражнению с `Pivot Table`, `Time Column = sale_date` и группировкой по `Time`.

```text
└── агрегированный расчёт по набору строк
```

На учебных данных создадим строковую прибыль:

```text
revenue - cost
```

и агрегированную прибыль:

```text
SUM(revenue) - SUM(cost)
```
