# Шпаргалка к уроку 05. Time column, Time range и Time grain

В Superset рядом находятся несколько настроек времени, и у каждой своя работа:

```text
Time column
→ по какому полю понимаем время

Time range
→ какие строки по времени берём

Time grain
→ с какой детализацией группируем выбранные строки
```

## На одном примере

Вопрос:

> Как менялась выручка по месяцам за первый квартал 2026 года?

```text
Time column = sale_date
Time range  = 2026-01-01 <= sale_date < 2026-04-01
Time grain  = Month
Metric      = SUM(revenue)
```

Ожидается:

```text
2026-01 = 1160.00
2026-02 = 1180.00
2026-03 = 1665.00
```

## 1. Time column — какое событие считаем датой

В реальном Dataset могут быть:

```text
created_at
updated_at
closed_at
sale_date
```

Для вопроса «сколько продаж было по месяцам?» нужна `sale_date`. Для вопроса «сколько заявок закрывалось по месяцам?» — `closed_at`.

Неправильная временная колонка может дать технически корректный, но смыслово неверный график.

## 2. Временной столбец

Superset должен распознавать поле как временное. В учебном Dataset это `sale_date`.

Если поле не работает как дата, проверьте метаданные Dataset и признак `Is temporal`.

## 3. Time range — какой период взять

Для полного февраля 2026 года:

```text
Start inclusive: 2026-02-01
End exclusive:   2026-03-01
```

То есть:

```text
2026-02-01 <= sale_date < 2026-03-01
```

Такая граница удобна для целых календарных периодов: начало включаем, начало следующего периода — уже нет.

## 4. Time grain — как сгруппировать время

`Time grain` не выбирает период. Он определяет календарную детализацию результата.

| Нужно | Time grain |
|---|---|
| каждый день | `Day` |
| по неделям | `Week` |
| по месяцам | `Month` |
| по кварталам | `Quarter` |
| по годам | `Year` |

## 5. Time range и Time grain работают вместе

```text
Time range = весь 2026 год
Time grain = Month
```

означает: взять данные 2026 года и показать их помесячно.

Если заменить `Month` на `Quarter`, период останется тем же, изменится только группировка.

## 6. Дата может фильтровать, но не быть осью

Вопрос:

> Сколько выручки было по регионам в феврале?

```text
Dimension  = region
Metric     = SUM(revenue)
Time range = февраль 2026
```

Дата здесь только отбирает строки. Результат группируется по регионам.

## 7. Когда Time grain не нужен

Если нужен один итог за февраль, достаточно метрики и `Time range`. Группировка по времени в таком вопросе лишняя.

## Типовые симптомы

| Симптом | Сначала проверить |
|---|---|
| график пустой | `Time range`, затем `Time column` |
| вместо месяцев дни | `Time grain` |
| сумма только части периода | `Time range` и обычные фильтры |
| события попали не в тот день | часовой пояс у `timestamp` |

## Про часовые пояса

В `training.sales` используется простой `sale_date`, поэтому в базовом курсе проблема временных зон не возникает.

Для `timestamp` в рабочей системе важно понимать, в каком часовом поясе хранится событие и какой календарный день ожидает пользователь. Записи около полуночи после преобразования времени могут перейти в соседнюю дату.

Для базового маршрута этого знания достаточно.

## В каком порядке выбирать настройки

1. Какое событие анализируем? → `Time column`.
2. За какой период? → `Time range`.
3. С какой детализацией? → `Time grain`.
