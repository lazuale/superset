# Шпаргалка к уроку 05. Time column, Time range и Time grain

Эта памятка нужна, потому что в Superset рядом встречаются несколько настроек времени, которые решают разные задачи.

```text
Time column
→ по какому полю понимаем время

Time range
→ какие строки по времени берём

Time grain
→ с какой детализацией группируем выбранные строки
```

## Самый короткий пример

Вопрос:

> Как менялась выручка по месяцам за первый квартал 2026 года?

```text
Time column = sale_date
Time range  = 2026-01-01 <= sale_date < 2026-04-01
Time grain  = Month
Metric      = SUM(revenue)
```

Ожидается:

```text
2026-01 = 1160.00
2026-02 = 1180.00
2026-03 = 1665.00
```

## 1. Time column — какое событие считаем датой

В реальном Dataset могут быть:

```text
created_at
updated_at
closed_at
sale_date
```

Вопрос:

> сколько продаж было по месяцам?

нужна:

```text
Time column = sale_date
```

Вопрос:

> сколько заявок закрывалось по месяцам?

нужна:

```text
Time column = closed_at
```

Неправильная временная колонка может дать технически корректный, но смыслово неверный график (`Chart`).

## 2. Временной столбец

Superset должен распознавать поле как временное.

В учебном Dataset это:

```text
sale_date
```

Если поле не работает как дата, проверьте метаданные Dataset и признак `Is temporal`.

## 3. Time range — какой период взять

Для полного февраля 2026 года:

```text
Start inclusive: 2026-02-01
End exclusive:   2026-03-01
```

То есть:

```text
2026-02-01 <= sale_date < 2026-03-01
```

Полуоткрытая граница удобна для целых календарных периодов:

```text
месяц    → первое число месяца ... первое число следующего
квартал  → начало квартала ... начало следующего
год      → 1 января ... 1 января следующего года
```

## 4. Time grain — как сгруппировать время

`Time grain` не выбирает период.

Он отвечает:

> с какой календарной детализацией показать выбранные данные?

| Нужно | Time grain |
|---|---|
| каждый день | `Day` |
| по неделям | `Week` |
| по месяцам | `Month` |
| по кварталам | `Quarter` |
| по годам | `Year` |

## 5. Time range и Time grain работают вместе

```text
Time range = весь 2026 год
Time grain = Month
```

означает:

> взять данные 2026 года и показать их помесячно.

А:

```text
Time range = весь 2026 год
Time grain = Quarter
```

означает:

> взять тот же период и показать его поквартально.

Коротко:

```text
Time range
→ меняет набор строк

Time grain
→ меняет временную группировку
```

## 6. Дата может фильтровать, но не быть осью

Вопрос:

> Сколько выручки было по регионам в феврале?

```text
Dimension  = region
Metric     = SUM(revenue)
Time range = февраль 2026
```

Дата отбирает строки, но результат группируется по регионам.

Это нормальный сценарий.

## 7. Когда Time grain вообще не нужен

Если вопрос:

> Сколько всего выручки было за февраль?

достаточно:

```text
Metric + Time range
```

Группировать результат по времени необязательно.

## 8. Типовые симптомы

| Симптом | Сначала проверить |
|---|---|
| график пустой | `Time range`, затем `Time column` |
| вместо месяцев дни | `Time grain` |
| сумма только части периода | `Time range` и обычные фильтры |
| события попали не в тот день | часовой пояс у `timestamp` |

## 9. Про часовые пояса

В `training.sales` используется простой `sale_date`, поэтому в базовом курсе проблема временных зон не возникает.

В рабочей системе для `timestamp` важно знать:

```text
в каком часовом поясе хранится событие
и в каком часовом поясе пользователь ожидает календарный день
```

Записи около полуночи могут перейти в соседнюю дату после преобразования времени.

Для базового маршрута это справочная заметка, а не отдельная тема обучения.

## 10. Порядок выбора

```text
1. Какое событие анализируем?
   → Time column

2. За какой период?
   → Time range

3. С какой детализацией?
   → Time grain
```

## Главное

```text
Time column
→ какая дата имеет смысл

Time range
→ какие события входят

Time grain
→ как они группируются по календарю
```

Это три разных решения.
