# Шпаргалка к уроку 05. Время: Time column, Time range и Time grain

Эта шпаргалка нужна для одной типовой проблемы новичка: в Superset рядом встречаются несколько настроек времени, и кажется, что они делают одно и то же.

На самом деле у них разные задачи.

```text
Time column
→ по какому полю понимаем время

Time range
→ какие строки по времени берём

Time grain
→ с какой детализацией группируем выбранные строки
```

Если запомнить только это различие, большая часть ошибок с датами исчезает.

---

## Самая короткая схема

Вопрос:

> Как менялась выручка по месяцам за первый квартал 2026 года?

Настройка:

```text
Time column = sale_date
Time range  = 2026-01-01 <= sale_date < 2026-04-01
Time grain  = Month
Metric      = SUM(revenue)
```

Логика:

```text
sale_date
→ определяет временное поле

2026-01-01 ... 2026-04-01
→ оставляет только нужный период

Month
→ объединяет оставшиеся строки по месяцам
```

Ожидаемый результат учебного Dataset:

| месяц | SUM(revenue) |
|---|---:|
| 2026-01 | 1160.00 |
| 2026-02 | 1180.00 |
| 2026-03 | 1665.00 |

---

# 1. Time column — какая дата вообще используется

В Dataset может быть несколько дат.

Например:

```text
created_at
updated_at
sale_date
closed_at
```

Это разные события.

Если аналитический вопрос звучит:

> сколько продаж было по месяцам?

нужна дата продажи:

```text
Time column = sale_date
```

Если вопрос:

> сколько заявок закрывалось по месяцам?

нужна уже дата закрытия:

```text
Time column = closed_at
```

Неправильная Time column может дать технически корректный, но смыслово неверный график.

---

## Temporal column

Superset должен знать, что столбец является временным.

В нашем учебном Dataset:

```text
sale_date
```

помечен как temporal.

Если дата не определяется как временная, проверьте Dataset:

```text
Datasets
→ sales
→ Edit
→ Columns
→ sale_date
→ Is temporal
```

---

# 2. Time range — какие строки по времени оставить

`Time range` — это фильтр по времени.

Он отвечает на вопрос:

> за какой период брать данные?

Например весь февраль 2026 года:

```text
Start (inclusive): 2026-02-01
End (exclusive):   2026-03-01
```

То есть:

```text
2026-02-01 <= sale_date < 2026-03-01
```

Для учебных данных это даёт:

```text
revenue = 1180.00
```

---

## Почему End exclusive

В пользовательском диапазоне урока используется верхняя граница, которая не входит в период.

Поэтому календарный февраль задаём так:

```text
начало февраля включительно
первое марта исключительно
```

а не пытаемся угадывать последнее возможное время последнего дня месяца.

Хороший шаблон для полного календарного месяца:

```text
2026-02-01 <= date < 2026-03-01
```

Для квартала:

```text
2026-01-01 <= date < 2026-04-01
```

Для года:

```text
2026-01-01 <= date < 2027-01-01
```

---

# 3. Time grain — как сгруппировать время

`Time grain` не выбирает период.

Он отвечает на другой вопрос:

> какой должна быть временная детализация результата?

Например одни и те же строки можно показать:

```text
по дням
по неделям
по месяцам
по кварталам
по годам
```

Типовая таблица:

| Нужно увидеть | Time grain |
|---|---|
| каждый день | `Day` |
| динамику по неделям | `Week` |
| динамику по месяцам | `Month` |
| квартальную динамику | `Quarter` |
| годовую динамику | `Year` |

---

## Time range и Time grain работают вместе

Например:

```text
Time range = весь 2026 год
Time grain = Month
```

означает:

> взять строки 2026 года и показать их помесячно.

А:

```text
Time range = весь 2026 год
Time grain = Quarter
```

означает:

> взять те же строки, но показать четыре квартальные группы.

`Time range` меняет набор строк.

`Time grain` меняет группировку этого набора.

---

# 4. Пример на training.sales

Исходные продажи находятся в январе–марте 2026 года.

Общая выручка:

```text
4005.00
```

Если задать:

```text
Time range = No filter
Time grain = Month
```

получим:

```text
2026-01 = 1160.00
2026-02 = 1180.00
2026-03 = 1665.00
```

Если затем задать:

```text
Time range:
2026-02-01 <= sale_date < 2026-03-01
```

то в наборе останется только февраль.

При `Time grain = Month` будет одна группа:

```text
2026-02 = 1180.00
```

---

# 5. Что выбирать сначала

Идите в таком порядке:

```text
1. Какое событие анализируем?
   → выбираем Time column

2. За какой период нужны данные?
   → выбираем Time range

3. С какой детализацией показать период?
   → выбираем Time grain
```

Не наоборот.

---

# 6. Дата в Filter и дата на оси — не одно и то же

Можно отфильтровать данные по времени, но не выводить дату как Dimension или X Axis.

Например вопрос:

> сколько выручки было по регионам в феврале?

Настройка:

```text
Dimension = region
Metric    = SUM(revenue)
Time range:
2026-02-01 <= sale_date < 2026-03-01
```

Дата используется для отбора строк, но результат группируется по регионам:

```text
Север = 450.00
Юг    = 730.00
```

Это нормально.

---

# 7. Когда нужен Time grain

Time grain нужен, когда временной столбец участвует в группировке или временной оси.

Пример:

```text
X Axis = sale_date
Time grain = Month
Metric = SUM(revenue)
```

Если вопрос только:

> сколько было выручки за февраль?

достаточно Time range и Metric.

Группировать по времени необязательно.

---

# 8. Частая ошибка: график пустой

Первым делом проверяйте период.

В учебном Dataset данные есть только в:

```text
январь 2026
февраль 2026
март 2026
```

Если установлен другой Time range, Chart может быть пустым даже при правильных Metric и Dimension.

Для базовых упражнений используем:

```text
sale_date (No filter)
```

если в конкретном шаге не задан другой период.

---

# 9. Частая ошибка: вместо месяцев появились дни

Проверьте:

```text
Time grain = Month
```

Сам факт того, что поле является датой, не означает автоматическую месячную группировку.

---

# 10. Частая ошибка: период правильный, сумма неожиданная

Проверьте отдельно:

```text
Time column
Time range
Metric
Filters
```

Например можно правильно выбрать февраль по `sale_date`, но одновременно оставить обычный Filter по региону. Тогда итог будет не весь февраль, а только выбранный регион.

---

# 11. Относительные периоды

Superset умеет работать не только с фиксированными датами, но и с относительными временными диапазонами.

Смысл таких фильтров:

```text
последние N дней
текущий период
предыдущий период
```

Для обучения сначала используйте фиксированные границы дат: их проще проверить контрольным SQL и исключить неоднозначность относительно текущего времени.

В production относительные периоды удобны для живых Dashboard, которые должны автоматически двигаться вместе с календарём.

---

# 12. Временная зона

Если источник содержит время, а не только календарную дату, в реальных системах может появиться ещё один уровень — timezone.

Например событие физически записано в UTC, а пользователь ожидает локальный день.

Тогда запись около полуночи способна попасть в соседний календарный день после преобразования времени.

Поэтому при расхождениях на границах суток проверяйте не только Time range, но и то, в какой временной зоне хранятся и интерпретируются timestamps.

В `training.sales` используется простой учебный `sale_date`, поэтому эта проблема в базовом курсе не возникает.

---

# 13. Быстрый выбор

```text
Нужно выбрать дату события?
→ Time column

Нужно ограничить период?
→ Time range

Нужно показать дни / недели / месяцы?
→ Time grain
```

---

# 14. Диагностика временного Chart

Если результат подозрительный, проверяйте в таком порядке:

```text
1. Dataset правильный?
2. Time column правильная?
3. Time range правильный?
4. Нет ли второго Filter по дате?
5. Time grain правильный?
6. Metric правильная?
7. Dimension / Series не дробит данные дополнительно?
8. Нет ли проблемы timezone у timestamp?
```

---

# 15. Главное правило

Не думайте о времени как об одной настройке.

```text
Time column
→ что считаем датой события

Time range
→ какие события берём

Time grain
→ как раскладываем их по календарю
```

Это три разных решения.
