# 08. Собираем Dashboard

## Что научимся делать

После этого урока вы должны уметь:

- создать новый `Dashboard`;
- понимать разницу между `Chart` и `Dashboard`;
- добавить на Dashboard уже сохранённые Chart;
- найти нужный Chart в панели `Charts`;
- перетащить Chart на сетку Dashboard;
- менять расположение и размер блоков;
- сохранять изменения Dashboard;
- понимать разницу между сохранением и публикацией;
- опубликовать Dashboard;
- найти Dashboard позже в общем списке;
- снова открыть его;
- перейти в режим редактирования;
- изменить компоновку и повторно сохранить Dashboard.

В этом уроке мы собираем в одну панель Chart, созданные в уроке 07.

Мы **не создаём Native Filters**. Фильтры Dashboard будут отдельной темой урока 09.

## Что нужно до начала

Должны быть полностью пройдены предыдущие уроки.

Особенно важен [урок 07](07-create-charts.md).

В Superset должны существовать четыре сохранённых Chart:

```text
Продажи по регионам — таблица
Общая прибыль
Выручка по регионам — столбцы
Выручка по месяцам
```

Проверить их можно через:

```text
Charts
```

или раздел списка Chart в верхнем меню Superset.

Если какого-то из четырёх Chart нет, сначала вернитесь к уроку 07 и создайте его.

Откройте Superset:

<http://localhost:8088>

и войдите под учебной учётной записью:

```text
логин:  admin
пароль: admin
```

## Что такое Dashboard

В предыдущем уроке каждый аналитический вопрос был сохранён как отдельный `Chart`.

Теперь появляется следующий уровень:

```text
PostgreSQL
    ↓
Dataset
    ↓
Chart 1 ─┐
Chart 2 ─┼──→ Dashboard
Chart 3 ─┤
Chart 4 ─┘
```

`Dashboard` — это сохранённая аналитическая панель, которая объединяет существующие Chart и хранит их расположение на странице.

Важно различать объекты:

```text
Dataset
→ описывает доступные данные и расчёты

Chart
→ хранит конкретный аналитический запрос и визуализацию

Dashboard
→ собирает несколько Chart в одну рабочую панель
```

Dashboard **не создаёт ещё одну копию данных** и не превращает четыре Chart в один большой Chart.

Каждый Chart остаётся самостоятельным сохранённым объектом Superset.

Поэтому один и тот же Chart при необходимости может использоваться на нескольких Dashboard.

## Какой Dashboard будем собирать

Создадим панель:

```text
Учебные продажи
```

Она должна отвечать на четыре простых вопроса:

| Блок | Вопрос |
|---|---|
| `Общая прибыль` | сколько прибыли получили всего? |
| `Выручка по регионам — столбцы` | какой регион даёт больше выручки? |
| `Выручка по месяцам` | как менялась выручка во времени? |
| `Продажи по регионам — таблица` | какие точные значения выручки и прибыли у регионов? |

Это уже небольшой, но законченный аналитический сценарий:

```text
KPI
↓
сравнение категорий
↓
динамика во времени
↓
точные значения
```

Не добавляйте на Dashboard Chart только потому, что они существуют.

У каждого блока должен быть понятный вопрос, на который он отвечает.

## Создаём новый Dashboard

Откройте:

```text
Dashboards
```

На странице списка нажмите:

```text
+ Dashboard
```

В Superset 6.1.0 эта кнопка создаёт новый Dashboard и открывает конструктор панели.

Укажите название:

```text
Учебные продажи
```

Если название редактируется непосредственно в заголовке страницы, нажмите на текущий заголовок, введите новое имя и подтвердите изменение.

Новый Dashboard сначала считается рабочим черновиком.

Публиковать его будем только после того, как соберём и проверим содержимое.

## Режим редактирования Dashboard

Dashboard имеет два принципиально разных состояния работы:

```text
просмотр
```

и:

```text
Edit dashboard
```

В режиме просмотра пользователь смотрит и использует готовую панель.

В режиме редактирования можно:

- добавлять Chart;
- перемещать блоки;
- менять их размер;
- использовать элементы компоновки;
- удалять блоки с Dashboard;
- сохранять новую раскладку.

При создании нового Dashboard вы должны находиться в режиме редактирования.

Если справа нет панели конструктора, найдите кнопку:

```text
Edit dashboard
```

и включите режим редактирования.

## Что находится справа

В Superset 6.1.0 боковая панель конструктора содержит две основные вкладки:

```text
Charts
Layout elements
```

### Charts

Здесь находятся сохранённые Chart, которые можно добавить на Dashboard.

В списке можно:

- искать Chart по имени;
- сортировать их;
- показывать только свои Chart;
- перетаскивать Chart на Dashboard.

### Layout elements

Здесь находятся элементы компоновки:

```text
Tabs
Row
Column
Header
Markdown
Divider
```

Они нужны для построения более сложной структуры панели.

В первом Dashboard не будем создавать сложную разметку. Нам достаточно научиться работать с сеткой и четырьмя Chart.

## Добавляем первый Chart

Откройте справа вкладку:

```text
Charts
```

Найдите:

```text
Общая прибыль
```

Если список большой, используйте поле поиска.

Перетащите Chart из боковой панели на рабочую область Dashboard.

После отпускания мыши на Dashboard должен появиться `Big Number` с контрольным значением:

```text
1530.00
```

Это тот же сохранённый Chart из урока 07.

Мы не создавали новый расчёт и не копировали Chart.

## Добавляем остальные Chart

Тем же способом добавьте:

```text
Выручка по регионам — столбцы
Выручка по месяцам
Продажи по регионам — таблица
```

После добавления на Dashboard должны находиться четыре блока.

Проверьте их содержимое.

### Общая прибыль

Контроль:

```text
1530.00
```

### Выручка по регионам — столбцы

Контроль:

```text
Север → 1360.00
Юг    → 2645.00
```

### Выручка по месяцам

Контроль:

```text
2026-01 → 1160.00
2026-02 → 1180.00
2026-03 → 1665.00
```

### Продажи по регионам — таблица

Контроль:

| Регион | Выручка | Прибыль |
|---|---:|---:|
| Север | 1360.00 | 520.00 |
| Юг | 2645.00 | 1010.00 |

Если какой-то Chart показывает другой смысл или другие данные, не исправляйте его компоновкой Dashboard.

Вернитесь к самому Chart и проверьте его настройки.

Dashboard отвечает за сборку панели, а не за исправление неправильной аналитики внутри Chart.

## Раскладываем панель

Теперь расположим блоки так, чтобы панель читалась сверху вниз.

Ориентир для курса:

```text
┌───────────────────────────────────────┐
│ Общая прибыль                         │
│ 1530                                  │
├───────────────────┬───────────────────┤
│ Выручка           │ Выручка           │
│ по регионам       │ по месяцам        │
│                   │                   │
├───────────────────┴───────────────────┤
│ Продажи по регионам — таблица         │
└───────────────────────────────────────┘
```

Это не обязательный универсальный шаблон Dashboard.

Здесь такая структура выбрана потому, что она отражает порядок чтения:

1. сначала главное итоговое число;
2. затем два визуальных разреза;
3. внизу точные значения.

## Перемещаем Chart

В режиме `Edit dashboard` перетащите блок за его область перемещения.

Разместите:

```text
Общая прибыль
```

в верхней части панели.

Ниже поставьте рядом:

```text
Выручка по регионам — столбцы
```

и:

```text
Выручка по месяцам
```

В нижней части разместите:

```text
Продажи по регионам — таблица
```

При перемещении Superset привязывает блоки к сетке Dashboard.

Не пытайтесь добиваться пиксельной точности. Важно получить устойчивую читаемую структуру.

## Меняем размер блоков

В режиме редактирования размер Chart можно изменить перетаскиванием границы или угла блока.

Сделайте так, чтобы:

- `Общая прибыль` не занимала ненужно большую площадь;
- два графика в среднем ряду были достаточно широкими для подписей;
- таблица внизу позволяла нормально читать оба региона и две метрики.

После изменения размера сам аналитический запрос Chart не меняется.

Меняется только место, выделенное этому Chart на Dashboard.

Это ещё одно важное разделение:

```text
изменили размер блока
→ изменили layout Dashboard
→ данные и Metric не изменились
```

## Сохраняем Dashboard
Когда четыре Chart добавлены и расположены, нажмите:

```text
Save
```

Эта команда сохраняет состояние Dashboard:

- название;
- состав размещённых Chart;
- их расположение;
- размеры блоков;
- другие настройки самой панели.

После сохранения обновление страницы не должно возвращать старую раскладку.

### Save — это не Publish

Это принципиально разные действия.

```text
Save
→ сохранить изменения Dashboard
```

```text
Publish
→ перевести Dashboard из Draft в Published
```

Можно иметь сохранённый Dashboard, который всё ещё остаётся `Draft`.

Не используйте публикацию как замену сохранению изменений.

## Проверяем сохранение до публикации

После `Save` обновите страницу браузера.

Проверьте:

- название осталось `Учебные продажи`;
- все четыре Chart присутствуют;
- блоки находятся в сохранённых позициях;
- их размеры не сбросились.

Если раскладка после обновления вернулась назад, значит изменения не были сохранены.

## Что означает Draft

Рядом с названием Dashboard должен отображаться статус:

```text
Draft
```

Это статус публикации Dashboard.

В базовом сценарии курса достаточно понимать:

```text
Draft
→ рабочий черновик Dashboard

Published
→ опубликованная версия Dashboard
```

Публикация **не означает публикацию в открытый Интернет**.

Она также не отменяет разрешения Superset на Dashboard и используемые данные.

Подробную модель прав доступа, Dashboard RBAC и роли в этом базовом курсе не разбираем.

## Публикуем Dashboard

После того как Dashboard сохранён и проверен, нажмите на статус:

```text
Draft
```

рядом с названием Dashboard.

Для пользователя с правом редактирования Superset переключает опубликованность панели.

Статус должен измениться на:

```text
Published
```

Теперь учебная панель считается опубликованной.

Если снова нажать на `Published`, владелец с соответствующими правами может вернуть Dashboard в `Draft`.

В рамках курса оставьте Dashboard в состоянии:

```text
Published
```

## Выходим из Dashboard

Теперь специально уйдите с панели, например откройте раздел:

```text
Dashboards
```

Наша задача — проверить, что Dashboard не существует только в текущей вкладке браузера.

В списке найдите:

```text
Учебные продажи
```

Откройте его.

Должна загрузиться сохранённая панель с четырьмя Chart.

## Проверяем Dashboard в режиме просмотра

После повторного открытия не переходите сразу в редактирование.

Сначала посмотрите на Dashboard как обычный пользователь.

Проверьте:

```text
Общая прибыль = 1530.00
```

а также наличие:

```text
Выручка по регионам — столбцы
Выручка по месяцам
Продажи по регионам — таблица
```

Смысл Dashboard должен считываться без открытия `Explore` каждого Chart.

Если для понимания панели постоянно требуется заходить внутрь каждого Chart, значит сама панель или названия её блоков недостаточно понятны.

## Повторно редактируем Dashboard

Теперь нажмите:

```text
Edit dashboard
```

Измените одну безопасную вещь в layout.

Например, немного увеличьте ширину:

```text
Выручка по месяцам
```

или высоту таблицы:

```text
Продажи по регионам — таблица
```

Не удаляйте Chart и не меняйте их аналитические настройки.

Нажмите:

```text
Save
```

Затем выйдите из режима редактирования или снова откройте Dashboard из списка.

Убедитесь, что новый размер сохранился.

Теперь вы прошли полный жизненный цикл Dashboard:

```text
создали
↓
добавили Chart
↓
разместили
↓
изменили размеры
↓
сохранили
↓
опубликовали
↓
ушли со страницы
↓
снова нашли
↓
открыли
↓
повторно изменили
↓
снова сохранили
```

## Что происходит с Chart внутри Dashboard

Добавление Chart на Dashboard не превращает его в независимую копию.

Модель остаётся такой:

```text
Chart
  │
  └── используется Dashboard
```

Поэтому логика Chart должна настраиваться в самом Chart через `Explore`.

Dashboard отвечает прежде всего за совместное представление сохранённых Chart.

Условно:

```text
нужно изменить SUM(revenue), фильтр или ось
→ редактируем Chart

нужно передвинуть блок или изменить его размер
→ редактируем Dashboard
```

Это разделение сильно упрощает работу с Superset.

## Почему не стоит делать один Dashboard «на всё»

Технически на панель можно добавить много Chart.

Но хорошая рабочая панель должна отвечать на связанный набор вопросов.

Наш Dashboard называется:

```text
Учебные продажи
```

и все четыре блока относятся к одному сюжету:

```text
продажи → выручка → прибыль → регионы → динамика
```

Если позже появится совершенно другой аналитический сценарий, не нужно автоматически складывать его на эту же панель.

Сначала задайте вопрос:

> Этот Chart помогает пользователю разобраться именно в теме текущего Dashboard?

Если нет, вероятно, ему нужна другая панель.

## Что пока не делаем

На Dashboard сейчас не нужно добавлять:

- Native Filters;
- вкладки `Tabs`;
- Markdown-блоки;
- сложную структуру `Row` / `Column`;
- CSS;
- dashboard-level роли;
- embedding;
- автоматическое обновление;
- сложные взаимодействия между Chart.

Эти возможности существуют, но одновременно изучать их вместе с базовой механикой Dashboard не нужно.

Следующий урок добавит только одну новую важную возможность — `Native Filters`.

## Типичные ошибки

### На Dashboard нет нужного Chart

Откройте вкладку:

```text
Charts
```

и найдите его по точному имени.

В нашем сценарии все четыре Chart были созданы тем же пользователем `admin`, поэтому они должны попадать в список при включённом:

```text
Show only my charts
```

Если вы работаете не по чистому учебному сценарию, переключатель можно отключить, чтобы увидеть и другие доступные Chart.

### Chart добавлен, но показывает неправильные числа

Не пытайтесь исправить это размером или положением блока.

Откройте исходный Chart и проверьте его запрос в `Explore`.

Контрольные числа курса:

```text
общая прибыль = 1530.00

выручка:
Север = 1360.00
Юг    = 2645.00

по месяцам:
2026-01 = 1160.00
2026-02 = 1180.00
2026-03 = 1665.00
```

### После обновления страницы раскладка пропала

Изменения layout были сделаны, но не сохранены.

Снова включите:

```text
Edit dashboard
```

восстановите нужное расположение и нажмите:

```text
Save
```

### Dashboard остался Draft

`Save` сохраняет изменения, но не обязан публиковать Dashboard.

После проверки нажмите на статус:

```text
Draft
```

и убедитесь, что он изменился на:

```text
Published
```

### После добавления Chart хочется сразу делать фильтры

Не делайте этого в уроке 08.

Сначала должен быть полностью понятен обычный Dashboard без дополнительной интерактивности.

`Native Filters` — следующий отдельный слой и тема урока 09.

## Попробуйте сами

Не подглядывая в пошаговую часть урока, выполните следующий цикл.

1. Откройте `Учебные продажи`.
2. Перейдите в `Edit dashboard`.
3. Поменяйте местами два графика среднего ряда.

5. Нажмите `Save`.
6. Уйдите в список `Dashboards`.
7. Снова откройте `Учебные продажи`.
8. Проверьте, что новая раскладка сохранилась.
9. Убедитесь, что статус Dashboard — `Published`.

После этого верните расположение к удобному для себя варианту и ещё раз сохраните Dashboard.

К концу урока одновременно выполнены следующие условия:

```text
                        ↓
                    Dashboard
                    └── Учебные продажи
```

На следующем шаге не будем создавать ещё одну панель.

Сделаем существующий Dashboard интерактивным с помощью `Native Filters`.
