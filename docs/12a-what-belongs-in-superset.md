## Где Superset чувствует себя естественно

Если данные уже доступны через SQL, а задача звучит как «отфильтровать, посчитать, сравнить и показать», это нормальная территория Superset.

Типичная цепочка:

```text
источник данных
→ Dataset
→ Explore
→ Metrics / Filters
→ Charts
→ Dashboard
```

## SQL внутри Superset — это нормально

SQL Lab подходит для проверки и исследования. Virtual Dataset — для локальной SQL-подготовки аналитического набора.

Сам по себе длинный SQL не является ошибкой. Вопрос в другом: **должна ли эта логика постоянно жить именно внутри Superset?**

## Когда логику лучше вынести ниже

Если преобразование тяжёлое, используется многими Dashboard, нужно другим системам, должно централизованно контролироваться или материализуется заранее, стоит рассмотреть слой данных:

```text
VIEW
MATERIALIZED VIEW
таблица-витрина
DWH
ETL / ELT
```

Superset после этого подключается уже к подготовленному результату.

## Что не стоит пытаться заменить Superset

### Систему ввода данных

Dashboard может помочь найти неправильную запись, но обычный BI-сценарий не предполагает редактирование рабочих данных прямо в графике.

### Согласование и управление задачами

Superset хорошо покажет количество открытых и просроченных задач или динамику статусов. Назначение исполнителей, согласование и жизненный цикл кейса остаются задачей операционной системы.

### ETL-конвейер

Superset читает аналитические данные и отправляет SQL источнику. Регулярная загрузка, очистка и преобразование сырья — отдельный слой.

### Среду научных вычислений

Наличие статистических визуализаций не превращает Superset в полноценную замену Python, R или специализированным аналитическим инструментам.

## Где должен жить расчёт

```text
значение одной строки
→ Calculated Column

показатель группы
→ Metric

локальная структура аналитического набора
→ SQL / Virtual Dataset

общая тяжёлая модель данных
→ БД / DWH / ETL

научный алгоритм
→ Python / R / специализированный инструмент
```

## Вопросы к реальному Dashboard

Перед тем как считать решение готовым, стоит уметь ответить:

- откуда пришли данные;
- что означает одна строка Dataset;
- где определён каждый важный KPI;
- какие фильтры меняют результат;
- где выполняется тяжёлая подготовка;
- почему логика находится именно на этом уровне.

Если ответ сводится к «где-то внутри нескольких графиков лежит разный SQL», модель стоит пересмотреть.

Граница здесь не запретительная: Superset исследует и показывает аналитические данные, слой данных готовит устойчивую модель, а операционные приложения создают и изменяют бизнес-записи.
