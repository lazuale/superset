# Шпаргалка к уроку 06. Зерно Dataset: что означает одна строка

Перед `COUNT`, `SUM`, `AVG` и другими расчётами сначала ответьте на вопрос:

> **Что означает одна строка Dataset?**

Это и есть зерно данных (`grain`).

```text
1 строка = продажа?
          документ?
          позиция документа?
          автомобиль за сутки?
          сотрудник за смену?
```

Пока ответ неясен, агрегирование выбирать рано.

## 1. Зерно учебного Dataset

В `training.sales`:

```text
1 строка = 1 продажа
```

Поэтому `COUNT(*) = 12` одновременно означает 12 строк и 12 продаж. Это работает только потому, что одна продажа представлена одной строкой.

## 2. Почему `COUNT(*)` не всегда считает бизнес-объекты

Если одна строка — позиция документа, документ с тремя позициями даст:

```text
COUNT(*) = 3
```

хотя документ один.

Если его идентификатор — `document_id`, количество документов нужно считать по уникальным идентификаторам:

```text
COUNT_DISTINCT(document_id)
```

## 3. Зерно определяет смысл `SUM`

Если одна строка — продажа, а `revenue` — выручка этой продажи, `SUM(revenue)` имеет понятный смысл.

Но если Dataset уже содержит готовые месячные итоги, повторное суммирование может быть неверным. Перед `SUM` проверьте две вещи: что означает строка и что означает само значение в колонке.

## 4. Измерение не меняет исходное зерно Dataset

При настройке:

```text
Dimension = region
Metric    = SUM(revenue)
```

Superset группирует исходные продажи по регионам. Сам Dataset от этого не превращается в набор регионов — его исходная строка по-прежнему означает продажу.

## 5. SQL может изменить зерно результата

```sql
SELECT
    region,
    SUM(revenue) AS revenue
FROM training.sales
GROUP BY region;
```

У результата уже другое зерно:

```text
1 строка = 1 регион
```

Это нормально, если именно такой результат нужен. Но дальнейшие расчёты должны учитывать, что отдельных продаж в этом наборе уже нет.

Для Virtual Dataset это особенно важно: предварительная агрегация меняет смысл всех последующих метрик.

## 6. Признаки проблемы

Стоит остановиться и перепроверить модель, если:

- нельзя уверенно закончить фразу «1 строка Dataset = ...»;
- один бизнес-объект неожиданно повторяется;
- `COUNT(*)` заметно больше ожидаемого числа объектов;
- одна и та же сумма дублируется в нескольких строках;
- два Dataset с якобы одинаковым смыслом дают разные KPI;
- непонятно, данные уже агрегированы или ещё нет.

## Перед расчётом

Проверьте:

1. что означает одна строка;
2. какой объект вы хотите посчитать;
3. есть ли у него стабильный идентификатор;
4. повторяется ли объект между строками;
5. можно ли складывать выбранное числовое поле;
6. не был ли набор агрегирован раньше.

Только после этого выбирайте `COUNT`, `COUNT_DISTINCT`, `SUM` или `AVG`.

## Как это связано с JOIN

JOIN может изменить фактическое зерно результата, если одна строка слева совпадёт с несколькими строками справа.

Подробный разбор идёт после SQL Lab:

→ [Справочник после урока 10. JOIN без размножения данных](10b-join-without-duplication.md)

Красивый Dashboard не исправляет ошибку в смысле одной строки. Если зерно определено неверно, проблема находится раньше визуализации.
