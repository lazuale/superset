# Шпаргалка к уроку 06. Зерно Dataset: что означает одна строка

Эта шпаргалка нужна перед `COUNT`, `SUM`, `AVG` и другими расчётами.

Главный вопрос:

> **Что означает одна строка Dataset?**

Это и есть зерно данных. В англоязычных материалах также используется термин `grain`.

```text
1 строка = что?
        ↓
продажа?
документ?
позиция документа?
автомобиль за сутки?
сотрудник за смену?
```

Пока ответ неясен, агрегирование выбирать рано.

## 1. Зерно учебного Dataset

В курсе используется:

```text
training.sales
```

Его зерно:

```text
1 строка = 1 продажа
```

Поэтому:

```text
COUNT(*)
→ количество строк
→ в этом Dataset одновременно количество продаж
```

Но это верно именно потому, что одна продажа представлена одной строкой.

## 2. Почему `COUNT(*)` не всегда считает бизнес-объекты

Допустим, Dataset имеет зерно:

```text
1 строка = 1 позиция документа
```

Документ №100 содержит три позиции:

```text
№100 / строка 1
№100 / строка 2
№100 / строка 3
```

Тогда:

```text
COUNT(*) = 3 строки
```

но документов:

```text
1
```

Если идентификатор документа — `document_id`, для количества документов нужен расчёт вроде:

```text
COUNT_DISTINCT(document_id)
```

## 3. Зерно определяет смысл `SUM`

Если:

```text
1 строка = 1 продажа
```

а `revenue` — выручка этой продажи, то:

```text
SUM(revenue)
```

имеет понятный смысл: суммарная выручка продаж.

Но если Dataset уже содержит готовые месячные итоги, повторный `SUM` может дать бессмысленный результат.

Перед суммированием проговорите:

```text
что означает одна строка?
что означает значение в колонке?
можно ли складывать эти значения между строками?
```

## 4. Измерение не меняет исходное зерно Dataset

Если:

```text
1 строка = 1 продажа
```

и в Explore задано:

```text
Dimension = region
Metric    = SUM(revenue)
```

Superset группирует продажи по регионам и считает метрику внутри каждой группы.

Исходный Dataset всё равно остаётся построчным набором продаж.

## 5. SQL может изменить зерно результата

Например:

```sql
SELECT
    region,
    SUM(revenue) AS revenue
FROM training.sales
GROUP BY region;
```

У результата уже другое зерно:

```text
1 строка = 1 регион
```

Это не ошибка. Но теперь нужно помнить, что Dataset больше не представляет отдельные продажи.

Преждевременная агрегация особенно важна при создании `Virtual Dataset`.

## 6. Красные флаги

Остановитесь перед построением KPI, если нельзя уверенно закончить фразу:

```text
1 строка этого Dataset = ...
```

Дополнительные признаки проблемы:

- один бизнес-объект неожиданно повторяется;
- `COUNT(*)` заметно больше ожидаемого числа объектов;
- одна и та же сумма повторяется в нескольких строках;
- два Dataset с якобы одинаковым смыслом дают разные KPI;
- непонятно, агрегированы данные уже или ещё нет.

## 7. Минимальный алгоритм

```text
1. Что означает одна строка?
2. Какой объект хочу посчитать?
3. Есть ли у объекта стабильный идентификатор?
4. Повторяется ли объект в нескольких строках?
5. Можно ли складывать выбранную числовую колонку между строками?
6. Не был ли Dataset уже агрегирован раньше?
```

Только после этого выбирайте `COUNT`, `COUNT_DISTINCT`, `SUM` или `AVG`.

## 8. Как это связано с JOIN

JOIN может изменить фактическое зерно результата, если одна строка слева совпадёт с несколькими строками справа.

Но подробный разбор JOIN идёт **после SQL Lab**, когда сам синтаксис соединения таблиц уже имеет контекст:

→ [Справочник после урока 10. JOIN без размножения данных](10b-join-without-duplication.md)

## Главное

```text
сначала зерно
→ потом агрегирование
→ потом визуализация
```

Красивый Dashboard не исправит ошибку в смысле одной строки.
