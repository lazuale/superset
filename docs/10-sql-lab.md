# 10. SQL Lab с нуля

## Что научимся делать

После этого урока вы должны уметь:

- открыть `SQL Lab` и выбрать учебную базу;
- найти схему `training` и таблицу `sales` через браузер объектов;
- понимать минимальную структуру SQL-запроса;
- использовать `SELECT` и `FROM`;
- ограничивать число возвращаемых строк через `LIMIT`;
- отбирать строки через `WHERE`;
- сортировать результат через `ORDER BY`;
- считать количество строк через `COUNT`;
- суммировать значения через `SUM`;
- объединять строки в группы через `GROUP BY`;
- читать результат запроса, а не только добиваться его успешного выполнения;
- сравнивать SQL-результат с уже знакомыми результатами `Explore`;
- самостоятельно изменить простой запрос и заранее понимать, что он должен вернуть.

В этом уроке мы используем только запросы на чтение данных.

То есть работаем с:

```sql
SELECT
```

и **не выполняем**:

```text
UPDATE
DELETE
INSERT
CREATE
DROP
ALTER
```

Наша задача сейчас — научиться получать данные, а не изменять базу.

## Зачем SQL Lab, если уже есть Explore

До этого момента почти все вопросы к данным мы задавали через `Explore`:

```text
выбрали Dataset
    ↓
выбрали колонку
    ↓
выбрали Metric
    ↓
настроили фильтр
    ↓
Superset построил SQL-запрос
```

Это удобно, потому что SQL писать не нужно.

`SQL Lab` решает другую задачу: здесь запрос пишем мы сами.

```text
SQL Lab
    ↓
пишем SQL
    ↓
Superset отправляет его в выбранную базу
    ↓
PostgreSQL выполняет запрос
    ↓
Superset показывает результат
```

`SQL Lab` не является отдельной базой данных и не хранит копию `training.sales`.

Он является SQL-интерфейсом Superset к подключённому источнику данных.

Для нашего учебного стенда цепочка выглядит так:

```text
браузер
   ↓
Superset SQL Lab
   ↓
Training PostgreSQL
   ↓
db:5432
   ↓
database training
   ↓
schema training
   ↓
table sales
```

В SQL Lab выберите:

```text

Schema:   training
```

Здесь снова важно не перепутать два имени `training`.

```text
Training PostgreSQL
→ имя сохранённого подключения в Superset

training
→ настоящее имя PostgreSQL database

training
→ имя schema внутри этой database
```

В запросах ниже таблицу будем указывать полностью:


Это означает:

```text

```

а не:

```text
database.table
```

Даже если schema `training` уже выбрана в интерфейсе SQL Lab, полное имя `training.sales` оставляем в учебных запросах намеренно: так запрос однозначно показывает, к какому объекту мы обращаемся.

## Находим таблицу без SQL

Слева в SQL Lab находится браузер схем и таблиц.

Раскройте:

```text
training
```

Найдите:

```text
sales
```

Откройте таблицу в дереве.

Вы должны увидеть знакомые столбцы:

```text
sale_id
sale_date
region
office
manager
product
quantity
revenue
cost
```

Их типы определены в PostgreSQL:

| Столбец | Тип |
|---|---|
| `sale_id` | `BIGINT` |
| `sale_date` | `DATE` |
| `region` | `TEXT` |
| `office` | `TEXT` |
| `manager` | `TEXT` |
| `product` | `TEXT` |

| `cost` | `NUMERIC(12,2)` |

Поле `manager` может содержать `NULL`; остальные учебные поля имеют `NOT NULL`.

Браузер объектов полезен для ответа на вопросы:

- как называется схема;
- как называется таблица;
- какие у таблицы есть столбцы;
- как правильно написать имя нужного поля в SQL.

Но сам запрос всё равно выполняется в редакторе.

# Запрос 1. Получаем первые строки

Начнём с самого простого запроса.

Введите в SQL Editor:

```sql
SELECT *
FROM training.sales
LIMIT 5;
```

Нажмите:

```text
Run
```

Также SQL Lab поддерживает запуск через:

```text
Ctrl + Enter
```

## Что означает запрос

Разберём его буквально.

```sql
SELECT *
```

означает:

> вернуть все столбцы.

```sql
FROM training.sales
```

означает:

> взять строки из таблицы `sales` схемы `training`.

```sql
LIMIT 5
```

означает:

> показать не больше пяти строк результата.

Точка с запятой:

```text
;
```

завершает SQL-выражение.

Для одного простого запроса некоторые SQL-инструменты могут работать и без неё, но в курсе запросы заканчиваем `;` — так границы выражений видны явно.

## Что должно появиться

После выполнения SQL Lab переключится на результат запроса.

Вы должны получить пять строк и все девять столбцов таблицы.

Но здесь есть важный момент:

```sql
SELECT *
FROM training.sales
LIMIT 5;
```

**не задаёт порядок строк**.

Для маленькой учебной таблицы PostgreSQL, скорее всего, покажет знакомое начало данных, но SQL не обещает определённый порядок без `ORDER BY`.

Поэтому следующий запрос сделаем воспроизводимым.

# Запрос 2. Выбираем только нужные столбцы

Замените запрос на:

```sql
SELECT
    sale_id,
    sale_date,
    region,
    revenue
FROM training.sales
ORDER BY sale_date
LIMIT 5;
```

Нажмите:

```text
Run
```

Теперь мы уже не просим все столбцы через `*`.

Мы явно выбираем только:

```text
sale_id
sale_date
region
revenue
```

## Что делает ORDER BY

Строка:

```sql
ORDER BY sale_date
```

означает:

> отсортировать результат по `sale_date` от меньшего значения к большему.

Для даты это означает от более ранней даты к более поздней.

Ожидаемые первые пять строк:

| sale_id | sale_date | region | revenue |
|---:|---|---|---:|
| 1 | 2026-01-05 | Север | 200.00 |
| 2 | 2026-01-12 | Юг | 450.00 |
| 3 | 2026-01-25 | Север | 150.00 |
| 4 | 2026-01-31 | Юг | 360.00 |
| 5 | 2026-02-01 | Север | 180.00 |

Теперь результат определён самим запросом.

## ASC и DESC

По умолчанию:

```sql
ORDER BY sale_date
```

эквивалентно:

```sql
ORDER BY sale_date ASC
```

`ASC` — по возрастанию.

Чтобы получить обратный порядок:

```sql
ORDER BY sale_date DESC
```

`DESC` — по убыванию.

Попробуйте заменить `ORDER BY` на:

```sql
ORDER BY sale_date DESC
```

и снова выполнить запрос.

Самая поздняя дата должна оказаться первой.

После проверки верните:

```sql
ORDER BY sale_date
```

# Запрос 3. Отбираем только Север

Теперь добавим условие.

Введите:

```sql
SELECT
    sale_id,
    sale_date,
    region,
    revenue
FROM training.sales
WHERE region = 'Север'
ORDER BY sale_date;
```

Нажмите `Run`.

## Что делает WHERE

Строка:

```sql
WHERE region = 'Север'
```

означает:

> оставить только строки, где значение `region` равно тексту `Север`.

Текстовые значения в SQL записываем в одинарных кавычках:

```sql
'Север'
```

а имя столбца:

```sql
region
```

в кавычки здесь не помещаем.

В результате должно быть:

```text
6 строк
```

Это все продажи региона `Север`.

## WHERE похож на фильтр в Explore

В уроке 05 мы делали то же самое через интерфейс:

```text
region = Север
```

Теперь условие написано напрямую:

```sql
WHERE region = 'Север'
```

То есть аналитический смысл одинаков:

```text
Explore filter
и
SQL WHERE
```

могут ограничивать строки по одному и тому же условию.

Разница в способе задания запроса.

# Запрос 4. Отбираем февраль 2026 года

Теперь отфильтруем данные по дате.

Введите:

```sql
SELECT
    sale_id,
    sale_date,
    region,
    revenue
FROM training.sales
WHERE sale_date >= DATE '2026-02-01'
  AND sale_date <  DATE '2026-03-01'
ORDER BY sale_date;
```

Нажмите `Run`.

Должно вернуться:

```text
4 строки
```

с датами:

```text
2026-02-01
2026-02-08
2026-02-18
2026-02-27
```

## Почему конец периода записан через `< 2026-03-01`

Мы задаём полуоткрытый интервал:

```text
с 2026-02-01 включительно
до 2026-03-01 не включительно
```

В SQL:

```sql
sale_date >= DATE '2026-02-01'
AND sale_date < DATE '2026-03-01'
```

Такой способ удобно читать:

```text
весь февраль
```

и его легко переносить на поля времени, где кроме даты могут присутствовать часы, минуты и секунды.

## AND

`AND` означает, что строка должна одновременно удовлетворять обоим условиям:

```text
дата не раньше 1 февраля
И
dата раньше 1 марта
```

# Запрос 5. Считаем количество и суммы

До этого мы возвращали отдельные строки.

Теперь используем агрегатные функции.

Введите:

```sql
SELECT
    COUNT(*) AS rows,
    SUM(quantity) AS quantity,
    SUM(revenue) AS revenue,
    SUM(cost) AS cost,
    SUM(revenue) - SUM(cost) AS profit
FROM training.sales;
```

Нажмите `Run`.

Должна получиться **одна строка**:

| rows | quantity | revenue | cost | profit |
|---:|---:|---:|---:|---:|
| 12 | 31 | 4005.00 | 2475.00 | 1530.00 |

Это главный контроль урока.

Он должен полностью совпасть с итогами, которые мы уже проверяли раньше.

## COUNT

```sql
COUNT(*)
```

считает строки результата.

У нас:

```text
12
```

## SUM

```sql
SUM(revenue)
```

складывает значения `revenue` всех строк, попавших в запрос.

Получаем:

```text
4005.00
```

Точно так же:

```sql
SUM(cost)
```

даёт:

```text
2475.00
```

## AS

Конструкция:

```sql
SUM(revenue) AS revenue
```

задаёт понятное имя столбцу результата.

Без `AS` база всё равно выполнит выражение, но заголовок вычисляемого столбца будет менее удобным.

В курсе используем понятные псевдонимы:

```text
rows
quantity
revenue
cost
profit
```

## Сравниваем с Metric из урока 06

В Dataset мы создали Metric:

```sql
SUM(revenue) - SUM(cost)
```

В SQL Lab мы написали то же выражение напрямую:

```sql
SUM(revenue) - SUM(cost) AS profit
```

Результат одинаков:

```text
1530.00
```

Но объекты разные:

```text
Metric в Dataset
→ сохранённое семантическое определение, доступное в Explore

SQL expression в SQL Lab
→ часть конкретного SQL-запроса
```

Одинаковая формула не делает эти сущности одним объектом Superset.

# Запрос 6. Считаем показатели по регионам

Теперь объединим строки в группы.

Введите:

```sql
SELECT
    region,
    COUNT(*) AS rows,
    SUM(revenue) AS revenue,
    SUM(cost) AS cost,
    SUM(revenue) - SUM(cost) AS profit
FROM training.sales
GROUP BY region
ORDER BY revenue DESC;
```

Нажмите `Run`.

Ожидаемый результат:

| region | rows | revenue | cost | profit |
|---|---:|---:|---:|---:|
| Юг | 6 | 2645.00 | 1635.00 | 1010.00 |
| Север | 6 | 1360.00 | 840.00 | 520.00 |

## Что делает GROUP BY

До `GROUP BY` таблица содержит 12 отдельных продаж.

Строка:

```sql
GROUP BY region
```

говорит PostgreSQL:

> собери строки с одинаковым `region` в группы.

В данных два значения региона:

```text
Север
Юг
```

Поэтому после группировки получаем две строки результата.

Для каждой группы отдельно вычисляются:

```sql
COUNT(*)
SUM(revenue)
SUM(cost)
SUM(revenue) - SUM(cost)
```

Смысл запроса можно прочитать так:

```text
возьми training.sales
    ↓
собери строки по region
    ↓
для каждого region посчитай строки, выручку, затраты и прибыль
    ↓
поставь регион с большей выручкой выше
```

## Это тот же вопрос, что в Explore

В уроках 05 и 07 мы уже строили:

```text
Group by = region
Metric   = SUM(revenue)
```

В SQL это выглядит как:

```sql
SELECT
    region,
    SUM(revenue)
FROM training.sales
GROUP BY region;
```

То есть `Explore` не использует какую-то другую математику.

Он помогает собрать запрос через интерфейс.

SQL Lab позволяет написать этот запрос напрямую.

# Запрос 7. GROUP BY вместе с WHERE

Теперь объединим фильтрацию и агрегацию.

Нужно ответить на вопрос:

> сколько выручки и прибыли дал каждый регион только за февраль 2026 года?

Введите:

```sql
SELECT
    region,
    COUNT(*) AS rows,
    SUM(revenue) AS revenue,
    SUM(revenue) - SUM(cost) AS profit
FROM training.sales
WHERE sale_date >= DATE '2026-02-01'
  AND sale_date <  DATE '2026-03-01'
GROUP BY region
ORDER BY revenue DESC;
```

Нажмите `Run`.

Ожидаемый результат:

| region | rows | revenue | profit |
|---|---:|---:|---:|
| Юг | 2 | 730.00 | 285.00 |
| Север | 2 | 450.00 | 175.00 |

Проверка общей февральской выручки:

```text
730 + 450 = 1180
```

Это совпадает с контрольным значением февраля из урока 05:

```text
2026-02 = 1180.00
```

## В каком порядке мысленно читать запрос

Запрос написан в таком порядке:

```text
SELECT
FROM
WHERE
GROUP BY
ORDER BY
```

Для понимания результата удобно мысленно разбирать его так:

```text
FROM
→ откуда берём строки

WHERE
→ какие строки оставляем

GROUP BY
→ как объединяем оставшиеся строки

SELECT
→ что выводим и что считаем

ORDER BY
→ как сортируем готовый результат
```

Это не полный разбор внутреннего порядка выполнения SQL СУБД.

Для базового курса это рабочая модель чтения простого запроса.

# Запрос 8. Проверяем COUNT и NULL

В уроке 06 мы уже видели, что `manager` заполнен не во всех строках.

Проверим это напрямую SQL-запросом:

```sql
SELECT
    COUNT(*) AS all_rows,
    COUNT(manager) AS rows_with_manager
FROM training.sales;
```

Результат:

| all_rows | rows_with_manager |
|---:|---:|
| 12 | 11 |

Причина:

```text
COUNT(*)
→ считает строки

COUNT(manager)
→ считает только строки, где manager не NULL
```

В одной учебной продаже:

```text
manager = NULL
```

поэтому:

```text
12 != 11
```

Это не ошибка SQL Lab.

Это свойство данных и функции `COUNT(column)`.

# Запрос 9. Самостоятельная группировка по product

Теперь запрос нужно закончить самостоятельно.

Вопрос:

> какая выручка, количество проданных единиц и прибыль получены по каждому продукту?

Нужны поля:

```text
product
SUM(quantity)
SUM(revenue)
SUM(revenue) - SUM(cost)
```

Группировка:

```text
product
```

Сортировка:

```text
от большей revenue к меньшей
```

| product | quantity | revenue | profit |


# Минимальная шпаргалка SQL этого урока

## SELECT

Что вернуть:

```sql
SELECT region, revenue
```

## FROM

Откуда взять строки:

```sql
FROM training.sales
```

## WHERE

Какие строки оставить:

```sql
WHERE region = 'Север'
```

## GROUP BY

По какому признаку объединить строки:

```sql
GROUP BY region
```

## ORDER BY

Как отсортировать результат:

```sql
ORDER BY revenue DESC
```

## LIMIT

Сколько строк максимум вернуть:

```sql
LIMIT 5
```

## COUNT

Сколько строк:

```sql
COUNT(*)
```

Сколько непустых значений конкретного столбца:

```sql
COUNT(manager)
```

## SUM

Сумма значений:

```sql
SUM(revenue)
```

## AS

Понятное имя вычисляемого столбца:

```sql
SUM(revenue) AS revenue
```

## Общий шаблон

Для большинства простых агрегированных запросов этого урока достаточно шаблона:

```sql
SELECT
    dimension,
    SUM(value) AS value
FROM schema.table
WHERE condition
GROUP BY dimension
ORDER BY value DESC
LIMIT 100;
```

Это не универсальный SQL на все случаи жизни.

Это минимальный каркас, который уже позволяет решать много обычных аналитических вопросов.

Когда нажимаете:


происходит примерно такая цепочка:

```text
текст SQL в редакторе
        ↓
Superset SQL Lab
        ↓
выбранное Database connection
        ↓
PostgreSQL
        ↓
выполнение SQL
        ↓
результат
        ↓
вкладка Results в SQL Lab
```

Важно:

`Run` не превращает SQL автоматически в Chart, Dataset или Dashboard.

На этом этапе мы просто выполняем запрос и смотрим табличный результат.

В следующем уроке как раз появится новый шаг:

```text
понятный SQL-запрос
        ↓
Virtual Dataset
        ↓
Explore
        ↓
Chart
```

Но в этом уроке Virtual Dataset ещё **не создаём**.

# Важная особенность: Run selection

Если в SQL Editor выделить часть текста, кнопка запуска может переключиться с:

```text
Run
```

на:

```text
Run selection
```

В этом случае SQL Lab выполнит выделенный фрагмент, а не обязательно весь текст редактора.

Для новичка это частая причина ситуации:

> я нажал Run, а выполнился не тот запрос.

Если результат кажется странным:

1. снимите выделение текста;
2. убедитесь, что курсор просто стоит внутри редактора;
3. снова нажмите `Run`.

Когда позже в одном редакторе будет несколько SQL-выражений, `Run selection` станет полезным инструментом.

Пока используем один запрос за раз.

# Как читать ошибки SQL

Ошибка SQL — нормальная часть работы.

Не нужно при первой ошибке переписывать весь запрос.

Сначала определите её класс.

## Таблица не найдена

Например, написано:

```sql
FROM sales
```

а нужная schema не находится в текущем `search_path`.

В курсе используем явное имя:

```sql
FROM training.sales
```

## Опечатка в имени столбца

Например:

```sql
SELECT revenues
FROM training.sales;
```

Но столбец называется:

```text
revenue
```

Проверьте список столбцов в левом браузере SQL Lab.

## Текст написан без одинарных кавычек

Неправильно:

```sql
WHERE region = Север
```

Правильно:

```sql
WHERE region = 'Север'
```

## В SELECT есть обычный столбец, но его нет в GROUP BY

Например:

```sql
SELECT
    region,
    product,
    SUM(revenue)
FROM training.sales
GROUP BY region;
```

Здесь `product` не агрегирован и не включён в `GROUP BY`.

Для нашего текущего уровня действует простое правило:

> если в агрегированном запросе обычный столбец выводится в `SELECT`, он должен соответствовать логике `GROUP BY`.

Исправление зависит от вопроса к данным.

Если нужна группировка только по региону — уберите `product`.

Если нужны группы `region + product` — это уже другая детализация результата.

## Выполнился только фрагмент запроса

Проверьте, не выделен ли текст.

Если выделение есть, SQL Lab может показывать:

```text
Run selection
```

Снимите выделение и запустите весь запрос.

## В SQL Lab нет Training PostgreSQL

Проверьте, что подключение из урока 03 существует:

```text
Settings → Data → Database Connections
```

Учебная учётная запись `admin` должна видеть его.

Если ранее выполняли полный reset:

```bash
docker compose down -v --remove-orphans
```

Superset metadata была удалена вместе с volume, поэтому подключение нужно создать заново по уроку 03.

# SQL и регистр

SQL-ключевые слова можно написать и строчными буквами:

```sql
select * from training.sales;
```

PostgreSQL поймёт такой запрос.

В курсе используем стиль:

```sql
SELECT
FROM
WHERE
GROUP BY
ORDER BY
LIMIT
```

то есть SQL-ключевые слова пишем в верхнем регистре.

Это не техническое требование.

Так запрос легче читать глазами.

Названия наших обычных незаключённых в кавычки объектов пишем так, как они созданы:

```text
training.sales
sale_date
region
revenue
```

# Что SQL Lab не заменяет

После этого урока может показаться:

> раз можно написать SQL, Dataset и Explore больше не нужны.

Нет.

Они решают разные части работы.

## SQL Lab

Удобен, когда нужно:

- самому написать запрос;
- быстро проверить гипотезу;
- увидеть результат SQL;
- подготовить выборку сложнее обычной физической таблицы;
- понять, что реально происходит с данными.

## Dataset

Нужен как управляемый аналитический источник Superset:

- колонки;
- типы;
- temporal-настройки;
- Metrics;
- Calculated Columns;
- использование в Explore.

## Explore

Удобен для интерактивного построения аналитического запроса и визуализации без ручного написания SQL.

## Dashboard

Собирает сохранённые Chart в рабочую аналитическую панель.

Получается не конкуренция инструментов, а цепочка:

```text
SQL Lab
→ подготовить или проверить запрос

Dataset
→ описать аналитический источник

Explore
→ построить Chart

Dashboard
→ собрать Chart в панель
```

# Самостоятельная проверка урока

Не копируя готовые запросы выше, выполните четыре задания.

## Задание 1

Покажите:

```text
sale_date
manager
product
revenue
```

только для региона:

```text
Юг
```

Отсортируйте от самой поздней продажи к самой ранней.

Ожидается:

```text
6 строк
```

## Задание 2

Одной строкой получите:

```text
число продаж
общую выручку
общую прибыль
```

для менеджера:

```text
Анна
```

Контроль:

```text
строк     = 3
выручка   = 750.00
прибыль   = 285.00
```

## Задание 3

Получите выручку по регионам только за март 2026 года.

Контроль:

```text
Юг    = 1105.00
Север = 560.00

всего = 1665.00
```

## Задание 4

Получите выручку по продуктам и отсортируйте результат от большей выручки к меньшей.

Контрольный порядок:

```text
Маршрутизатор → 1605.00
Датчик         → 1210.00
Терминал       → 1190.00
```

Если все четыре задания выполнены без копирования готового SQL, минимальная база урока усвоена.

# Критерии завершения урока

Урок можно считать пройденным, если вы без пошаговой подсказки можете:

1. открыть `SQL Lab`;
2. выбрать `Training PostgreSQL`;
3. выбрать schema `training`;
4. найти `sales` в браузере объектов;
5. написать простой `SELECT`;
6. добавить `WHERE`;
7. добавить `ORDER BY`;
8. ограничить результат через `LIMIT`;
9. получить `COUNT(*)`;
10. получить `SUM(revenue)`;
11. сгруппировать результат через `GROUP BY`;
12. объяснить, почему `COUNT(*) = 12`, а `COUNT(manager) = 11`;

17. прочитать простую SQL-ошибку и найти очевидную опечатку;
