# Шпаргалка к уроку 07. Форматы чисел, процентов и дат

Эта шпаргалка нужна после того, как Chart уже считает **правильное значение**.

Главное правило:

```text
значение
≠
формат отображения
```

Формат может сделать число понятнее, но не исправит ошибочную Metric.

## Самая короткая таблица

| Значение | Хотим показать | Что меняется |
|---|---|---|
| `1234567.89` | `1 234 567,89` | только представление |
| `0.253` | `25.3%` | процентный формат |
| `2026-08-25` | `25.08.2026` | формат даты |
| `324` | `324`, а не `324.00` | точность отображения |

## 1. Сначала проверьте масштаб показателя

Если Metric вернула математическую долю:

```text
0.253
```

процентный формат должен показать примерно:

```text
25.3%
```

Но если SQL уже вернул:

```text
25.3
```

и затем применить формат, который дополнительно масштабирует долю в проценты, можно получить:

```text
2530%
```

Перед `%` всегда ответьте:

```text
Metric возвращает 0.253 или 25.3?
```

## 2. Не превращайте числовую Metric в строку ради красивого вида

Не стоит без необходимости делать:

```sql
CONCAT(ROUND(..., 1), '%')
```

Так число становится текстом и может хуже сортироваться, повторно форматироваться и использоваться в других Chart.

Предпочтительно:

```text
Metric возвращает число
→ Chart отвечает за внешний вид
```

## 3. Числовой формат

Во многих Chart Superset используются D3-style форматы.

Типовые примеры:

```text
.0f   → без десятичных знаков
.2f   → два знака после запятой
,.2f  → разделитель тысяч + два знака
.1%   → процент с одним знаком
.2%   → процент с двумя знаками
```

Конкретные разделители зависят от локали.

Не заучивайте один путь в интерфейсе для всех Chart: поле форматирования зависит от типа визуализации.

## 4. Точность должна соответствовать смыслу

Количество документов:

```text
324
```

обычно лучше, чем:

```text
324.00
```

Среднее время:

```text
3.4 дня
```

может быть понятнее, чем:

```text
3.428571 дня
```

Деньги часто требуют согласованного количества знаков и понятной валюты.

Принцип:

```text
расчёт сохраняет нужную точность
→ визуализация показывает столько знаков, сколько нужно пользователю
```

## 5. Дата и Time grain — разные вещи

```text
Time grain = Month
```

меняет группировку данных по времени.

Формат вроде:

```text
%d.%m.%Y
```

меняет только внешний вид подписи даты.

Не путайте:

```text
Time grain
→ аналитическая логика

Time format
→ представление
```

## 6. Типовые D3 time-format

```text
%Y       → 2026
%m       → номер месяца
%d       → день
%H       → час
%M       → минуты
%Y-%m-%d → 2026-08-25
%d.%m.%Y → 25.08.2026
%H:%M    → 14:35
```

## 7. Компактные значения

Для обзорного KPI может быть удобно:

```text
1 250 000
→ 1.25M
```

Но для контрольной таблицы такое сокращение хуже.

Простое правило:

```text
обзорный KPI
→ допустим компактный формат

сверка / детализация
→ точное значение
```

## 8. Единообразие Dashboard

Для одной панели заранее договоритесь:

```text
деньги      → одна точность
проценты    → одна точность
количество  → без лишних .00
даты        → один понятный стиль
единицы     → видны из названия или подписи
```

Одинаковая Metric не должна выглядеть как разные показатели без причины.

## 9. Быстрая проверка

```text
[ ] Само число уже проверено?
[ ] Понятна единица измерения?
[ ] Процент не умножен на 100 дважды?
[ ] Нет лишних десятичных знаков?
[ ] Дата читается однозначно?
[ ] Time grain не перепутан с форматом даты?
[ ] Компактное K/M не мешает сверке?
```

## Главное

```text
правильное значение
→ правильная единица
→ удобный формат
```

Именно в таком порядке.
