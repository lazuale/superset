# Справочник после урока 07. Форматы чисел, процентов и дат

Форматирование имеет смысл настраивать только после того, как сам расчёт уже проверен.

| Значение | Хотим показать | Что меняется |
|---|---|---|
| `1234567.89` | `1 234 567,89` | только представление |
| `0.253` | `25.3%` | процентный формат |
| `2026-08-25` | `25.08.2026` | формат даты |
| `324` | `324`, а не `324.00` | точность отображения |

Формат может сделать число понятнее, но не исправит неверную метрику.

## Сначала проверьте масштаб показателя

Если метрика вернула математическую долю `0.253`, процентный формат должен показать примерно `25.3%`.

Если SQL уже вернул `25.3`, а затем применить формат, который ещё раз переводит долю в проценты, можно получить `2530%`.

Перед `%` всегда нужно понимать: расчёт возвращает `0.253` или `25.3`?

## Не превращайте число в строку ради красивого вида

Без необходимости не стоит делать:

```sql
CONCAT(ROUND(..., 1), '%')
```

После этого число становится текстом и хуже подходит для сортировки, повторного форматирования и использования в других графиках.

Лучше оставить метрику числом, а отображение настроить в Chart.

## Числовые форматы

Во многих визуализациях Superset используются форматы D3.

```text
.0f   → без десятичных знаков
.2f   → два знака после запятой
,.2f  → разделитель тысяч + два знака
.1%   → процент с одним знаком
.2%   → процент с двумя знаками
```

Конкретные разделители зависят от локали. Поле форматирования также зависит от типа Chart, поэтому одного универсального пути по интерфейсу для всех визуализаций нет.

## Точность должна соответствовать смыслу

Количество документов `324` обычно читается лучше, чем `324.00`. Среднее время `3.4 дня` может быть полезнее, чем `3.428571 дня`.

Расчёт должен сохранять необходимую точность, а визуализация — показывать ровно столько знаков, сколько нужно для чтения показателя.

## Дата и Time grain — разные вещи

```text
Time grain = Month
```

меняет группировку данных.

Формат:

```text
%d.%m.%Y
```

меняет только внешний вид даты.

Это разные настройки: одна влияет на аналитический результат, другая — только на представление.

## Часто используемые форматы времени D3

```text
%Y       → 2026
%m       → номер месяца
%d       → день
%H       → час
%M       → минуты
%Y-%m-%d → 2026-08-25
%d.%m.%Y → 25.08.2026
%H:%M    → 14:35
```

## Компактные значения

В обзорном KPI `1 250 000` иногда удобно показать как `1.25M`. В контрольной таблице такое сокращение обычно мешает сверке.

То есть формат выбирается по назначению графика: обзор допускает компактность, детализация — точность.

## Единообразие Dashboard

На одной панели заранее определите общий подход к деньгам, процентам, количествам, датам и единицам измерения.

Одна и та же метрика не должна без причины выглядеть как разные показатели на соседних графиках.

## Перед публикацией

Проверьте:

- само число уже подтверждено;
- единица измерения понятна;
- процент не умножен на 100 дважды;
- нет лишней точности;
- дата читается однозначно;
- `Time grain` не перепутан с форматом даты;
- компактные `K/M` не мешают сверке.

Порядок простой: сначала правильное значение, потом единица измерения, затем оформление.
