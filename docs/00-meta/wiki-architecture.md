# Архитектура wiki

## Принцип

Wiki организована по учебным зависимостям, а не по меню Superset и не по структуре официального сайта.

Порядок обучения и полнота официального покрытия — разные задачи и ведутся отдельно.

## Слои

### Основной учебный маршрут — `01` … `10`

Отвечает на вопрос: **что изучать и в каком порядке**.

Тема появляется только после необходимых prerequisite. Учебная глава объясняет модель, границы и внутреннюю механику, но не хранит вторую копию исполняемого lab.

### Labs — `11-labs`

Единственное каноническое место для:

- DDL;
- seed data;
- reset/rebuild;
- исполняемых команд;
- контрольных SQL;
- ожидаемых результатов.

Если lab меняется, учебные главы ссылаются на него, а не копируют команды.

### Troubleshooting — `12-troubleshooting`

Диагностика начинается с наблюдаемого симптома и идёт через проверяемую причину к исправлению. Здесь не создаётся альтернативный учебный курс.

### Reference — `13-reference`

Справочники параметров, permissions, chart types, database drivers, feature flags, API endpoints и других областей, которые нужны для полноты, но не являются последовательными уроками.

### Meta — `00-meta`

Управляет всей системой: baseline, источники, roadmap, coverage и Definition of Done.

## Типы страниц

- **concept** — модель, термин, границы или механизм;
- **procedure** — последовательность действий для конкретного результата;
- **lab** — воспроизводимая практика на контролируемом стенде;
- **reference** — справочник;
- **troubleshooting** — диагностика;
- **version note** — подтверждённое отличие версии или upstream-расхождение;
- **meta** — правила самой wiki.

Definition of Done находится в [`page-standard.md`](page-standard.md).

## Типы сущностей

Wiki явно различает:

- **объекты Superset**: Database Connection, Dataset, Metric, Chart, Dashboard, Saved Query, Role и другие сохраняемые сущности;
- **объекты подключённой СУБД**: database, schema, table, view и т. п.;
- **аналитические понятия**: grain, dimension, measure, fact, star schema и т. п.;
- **инфраструктурные компоненты**: metadata database, Redis, Celery worker, reverse proxy и т. п.

Аналитическое понятие нельзя описывать как отдельный metadata-объект Superset, если продукт такой сущности не имеет.

## Навигация

Каждая учебная глава указывает prerequisite и, когда применимо, предыдущую и следующую тему основного маршрута.

Стабильный идентификатор — смысловой slug. Глобальный порядковый номер урока не является постоянной ссылкой.

## Каноническое место материала

Для одной темы выбирается одна каноническая страница. Остальные разделы ссылаются на неё.

Пример для Quickstart:

```text
01-fundamentals
→ зачем нужен sandbox и чем он отличается от production

11-labs/00-sandbox
→ реальные команды, verify и reset

08-administration
→ Docker Compose как deployment mechanism и его ограничения
```

## Версионность

Нормативные refs находятся в [`release-baseline.md`](release-baseline.md). Материал не переписывается незаметно под `Next` или более новую stable-версию.
