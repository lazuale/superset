# Стандарт страниц

Один универсальный шаблон не должен заставлять concept page притворяться lab. Сначала определяется тип материала, затем применяется соответствующий Definition of Done.

## Общие требования

Любая готовая страница должна:

1. соответствовать baseline 6.1.0;
2. не иметь скрытых prerequisite;
3. использовать термины без подмены типов сущностей;
4. объяснять существенные границы темы;
5. иметь конкретное официальное основание;
6. не выдавать непроверенный вывод за факт реализации;
7. иметь рабочие внутренние ссылки;
8. показывать честный статус проверки.

## Рекомендуемые разделы

Используются только применимые разделы:

```text
# Название
## Зачем это нужно
## Что нужно знать до начала
## Термины и типы понятий
## Границы темы
## Как это устроено
## Где находятся данные и metadata
## Что происходит при выполнении операции
## Пошаговый пример
## SQL / конфигурация
## Практическое задание
## Проверка результата
## Типичные ошибки
## Ограничения
## Контрольные вопросы
## Официальные источники
## Статус проверки
## Навигация
```

Неприменимый раздел опускается.

## Терминология

Новый существенный термин определяется до первого содержательного использования и относится к одному из уровней:

- объект Superset;
- объект СУБД;
- аналитическое понятие;
- инфраструктурный компонент;
- настройка / permission.

Официальные названия Dataset, Metric, Chart, Dashboard, Explore, SQL Lab, Saved Query и другие сохраняются без смысловой подмены.

## Внутренняя механика

Когда это полезно для понимания, показывается цепочка:

```text
действие пользователя
    ↓
изменяемый объект или настройка
    ↓
SQL / API / backend-механизм
    ↓
место чтения или сохранения данных
    ↓
результат
```

Минимальный эквивалентный SQL может использоваться для объяснения. Точный generated SQL выдаётся за точный только после фактической проверки.

## Статус проверки

```text
Тип страницы: concept / procedure / lab / reference / troubleshooting
Документировано для: Apache Superset 6.1.0
Проверка реализации: выполнена / не требовалась / не выполнена
Проверка на стенде: выполнена / не выполнена / неприменима
```

`Неприменима` допустимо только когда стенд действительно не нужен.

## DoD: concept

Concept page готова, если читатель может:

- объяснить модель своими словами;
- отличить её от соседних понятий;
- назвать существенные границы;
- предсказать базовое следствие изменения состояния.

Исполняемый lab не обязателен.

## DoD: procedure

Procedure готова, если объявлены:

- исходные условия;
- действия;
- ожидаемый результат;
- способ проверки.

Если процедура требует стенда, но проверка не выполнена, страница не готова к merge.

## DoD: lab

Lab готов только после фактического воспроизведения. Обязательны:

- зафиксированные версии;
- исходное состояние;
- канонические команды/fixtures;
- ожидаемые результаты;
- проверка результата;
- reset/rebuild для сохраняемого состояния;
- повторный прогон после reset, если заявлена детерминированность или идемпотентность.

Старый Docker volume или другая внешняя state не должна незаметно менять результат.

## DoD: reference

Reference page должна иметь определённую область охвата, точную семантику элементов и ссылки на канонические объяснения. Искусственная практика не требуется.

## DoD: troubleshooting

Структура:

```text
симптом → наблюдение → причина → исправление → проверка
```

Добавляются только реальные классы ошибок, подтверждённые документацией, реализацией или стендом.

## Стиль

Текст технический и прямой. Исключаются рекламные формулировки, канцелярские вводные конструкции, искусственные «выводы», повтор одной мысли и выдуманные проблемы ради объёма.
